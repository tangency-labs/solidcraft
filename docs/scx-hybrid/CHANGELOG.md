# scx change log

One entry per version: why it was added (the trigger), what changed, and what happened after. When a version does worse than the one before, review its entry first: undo or narrow the change whose trigger did not recur.

Scores are from the modelling bench described in the README: 23 tasks in four sets ([tasks/](tasks)), input tokens incl. cache. v1-v7 used Haiku 4.5 with one run per task; v9 onwards used Haiku 5.5 with three runs per task (69 runs). Run-to-run noise is about ±2 passes on the 12-task simple set (v5 run twice: 12/12 and 10/12).

## Stopping rule

Keep a change only if the 3-run average gains at least 5% (cost or tokens) with no lost pass; run-to-run
spread is 2-12%, so smaller gains are noise. Stop tuning for a model after two changes in a row miss the bar.

## Also tried: scripts in issue reproductions

Bug-report reproductions (an agent rebuilds a reported problem as a minimal SolidCraft design) were tried
once with scx v8's scripts available (14 cases, blind-scored out of 8), before the v9-v14 work. Score 5.07 with scx vs 5.29 without; where
the agent used scripts it built look-alike stand-ins instead of minimal ones. Tokens were about the same
(94k vs 96k per run). Not adopted for that job.
