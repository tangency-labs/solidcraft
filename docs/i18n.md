# Translating the documentation

```text
docs/
  book/               # Existing English book and shared mdBook settings
    src/              # English originals stay in their original location
      SUMMARY.md
      introduction.md
      guide/
      reference/
      dev/
  da/                 # Same pages, ready for Danish translation
  fr/                 # Same pages, ready for French translation
  de/                 # Same pages, ready for German translation
  languages.json      # Languages in the selector
```

English remains the default language. The existing `docs/book/src` structure and the
shared English documents included from elsewhere in the repository are unchanged.
There is no separate English language folder. Each translation folder contains editable
copies of the English source pages. Open a page
in your language folder and translate it directly. No src/ subfolder is needed. Chapter
files that include another document are expanded only in the translation copies and
disposable build output, so the copies can be edited independently while English continues
to use its existing source files and includes.

Keep filenames, command IDs, code, placeholders and link targets. Translate SUMMARY.md
to change chapter titles. The build matches labels by stable page path and retains the
complete English chapter list, so new English chapters remain accessible.

An unchanged copy of the current English source is marked as English. A missing or empty
page uses the current English original automatically. Existing edited pages are preserved;
when English changes, review and update the language copies rather than overwriting them.

The command reference and screenshots remain generated English resources, shared at
build time; do not commit generated copies. Every manually maintained chapter is present
in each language folder.

Language links preserve the chapter. English stays at the existing root URLs, and other
languages use /da/, /fr/ and /de/. No Japanese documentation site is added. The existing
i18n_catalog_ja.md application-message table is separate and remains unchanged.

Build all languages and generated English resources with cargo xtask book. If generated
resources already exist, run just the documentation build and focused tests:

```sh
python3 scripts/docs/build.py
python3 -m unittest discover -s scripts/docs -p 'test_*.py'
```

Python 3.11+ and the mdBook version pinned in the Pages workflow are required.
Staged sources and coverage.json are under target/docs-i18n/; output is target/book/.
These generated files are never committed.

## Tracking English changes

Run `python3 scripts/docs/sync.py` to copy new English pages into every language folder
and refresh `docs/TRANSLATION_STATUS.md`. Untouched English copies are updated automatically.
For edited translations, new and changed English paragraphs, sections, tables and code examples
are appended in a marked **English updates awaiting translation** section. Existing translated
text is preserved. Unchanged English paragraphs are omitted. Fenced code examples stay intact.
An untouched update block is refreshed rather than duplicated when English changes again;
once a translator edits that block, automation preserves their work. Compare the current English
page when integrating the changes, because a later source update may also need to be included.
Deleted English pages are flagged for manual
review; their translations are retained. Generated chapters and screenshots are excluded.

Each language has a `.translation.json` recording the English source last reviewed for
each page. After translating or reviewing edited pages, run
`python3 scripts/docs/sync.py --review da` (or `fr` / `de`) and commit the manifest with
the translation. First integrate the English updates into the translated text and remove the
entire marked section, including its HTML comment markers. The review command refuses to acknowledge
a language while any marked sections remain. This acknowledges all edited pages in that language;
run it only after reviewing those pages against the current English source. English copies continue
to be listed as untranslated. New chapter links are inserted into translated SUMMARY.md files
with English labels while existing translated labels and matched headings are retained.

`docs/.translation-sources.json` stores the English source snapshots needed to identify changed
paragraphs. Commit it with synchronization changes; it contains source documentation, not generated
command registry data. Old snapshots are retained only while a language still references them.
When migrating without a known baseline, the complete current English page is presented for review.

The status counts distinct commits affecting pending English pages since their recorded
revision, including changes to documents referenced by mdBook includes, rather than
unrelated application commits. Full Git history is required; an
unavailable revision is shown as unknown instead of reporting a false zero.

On main updates, the Documentation translation reminders workflow refreshes one bot-owned
issue per language, reopens it for new work and closes it when no work remains. It proposes
copy and status changes through a normal PR; it never pushes directly to main. While a sync
PR is open, it is refreshed from main using a lease on its own bot branch. Branches with a human
commit are left for manual review. GitHub Actions
also shows the current status in its run summary. The repository must allow Actions to
create PRs and issues. No additional secrets or scheduled service are needed.

Before a release, inspect the language issues and status overview and integrate pending English
sections. This workflow provides reminders and reviewable changes; it does not automatically
approve translations or publish a release.
