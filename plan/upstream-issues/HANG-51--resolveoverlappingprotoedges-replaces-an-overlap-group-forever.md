#### HANG-51. `SmProtoTopologyManager::ResolveOverlappingProtoEdges` replaces an overlap group with one that overlaps again, forever
- **Severity:** Hang
- **Area:** Topology
- **Location:** `source/SMLib/src/SmProtoTopology.cpp:7082`, `SmProtoTopologyManager::ResolveOverlappingProtoEdges` (def. `:7045`): `for(ii=0;ii<rPEs.GetSize();ii+=bFoundOverlapGroup ? 0 : 1)`. When `rPEs[ii]` is in an overlapping proto edge group, the group's proto edges are deleted and replaced by new ones from a classification of the coincident curve against the source faces (`FindOrCreateProtoEdge`, `:7493`), and `ii` is not advanced. Nothing bounds the number of groups replaced.
- **What happens:** the replacement proto edges form a new overlapping group at the same index, which is replaced the same way, and so on. The loop never ends; each pass runs `SmCurve::GlobalCoincidenceChecker` and two `SmFace::CurveOnClassify` calls, which is where a sample of the stack lands. This is not HANG-10 or HANG-48: those are the checker's own split recursion (unbounded depth, and `3^depth` calls on overflowing coordinates). Here every checker call returns (at most 7 nested splits in the samples, normal coordinates); the outer loop is what does not end.
- **Trigger:** `Solids/extrusion_old.smb` (whole body), `SmOffsetExecutive` solid offset with distance 2.5, outset, rounded (extend convex edges off), merge results on, member approximation tolerance `1e-4` (difftest unit `offset.offset_executive_p2`, operation `solid`): `DoSolidOffset` -> `SmOffsetExecutive::PiecewiseMerge` -> `SmMerge::PiecewiseMerge` -> `ManifoldBoolean` -> `SmTopologyIntersector::IntersectInsertRelate` -> `ResolveIntersections` -> `ResolveOverlappingProtoEdges`.
- **How found:** offset coverage sweep (difftest PR #1689): the case timed out on both sides. The C++ side was sampled four times (SIGUSR1 backtraces at 20, 60, 150 and 240 s from an `LD_PRELOAD` handler, frames resolved with `addr2line`); the Rust port, which follows the same loop, was instrumented.
- **Confirmed:** yes for the hang (no result after 300 s). Every C++ sample is inside `ResolveOverlappingProtoEdges`, under different callees (`GlobalCoincidenceChecker` directly; `SmFace::CurveOnClassify` -> `SmCurveClassification::IntersectEdges` -> `SmCurve::GlobalCurveIntersect` -> `SmGlobalSolver` / `GlobalCoincidenceChecker`). The loop itself is shown on the Rust side: there the proto edge list stays at 4 entries while a two-edge group at index 2 is replaced by two new proto edges that form the next group, about 1,950 times in 60 s. The C++ loop was not instrumented.
- **Fix direction (upstream):** bound the replacements, or stop when a group's replacement overlaps itself again.
- **Rust port:** hung the same way (`ProtoTopologyManager::resolve_overlapping_proto_edges`, `crates/solidcore/src/topology/proto_topology/p3.rs`). Unconditional fix in #1803: `InvalidInput` once one call has replaced more than 64 + 4 x (proto edges at entry) groups (module deviations of `topology::proto_topology::p3`); regression test `crates/solidcore/tests/hang_51_extrusion_old_offset.rs`.
