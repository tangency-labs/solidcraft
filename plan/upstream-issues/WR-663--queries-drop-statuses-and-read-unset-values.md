#### WR-663. The loop, vertex, edge use, face, curve and surface queries drop failed statuses and classify from unset values
- **Severity:** Wrong result
- **Area:** Topology queries, curve and surface predicates
- **Location:** `source/SMLib/src/SmLoop.cpp` (`GetUVCornerBoundaries`, `ContainsUVPoint`), `SmVertex.cpp` (`IsTopologicalVertex`, `HasParallelFaces`, `CalcCornerFromFaces`, `IsOnFaceCorner`), `SmEdgeuse.cpp` (`CreateUVTrimCurve`, `EvaluateBinormal`, `NormalizedEvaluate`, `IsEdgeuseSideInSurface`, `HasDogLegNearPole`, `GetStartPointUVLoopGap`, `sm_CalcDistAndDev`), `SmFace.cpp` (`sm_AreConnected`, `sm_FixUVTrimCurves`, `GetPointsInFace`, `CalculateAnInternalPoint`, `MoveSeam`, `SplitAtSeam`, `SwapUV`, `ShrinkGeometry`, `CreateCurvesFromFace`, `CreateUVTrimCurves`, `FaceIntersect`), `SmBSplineCurve.cpp` (`TrimGap`), `SmCurve.cpp` (`ApproximateLength`, `IsClosed`, `IsDegenerate`), `SmSurface.cpp` (`IsClosed`, `IsPlanar`).
- **What happens:** an evaluation, drop, trim, interval edit or sub-operation fails and its status is not checked. Functions that return `SmStatus` go on and return `SM_SUCCESS`. Predicates and classifications read the output the failed call never wrote, which is either the default `SM_UNDEF_DOUBLE` vector or the previous edge use's value, and answer from it. For example, `IsDegenerate` calls a curve that cannot be evaluated degenerate, `TrimGap` reports two curves joined, `ApproximateLength` returns 0, `IsTopologicalVertex` takes a zero tangent as G1, and `HasParallelFaces` compares a stale normal. No crash.
- **Trigger:** no valid input is known to fail these calls. The tests inject the failure: an empty B-spline curve or surface, or a composite curve, which cannot be evaluated.
- **How found:** code reading. The SolidCraft fork (tangency-labs/smlib) handles these statuses in 7a35f33 (SmLoop, SmVertex), 6997962 (SmFace), 666242b (SmEdgeuse), 8843967 (SmBSplineCurve), 8311f8e (SmCurve) and 21dcf69 (SmSurface). They are tracked as #2009 group D.
- **Confirmed:** in the port, by injected-failure tests with the flag on and off. The pinned C++ drops the statuses, so with the flag off the port matches it.
- **Fix (fork):** `SER` on each dropped status in a function that returns `SmStatus`. A classification answers only from what it computed: `SM_POC_UNKNOWN`, no boundary, not G1, no pair compared, no best point, `TRUE` ("cannot tell") for `IsEdgeuseSideInSurface`, no dog-leg, `SM_BIG_DOUBLE` for an unmeasurable loop gap, `-1` for a distance, `FALSE` for the predicates, `SM_UNDEF_DOUBLE` for a length, and 0 (not fixed) for `TrimGap`. Kept dropped: `GetEnds`, the gap caches' refreshes, `HasSeamProblem` and its callers, `EuclidianStepOff`, `ShrinkGeometry`'s curve trims, `InsertTopologyIntersections` in `IsDegenerate`, the list getters, `AssertValid` and drawing.
- **Rust port:** opt-in `Kernel::fixes.query_statuses_pass_on` (default `false`, upstream's behaviour). The `SER` sites go through `crate::error::passed_on`, so with the flag off each site keeps its own ignore policy. Sites: `topology/edgeuse/{p2,p3}.rs`, `topology/vertex.rs`, `topology/vertex/corner.rs`, `query/loop.rs`, `topology/face/{p1,p2,p3}.rs`, `nurbs/b_spline_curve/p3.rs`, `curve/curve/{p2,p4}.rs`, `surface/surface/p7.rs`. The fork's soft answers in `GetUVCornerBoundaries`, `GetStartPointUVLoopGap` and `sm_CalcDistAndDev` replace what the unshipped `topology_failed_evaluations_propagate` (WR-262/263/264, #521) did there, which was to return an error. The flag now gives the fork's answers, and its failed point drops in `GetUVCornerBoundaries` stay ignored, as in the fork.
- **Not ported here:** most of the fork's `SER` sites in `SmCurve.cpp` (about 205), `SmSurface.cpp` (about 260) and `SmBSplineCurve.cpp` (bounding boxes, frames, knot edits, approximations), and their remaining predicates (`IsArc`, `IsLine`, `IsLinear`, `IsPlanar`, `AreCoPlanar`, `AreOnPlane`, `IsPeriodic`, `IsDomainBoundary`, `HasPlaneCrossings`, the curve-list helpers, `GetEnds`; the surface's `IsDegenerateCurve/Point`, `IsPlanarPoint`, `IsFlatCorner`, `IsOnUVBoundary`, `IsSingularity`, `GetSingularities`, `ApproxDerivativeLengths`, the solvers' `LocalSolve`; the B-spline curve's `HasInternalPole`, `HasNullSegments`, `HasSameParameterization`, `IsLine`, `IsDegenerate`, `AssertNoPeriodicJump`, `GetGrevileAbscissa`, `AssertValid`). Also not ported: the `SmFace.cpp` sites in functions without a port (`ShrinkSurface`, `IdentifyFillet`, `GlobalLineIntersect`, `ClassifyLoops`, `OutputPolygons`, drawing), and the `SmVertex.cpp`/`SmLoop.cpp` sites in `RefineGeometry`, `RebuildFromEdgeCurves` and `FindAndRemoveVertexuseByEdge`, none of which has a port. The same goes for `SmEdgeuse`'s `IsMaxEdgeFaceGapFresh`, `IsEdgeCCWEdgeGapFresh` and `NormalizedEvaluateAndDropPt`.
