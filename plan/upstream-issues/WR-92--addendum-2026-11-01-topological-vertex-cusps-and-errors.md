Updates: WR-92

#### WR-92 (update, 2026-11-01). Opt-in cusp rejection and start-tangent error propagation in `SmVertex::IsTopologicalVertex`

- **Status in the port:** `Kernel::fixes.is_topological_vertex_rejects_cusps_and_tangent_errors`, off by default. The default `topology::vertex::is_topological_vertex` preserves the pinned v1.0.1 C++ behavior so `topology.vertex` difftest cases (including `turn180p0_*` and `turn179p51_*`) remain at parity.
- **Location:** `source/SMLib/src/SmVertex.cpp:716, 774, 776, 791-796` (`SmVertex::IsTopologicalVertex`, def. `:702`) at v1.0.1 (`3fd5b95`); in Rust, `crates/solidcore/src/topology/vertex.rs` (`is_topological_vertex`).
- **What changes:** When `Kernel::fixes.is_topological_vertex_rejects_cusps_and_tangent_errors` is `true`:
  1. **Failed start-tangent propagation:** When either edge starts at `v` (`at_start == true`) and `edge_end_tangent(k, b, e, true)` (`pEdgeN->GetEndTangent(TRUE, ...)`) fails with a curve evaluation status (such as `SM_ERR`), `is_topological_vertex` propagates `Err(err)` instead of returning the non-zero `SmStatus` from an `SmBoolean` function as `Ok(true)`.
  2. **Directed tangent orientation and cusp rejection:** Upstream skipped `edge_start_vertex` when both curves passed `IsLine` and never oriented `sTanVec1` / `sTanVec2` relative to `v` (nor negated `SmLine::IsLine`'s STEP tangent when `SmLine::GetInsideOut()` is `TRUE`), then accepted both `|angle_rad| <= ang_limit_rad` and `|angle_rad ± PI| <= ang_limit_rad` (`// gwc: is this a bug? it counts cusps`). Under the opt-in flag, `Line::inside_out()` line tangents are oriented in the NURB-increasing direction, `t1` is oriented incoming to `v` (`if at_start1 { t1 = -t1; }`) and `t2` outgoing from `v` (`if !at_start2 { t2 = -t2; }`, matching `SmVertex::AreEdgesTangent`), and the angle test requires `angle_rad.abs() <= ang_limit_rad`, keeping smooth `G1` continuations (`Ok(true)`) across forward, reversed (`OrientType::Opposite`), and `inside_out` edges while rejecting `180°` cusps (`Ok(false)`).
  3. **Caller behavior and composition:** `topology::brep::p1::topological_vertices` and `boolean::merge::p1::boolean_post_process` call `vertex::is_topological_vertex(k, ...)?`, so they exclude `180°` cusps and propagate start-tangent evaluation errors. `topology::brep::p5::remove_topological_with_notifications` wraps the predicate in `error::ignored(...)?.unwrap_or(false)`, so both `180°` cusps (`Ok(false)`) and failed start-tangent evaluations (`Err(_) -> None -> false`) keep the vertex instead of deleting it. The fix also composes cleanly with `Kernel::fixes.query_statuses_pass_on` (`WR-256`) when `GetEndTangent(false)` fails (`-Vec3::UNDEF` still fails `Vec3::angle_between` and returns `Ok(false)`).
- **Regression evidence:** Unit tests in `crates/solidcore/src/topology/vertex.rs`:
  - `wr92_flag_lookup_and_default` checks default `false`, `UpstreamFixes::NAMES` membership, and `UpstreamFixes::flag_mut("is_topological_vertex_rejects_cusps_and_tangent_errors")`.
  - `wr92_rejects_cusps_and_keeps_smooth_g1_and_corners` checks straight `Line` chains (`0°`, `0.3°`, `0.6°`, `90°`, `180°`, `±179.7°`) and curved degree-2 `BSplineCurve`s (`is_line == None`) meeting at equal parameter (`G1` continuation, `180°` cusp, `90°` corner) under default (`false`) vs. opt-in (`true`).
  - `wr92_reversed_and_inside_out_edges_distinguish_g1_from_cusp` checks reversed `OrientType::Opposite` edges (`at_start1 == false && at_start2 == false`) on both lines and curved degree-2 B-splines, plus `Line::bounded` with `BoundedLineOptions { inside_out: true, .. }`, verifying smooth `G1` continuations stay `Ok(true)` while `180°` cusps become `Ok(false)`.
  - `wr92_propagates_failed_start_tangent_evaluation` checks `CompositeCurve::new(3)` failing `GetEndTangent(true)` at matching parameters for both `edge2` (`at_start2 == true`) and reversed `edge1` (`at_start1 == true`), plus composition with `query_statuses_pass_on` on `GetEndTangent(false)`.
