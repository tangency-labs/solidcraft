#### UB-264. `SmOffsetExecutive::PiecewiseMerge`: deleting the merged offset after a failed merge calls through freed memory in `SmEdge::~SmEdge`
- **Severity:** Crash / undefined behaviour
- **Area:** Offset
- **Location:** `source/SMLib/src/SmOffsetExecutive.cpp`, `SmOffsetExecutive::PiecewiseMerge` (def. `:2236`): `SmObjDelete sClean2(pMergedOffset)` (`:2443`) deletes the merged offset when `SER(sMerge.PiecewiseMerge(...))` (`:2469`) returns a failure; `SmBrep::~SmBrep` → `SmEdge::~SmEdge` (`source/SMLib/src/SmEdge.cpp:59`) then makes an indirect call whose target comes from freed heap memory. Which pointer is dangling (the edge's `m_pCurve`, deleted at `SmEdge.cpp:94`, or an object reached from `Notify` at `:88`) is not established.
- **What happens:** use after free. The faulting call target lies in the allocator's free-list metadata, reached from `SmEdge::~SmEdge`: a virtual call through an object whose memory had been freed and reused. Whether it crashes depends on what the freed memory holds, so it shows only in some heap layouts.
- **Trigger:** the ND-261 shell: `SmApiCreateBox(0, 30, 20, 10)`, `SmApiFilletEdges` on all twelve edges (r3, cross section 1, continuity 1, thumbweight 1), `SmApiShellBrepFull(-2, TRUE, TRUE, FALSE, open)`, in a heap layout where the offset's merge fails.
- **How found:** crash in the C++ reference run (difftest `blend.fillet_executive_p3`, ND-261's heap-layout sweep: 6 of 25 layouts crashed).
- **Confirmed:** yes, crash in the C++ reference run (prebuilt c9c5979 release build, x86-64 Linux), under gdb in one of the sweep's heap layouts: SIGSEGV with the stack `SmEdge::~SmEdge` ← `SmBrep::~SmBrep` ← `SmOffsetExecutive::PiecewiseMerge` ← `DoExtendedOffset` ← `ShellBrep` ← `SmApiShellBrepFull`. The use-after-free class is read from registers, not from a sanitizer; the same layout with `MALLOC_PERTURB_` set did not crash.
- **Rust port:** not affected (safe Rust). At c9c5979 the port refused this shell with `SM_ERR` (ND-261). Following 1.0.1, it builds it.
- **Fixed upstream:** in usd-brep v1.0.1 (3fd5b95), for this trigger. Against the 1.0.1 reference, none of the 25 heap layouts crashes, and the merge no longer fails here, so the failure cleanup is not reached. 1.0.1 also removes freed objects from the state `PiecewiseMerge` reads: `RemoveExcessFaces` forgets the deleted faces and edge uses (UB-256), and `CloseIntersectionLoop`'s squeezed vertices and edges leave the merge's intersection lists. Which change removes the dangling pointer read in `SmEdge::~SmEdge` was not isolated. Whether the cleanup path is still unsafe when a merge fails for another reason is not established. Read from the v1.0.1 source and the sweep only.
