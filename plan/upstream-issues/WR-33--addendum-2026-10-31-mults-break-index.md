Whenever `rdKnots` does not align 1:1 with `m_dBreaks` from index `0` — such as `GetKnots` with a sub-interval on a cached curve (which filters `m_dBreaks` via `ContainsValue(b, 0.0)` into a shorter `rdKnots`), a break subset passed to `GenerateMults`, or interleaved non-break query parameters — matched breaks receive the continuities of `m_sConts[0..]` instead of `m_sConts[bi]`, and non-break query points that push `ii >= m_sConts.GetSize()` read out of bounds upstream.
- **What changes (`crv_in_volume_mults_by_break_index = true`):** `CrvInVolume::fill_mults` reads `self.conts[bi]` instead of `self.conts[ii]`. Cached sub-interval `GetKnots` queries (`knots`, `knots_ref`, `knots_with_status`, `knots_with_status_ref`) and `GenerateMults` subset or mixed break/non-break queries (`generate_mults_with_kernel`, `generate_mults_opt_in(..., true)`) return each matched break's own effective multiplicity from `self.conts[bi]`, check `ContinuityType::Undefined` on `self.conts[bi]`, and never fail bounds checks when non-break query points make `ii >= self.conts.len()` (`bi < self.breaks.len() == self.conts.len()` holds at every match).
