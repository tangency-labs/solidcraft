#### WR-537. A point on the seam of a face that closes on itself has two solutions and classifies as unknown: the boolean fails in `Homogenize`
- **Severity:** Wrong result (the boolean fails, `SM_ERR` 1001, on valid input)
- **Area:** Booleans
- **Location:** `source/SMLib/src/SmPointClass.cpp`, `SmPointClassification::ComputePointParameters` (def. `:651`): the face/surface branch takes `GlobalPointSolve(.., SM_SR_SINGLE)`. If that does not return exactly one solution, it retries at 100 times the tolerance and then fails.
- **What happens:** On a face that closes on itself (a whole cylinder's wall), a point on the seam has its parameters at both ends of the period, so the solve returns two solutions that are the same point. `ComputePointParameters` drops the classification to `SM_PC_UNKNOWN`. `InsertPointClass` then treats an unknown point inside a face interval as a conflict, and `SmCurveClassification::Homogenize` fails.
- **Trigger:** a plate's r 3 hole intersected with a pin of the same radius 1e-6 off its axis, both cylinders with their seams at the same angle (SolidCraft's inspect.interference). At the failing point the wall's face domain is u in [0, 18.8496], and the solve returns u = 6.39e-7 and u = 18.8496: the same point, 5.8e-7 apart.
- **How found:** reported by SolidCraft. The fork's fix is tangency-labs/smlib@577f7be ("booleans: a point on a closed face's seam classifies to that face"), which is not merged upstream.
- **Confirmed:** no C++ run was made here. The Rust port's `compute_point_parameters` follows the pinned C++ (`3fd5b95`).
- **Rust port:** behaves as upstream by default. With `Kernel::fixes.seam_point_solutions_are_one`, after each of the two solves `compute_point_parameters` keeps only the nearest solution (the first of the smallest solution values) when every solution evaluates within the source zone tolerance of the first's point (`one_point`). A failed evaluation keeps them all. `tests/wr_537_pin_a_hair_off_a_seam.rs` checks that the intersection comes out empty with the fix.
