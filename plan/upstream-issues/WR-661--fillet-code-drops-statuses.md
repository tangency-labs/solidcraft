#### WR-661. The fillet executive, solvers, corners and geometry drop failed statuses and fillet on
- **Severity:** Wrong result
- **Area:** Blends / fillets
- **Location:** `source/SMLib/src/SmFilletExecutive.cpp` (36 dropped statuses: `SetFilletParameters`' `LoadFilletSolver`, `DoFilleting`'s `OrientTrimmedSurfaces`, `TestAndConvertBigRadFillet`'s vertexuse moves and `CalcRailIntRail`, `UpdateTopologyChanges`' `UpdateSplitFace`, `CreateSmoothEdgeSequence`'s `OrientEdgeSequence`/`Trim`/`Evaluate`/`SetMinMax`/`EditParameterization`/`CreateByJoining`, `SmTemporaryRadiusChange::SetUp`); `SmFilletSolver.cpp`, `SmFilletCorner.cpp`, `SmFilletStandardSolver.cpp`, `SmFilletCustomSolver.cpp`, `SmBlendSurface.cpp`, `SmCurveFilletExecutive.cpp`, `SmFilletIntersector.cpp`, SM_API `SmApiFillets.cpp` (245 calls: copies, trims, interval `Intersect`/`SetMinMax`, `InsertOneKnot` of the two rails, `GetKnots`, `Get/SetControlPoint`, `AdjustSTEPUVDomain`, evaluations, `SwapUV`, `Transform`, `ConvertTo2D`, `GetOrCreateUVTrimCurve`, `CalcCornerVertGeom`/`CalcCornerEdgeGeom`/`ReCalcFilletGeom`, `SimpleCoincidenceChecker`, `InsertKnots`, `SetFromGwNurb`, `DampenKnotSpacing`, `LoadFilletSolver`); `SmFilletGeom.cpp` (67: `SmFilletGeom::Trim`, `Copy`, `CalcEdgeOnEdge`, `CalcSetBackRail`, `TrimRailCurves`, `TrimCliffRails`, `ConvertTo2D`, `MakeNurb`, `GetRailIndexOfSideEU`, `ComputeUVPoint`, `CalcMateGeom`'s `CalcCornerVertGeom`, `sm_ExamineNFixFilletGeoms`, `sm_MoveTSP`, `UpdateSplitFace`).
- **What happens:** a call fails (a copy, trim, interval intersection that comes back `Init()`, a knot inserted in one rail and not the other, an evaluation) and its status is not checked, so the fillet goes on with an unset or stale value and can return `SM_SUCCESS`. No crash: a wrong success.
- **Trigger:** no valid input is known to fail these calls; the failure is injected (disjoint intervals, a knot outside a rail's range, an edge without curve, a failing callee). See the tests below.
- **How found:** code reading; the SolidCraft fork (tangency-labs/smlib) passes these statuses on in 873c7c9 (SmFilletExecutive), 66b02de (solvers, corners, blends, SM_API fillets) and 9b7cd48 (SmFilletGeom), tracked as #2009 group B.
- **Confirmed:** in the port, by injected-failure tests (each expects different outcomes with the flag on and off). The pinned C++ drops the statuses, so with the flag off the port matches it.
- **Fix (fork):** each dropped status is wrapped in `SER` in functions that return `SmStatus`. Where the function cannot return one the fork fails softly: `sm_TestG1Continuity` finds no tangency without an end tangent, `CheckAndFixDegeneracy` refines a UV point only with a computed one, `sm_CheckEdgeCurveDomains` returns no trimmed curve when the copy cannot be trimmed, `GetFilletSolverOfEdge` returns `NULL` when `GetEdgeuses` fails, `sm_GetFilletRadius` returns its angle's status. Kept dropped, with the reason: `ProcessSmoothEdgeSequences` in `CreateFilletBrep`, `DoPiecewiseMerge`'s `RelatePair`, `ShrinkGeometry`, `Unitize` of possibly zero vectors, the plane intersections that fall through to the general intersectors, `SetMinMax` of intervals ordered just before, constructors and destructors.
- **Rust port:** opt-in `Kernel::fixes.fillet_statuses_pass_on` (default `false`, upstream's behaviour), at each site through `crate::error::passed_on` inside the site's own ignore helper, so with the flag off every site is unchanged. Sites in `crates/solidcore/src/blend/fillet_executive/{p1,p2,p3,api,topology_changes}.rs`, `session.rs` (the Nx1 end-gap checks) and `session/big_radius.rs`; `blend/fillet_geom/{p1,p2,p3,p5,p6}.rs` (`SmFilletGeom::Trim` also with the existing `fillet_trim_status`); `blend/fillet_corner/{p1,p2,p3}.rs`; `blend/fillet_solver/{p1,p2,p3,p4,curve_blend_sih}.rs`, `p5/recovery.rs`; `blend/fillet_standard_solver/p1.rs`; `blend/fillet_custom_solver.rs`. The fork's soft changes in `sm_TestG1Continuity`, `CheckAndFixDegeneracy` and `sm_CheckEdgeCurveDomains` are the existing `fillet_corner_statuses` and `fillet_edge_curve_domain_statuses`, moved to the fork's behaviour (addendum `plan/findings/general--status-audit-483--addendum-2026-11-01-fork-fillet-statuses.md`); `GetFilletSolverOfEdge`'s `NULL` is under `fillet_statuses_pass_on`. Not ported, so not wired: `SmBlendSurface`, `SmCurveFilletExecutive`, `SmFilletLaw::CreateLawSequence`, `FlushCurve`'s `IsSelfIntersecting` (dead upstream). Not wired: `DirectTemporaryRadiusChange`'s copy of `SetUp` (no kernel in scope). Rust sites that already propagate or cannot fail need no change. Tests: `blend::fillet_executive::topology_changes::tests::fillet_statuses_pass_on_*`, `blend::fillet_geom::p1::tests::fillet_statuses_pass_on_*`, `blend::fillet_geom::p3::tests::fillet_statuses_pass_on_*`, `blend::fillet_corner::p3::tests::fillet_statuses_pass_on_*`, `blend::fillet_solver::p3::tests::fillet_statuses_pass_on_*`, `blend::fillet_solver::curve_blend_sih::tests::fillet_statuses_pass_on_*`, `blend::fillet_standard_solver::p1::tests::fillet_statuses_pass_on_*`.
