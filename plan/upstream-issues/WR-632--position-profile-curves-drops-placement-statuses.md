#### WR-632. `PositionProfileCurves` drops its placement and transform statuses (#483)
- **Severity:** Wrong result
- **Area:** Primitive creation / sweeps
- **Location:** `source/SMLib/src/SmPrimitiveCreation.cpp:5596`, static `PositionProfileCurves` at pinned v1.0.1 (`3fd5b95`): `SetCanonical` at `:5625` and `:5663`, profile `Transform` at `:5628`, `:5645` and `:5667`, and `MakeUnitOrthoVectors` at `:5660`.
- **What happens:** all six fallible placement writes drop their status. `MakeUnitOrthoVectors` fails when the path's start tangent is too large to unitize: `1e300` components make its squared length overflow, so `Unitize` underflows the components to zero and no perpendicular can be found. Upstream ignores that `SM_ERR`, then calls `SetCanonical` with the zero X axis it wrote, which fails as well, and transforms every profile by a placement whose X is `(0,0,1)` and whose Y is still the unnormalised `Z x tangent` (up to `1e300`). The function returns success and the caller sweeps profiles positioned by that partial frame.
- **Trigger:** `overflow_regression_053`, `overflow_regression_299`, `overflow_regression_736` and `overflow_regression_987` of `primitive.primitive_creation_p1` (`fixtures/primitive.primitive_creation_p1/overflow.json`, op 3): a line path with a `1e300` start or end coordinate and a circular profile.
- **How found:** the first 1,000-case differential fuzz run; retained as fixtures in PR #213 and revalidated against pinned v1.0.1.
- **Confirmed:** yes, the four cases each compare the output count and 32 sampled floats (every output interval and five position/tangent samples) against pinned v1.0.1 in the validated native artifact, maximum relative error 0. This is default-reference evidence; the opt-in status propagation is tested separately in Rust because the reference drops the statuses.
- **Rust policy:** default keeps the pinned result. `Kernel::fixes.planar_path_profile_placement_statuses` is the default-off opt-in that returns the first error of the two `SetCanonical` calls, the three `Transform` calls and `MakeUnitOrthoVectors`, in that operation order, before a failed result is used; the edits already made stay (there is no rollback). The identity `SetCanonical` at `:5636` always succeeds upstream and has no corresponding Rust call. The read-side calls around it (`CalculateBoundingBox`, `ComputeCrvsNormal`, `Evaluate`) and the neighbouring `ExtendPathCurves`/`SweepProfilesAlongPath`/`CreateCurveSweep` statuses are unchanged: `SweepProfilesAlongPath` keeps ignoring its status because the WR-400 opt-in depends on that, and the rest of #483 is separate work.
