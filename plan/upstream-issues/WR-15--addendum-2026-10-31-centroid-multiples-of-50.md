Updates: WR-15

#### WR-15 (update, 2026-10-31). Opt-in fix for 50-point block sums and centroid cache flag

- **Status in the port:** `Kernel::fixes.point_set_centroid_all_blocks`, off by default. The default `PointSet3d::centroid` (`centroid_opt_in(false)`) preserves the pinned v1.0.1 C++ behavior so `geom.point_set` fixtures (`centroid_blocks_49`, `centroid_blocks_50`, `centroid_blocks_51`, `centroid_blocks_100`) remain at bit-for-bit parity.
- **Location:** `source/SMLib/src/SmPointSet.cpp:410-448` (`SmPointSet3d::SetUpCentroid`) and `source/SMLib/inc/SmPointSet.h:171` (`SmPointSet3d::GetCentroid`) at v1.0.1 (`3fd5b95`); `crates/solidcore/src/geom/point_set.rs` (`PointSet3d::centroid`, `PointSet3d::centroid_opt_in`, `PointSet3d::centroid_with_kernel`, and `PointSet3d::set_up_centroid`, inherited by `PointSequence` via `DerefMut`).
- **What changes:** When `all_blocks` / `point_set_centroid_all_blocks` is `true`:
  1. When `extras = size % 50 == 0`, the initial block count starts at `BLOCK_SIZE` (`50`) instead of `extras` (`0`). For `size == 0`, `iters` is `0` so the loop does not execute and the centroid remains `(0, 0, 0)`; for positive multiples of 50 (`50, 100, 150, ...`), all `iters = size / 50` blocks of 50 points are summed instead of wasting iteration 0 on an empty block and dropping the final 50 points. Non-multiple counts (`extras != 0`) keep the exact `extras` followed by `BLOCK_SIZE` summation order.
  2. `Cache::CENTROID` (`m_bCentroidSet = TRUE`, matching upstream's own header note at `SmPointSet.cpp:408`) is set at the end of `set_up_centroid`. Setting `Cache::CENTROID` does not alter `normal()`, `bbox()`, `tight_pbox()`, `area()`, or `point_containment()`, because `set_up_axes` gates on `Cache::AXES` and `Cache::NORMAL` rather than `Cache::CENTROID`.
- **Caller trace:** The only in-crate caller of `PointSet3d::centroid` outside `geom::point_set` is `PolyBrep::calculate_bounding_box` (`crates/solidcore/src/query/poly.rs:3212`), which builds `PointSet3d::new(pts, 0.0, None)` without a user normal and calls `set.bbox(..)` first; `set.bbox` runs `set_up_axes()` (`best_fit_plane_to_points`), which always populates `self.centroid` and `Cache::CENTROID` before `set.centroid()` is reached. Upstream's only other non-poly caller, `SmCurve::AreCoPlanar` (`SmCurve.cpp:13967`), is unported dead code outside the in-scope callgraph.
- **Regression evidence:** Unit tests in `crates/solidcore/src/geom/point_set.rs`:
  - `wr15_empty_and_non_multiple_block_sizes` checks `0`, `49`, and `51` points across default and opt-in modes, verifying identical non-multiple block sums and `Cache::CENTROID` caching / `clear_cache()` reset.
  - `wr15_multiples_of_50_points_50_and_100` checks `50` and `100` points via `centroid`, `centroid_opt_in`, `centroid_with_kernel`, and `PointSequence`, verifying both default pinned behavior (`(0, 0, 0)` on 50 points; dropped second block on 100 points) and opt-in exact averages with `Cache::CENTROID` set.
  - `wr15_call_order_independence_before_and_after_normal` checks `centroid` before vs. after `normal()` on `50` and `100` planar points both with `normal = None` and with a user-supplied normal `Some(&mut z)`, confirming call-order independence under the opt-in.
