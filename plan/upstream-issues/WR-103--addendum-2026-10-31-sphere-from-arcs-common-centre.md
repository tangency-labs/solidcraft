Updates: WR-103

#### WR-103 (update, 2026-10-31). Opt-in `sphere_from_arcs_common_centre` refuses arcs about different centres
- **What changed:** the pinned C++ `SmBSplineSurface::CreateSphereFromArcs` still takes `const SmPoint3d & rOrigin = sRefFrame.GetOriginRef()` (`source/SMLib/src/SmBSplineSurface.cpp:2049`), overwrites `sRefFrame` with each later `IsArc` call, and then compares `sRefFrame.GetOriginRef()` with `rOrigin` (`:2068`), a reference to that same origin. The difference is always zero, so the "OtherCurve center is not the same as 1st Curve cent" test never fires, non-concentric arcs are accepted, and the later sphere origin and axis (`:2179`, `:2188`) see the last examined arc's frame. The Rust port keeps that behaviour by default (the aliasing recorded in WR-103).
- **Opt-in:** `Kernel::fixes.sphere_from_arcs_common_centre` (default off) copies the first arc's centre by value once and, after the existing radius test and before the existing reference-frame adoption, refuses an arc whose centre is farther than `tol_3d` from it with `SM_ERR` (1001, operation `nurbs::b_spline_surface::p2::BSplineSurface::create_sphere_from_arcs`). The threshold is the strict `>` of the upstream test, the radius is still checked first, and the construction origin, Z axis, angle span, arc order, orientations, neighbour rechecks and reference-frame adoption are unchanged. The flag refuses the input; it does not move the sphere to the first centre.
- **Trigger:** the existing `three_arcs_about_two_centres` inputs (three radius-5 arcs: 120 degrees about the origin, 90 degrees about `(10, 0, 0)` sharing its start point, 60 degrees about `(10, 0, 0)`) are accepted with the flag off and refused with it on. Three 120-degree radius-5 arcs about one centre close a loop and are accepted with the flag on and off, with bit-identical NURB data.
- **Confirmed:** the C++ build confirmed the default acceptance (WR-103's original trigger). The opt-in refusal is a Rust-only fix; no C++ comparison is claimed for the new error path.
- **Rust port:** `crates/solidcore/src/nurbs/b_spline_surface/p2.rs`, tests `sphere_from_arcs_common_centre_refuses_two_centres` and `sphere_from_arcs_common_centre_keeps_concentric_sphere`. The four-arc path (`fillet_corner_sphere_from_four_arcs`) is unchanged and still runs before the three-arc check.
