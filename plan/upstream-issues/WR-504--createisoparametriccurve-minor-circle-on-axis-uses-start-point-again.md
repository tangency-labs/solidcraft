#### WR-504. `SmTorus::CreateIsoParametricCurve` takes a minor circle's direction from its start point again when the start lies on the axis
- **Severity:** Wrong result (a horn torus's minor iso circles get no direction and no analytic domain, so the revolve reports no solid)
- **Area:** Surfaces / torus
- **Location:** `source/SMLib/src/SmTorus.cpp`, `SmTorus::CreateIsoParametricCurve`, minor circle branch: the fallback for a start point on the axis evaluates the mid point `sNurbMidPoint` and forms `sNurbMidVec`, but then computes `sXAxis = sTorusZAxis * sNurbMinVec * sTorusZAxis` from the start vector again.
- **What happens:** the minor circle's direction is the start point's radial vector. When the tube starts on the axis (a horn torus, major radius equal to minor radius, whose tube starts at 180 degrees) that vector is zero, so the iso circle gets no direction (its axis is zero, not a unit vector) and no analytic domain. Every minor iso circle starts at the torus centre, on the axis, so the revolve of a disc touching the axis at its seam reports no solid.
- **Trigger:** tangency-labs/solidcore#1514: a disc of radius 5 centred 5 from the axis, revolved about it (a horn torus).
- **How found:** SolidCraft fork (tangency-labs/smlib#40), reported in tangency-labs/solidcore#1514.
- **Confirmed:** no. The pinned C++ is not built on this machine, so the fork's change is the evidence. The port reproduces it with the opt-in off: `issue_1514_horn_torus_minor_iso_circle_takes_direction_from_midpoint` (`crates/solidcore/src/surface/torus.rs`) finds the minor circle's x axis not finite (`x: NaN`).
- **Fix (fork):** tangency-labs/smlib#40 changes the fallback to `sXAxis = sTorusZAxis * (sNurbMidVec * sTorusZAxis)`, so the direction comes from the mid point's vector (`*` between vectors is the cross product).
- **Rust port:** opt-in `Kernel::fixes.torus_iso_circle_axis_from_midpoint` (default `false`, upstream's behaviour) in `Torus::create_iso_parametric_curve` (`crates/solidcore/src/surface/torus.rs`, the `iso_curve` fallback). With the flag on, the midpoint is evaluated and its failure propagates (the fork's `SER`, tangency-labs/smlib@672a437ee; v1.0.1 ignores the status); with it off the fallback is unchanged, the midpoint evaluation is ignored and the start vector is used again. Test: `issue_1514_horn_torus_minor_iso_circle_takes_direction_from_midpoint`, which asserts a unit x axis, radius 5, an analytic domain of 360 degrees and a start at the torus origin with the flag on, and a non-finite x axis with it off.
