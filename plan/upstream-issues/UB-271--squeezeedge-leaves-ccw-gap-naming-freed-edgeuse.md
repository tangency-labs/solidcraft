#### UB-271. SqueezeEdge leaves a neighbour's cached CCW gap pointing at the freed edge use
- **Severity:** Crash / undefined behaviour
- **Area:** Topology
- **Location:** `source/SMLib/src/SmBrep.cpp:27040`, `SmBrep::SqueezeEdge`; the cache is `SmEdgeuse::m_sEdgeCCWEdgeGap3d` (`source/SMLib/inc/SmEdgeuse.h:101`), set by `SmEdgeuse::CalcEdgeCCWEdgeGap` (`source/SMLib/src/SmEdgeuse.cpp:5357`).
- **What happens:** `SqueezeEdge` relinks the squeezed edge's CW neighbours to skip its edge uses and then `delete`s those edge uses, but does not reset the neighbours' cached edge-to-CCW-edge gaps. A neighbour whose gap was cached before the squeeze keeps `m_pEdgeuse1` pointing at freed memory and `IsInit()` stays true, so `GetEdgeCCWEdgeGap()` (no force) returns the stale gap. `SmEdgeEdgeGap::GetEdge(1)` (`source/SMLib/src/SmGap.cpp:677`) would dereference the freed edge use. Only `SmEdge::ClearUVCaches` resets these gaps, and only for the edge's own uses.
- **Trigger:** `SmBrep::ReadFromFile` on `TestFiles/pt_TestFiles/Fillet/open_shell.smb`: the healer's `Fix_CoinVertices` combines vertices 2 and 3 and squeezes the short common edge (file edge 2) after `Cache_EdgeProps` cached the gaps. Four reached edge uses keep a CCW gap naming one of the four deleted edge uses (gap value 0, edge parameters `(6.59965805186031, 0)`, `(0, 1)`, `(0, 1)`, `(6.59965805186031, 0)`).
- **How found:** own-reader rollout of `blend.fillet_corner_p3` (the Rust renumbering could not place the gap's edge use); confirmed by a private probe linking the reference libraries with `free` wrapped: after `ReadFromFile` (status 1000) the walk reaches 62 edge uses, and the 4 stale `m_pEdgeuse1` pointers are neither reached nor the edge use's CCW, and all 4 were passed to `free` during the read.
- **Confirmed:** yes (probe, not a difftest case). No dereference of a stale pointer was observed in the fixtures.
