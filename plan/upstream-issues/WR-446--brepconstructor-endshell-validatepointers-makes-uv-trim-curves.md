#### WR-446. `SmBrepConstructor::EndShell(TRUE)` changes the B-rep through a `const` validation (`ValidatePointers` makes UV trim curves)
- **Severity:** Wrong result
- **Area:** Topology
- **Location:** `source/SMLib/src/SmBrepData.cpp:272`, `SmBrepConstructor::EndShell` (def. `:261`); `source/SMLib/src/SmBrep.cpp`, `SmBrep::ValidatePointers` (def. `:30890`) and the static `sm_CheckEdgeuseGeometry` (def. `:29752`).
- **What happens:** `EndShell(TRUE)` calls `m_pBrep->ValidatePointers()` and ignores its status, so it reads as a debugging check. But `ValidatePointers` (a `const` member) runs `sm_CheckEdgeuseGeometry` on every edge use that has a UV trim curve, which evaluates the clockwise neighbour with `SmEdgeuse::NormalizedEvaluate(.., TRUE, ..)`; that goes through `GetOrCreateUVTrimCurve` and stores a new UV trim curve (`SetUVTrimCurve`) on each neighbour that had none. A face with one UV trim curve thus ends the call with all of them, and the B-rep `EndShell(TRUE)` hands to the stitcher depends on a validation call.
- **Trigger:** any shell ended with `EndShell(TRUE)` where some face already has a UV trim curve, e.g. three faces joined on one edge (the non-manifold `StartEdge` path classifies with `FindRadialSector`, which makes the trim curves of that edge's uses) or an edge made from a UV curve (`SetEdgeCurve(.., TRUE)`).
- **How found:** built-in difftest case `fan_three_shared_stitched` of `topology.brep_constructor` (PR #1000): after `EndShell(TRUE)` the C++ B-rep had UV trim curves on every lamina edge use of the fan, before the stitch ran; gdb breakpoints on `SmEdgeuse::SetUVTrimCurve` show the calls under `SmBrep::ValidatePointers` -> `sm_CheckEdgeuseGeometry` -> `SmEdgeuse::NormalizedEvaluate` -> `GetOrCreateUVTrimCurve`.
- **Confirmed:** yes, with the C++ reference build. The port reproduces it: `EndShell(TRUE)` calls the ported `ValidatePointers` (`topology::brep::validation::validate_pointers`, unit `topology.brep_validation`), whose `sm_CheckEdgeuseGeometry` makes the same UV trim curves, so these cases are compared against C++ rather than deferred.
