#### WR-590. A partial rotational sweep of a curve that meets the axis inside itself fails: `CheckCurveSweep` refuses it and nothing splits it there
- **Severity:** Wrong result (the sweep fails, 1001, on valid input)
- **Area:** Sweeps
- **Location:** `source/SMLib/src/SmRotationalSweepGeometry.cpp:430` (`rSweepState = SM_SC_ROT_ON_CURVE`), `SmRotationalSweepGeometry::CheckCurveSweep` (def. `:334`), reached from the partial-turn `SmPrimitiveCreation::CreateRotationalSweep` (`source/SMLib/src/SmPrimitiveCreation.cpp`, def. `:2852`), which hands the profile's curves to the sweep as given (`:2934` on).
- **Pinned reference:** SMLib v1.0.1, commit `3fd5b95`.
- **What happens:** `CheckCurveSweep` refuses a curve that meets the axis anywhere but at its ends (its comment: split the curve at the point and try the same sweep on the pieces), but the partial-turn `CreateRotationalSweep` never splits one, so the sweep fails with `SM_ERR`. A whole circle tangent to the axis (a horn torus) turned part way fails unless its seam happens to lie on the axis: the same disc starting at the touching point sweeps fine.
- **Trigger:** `SmApiCreateRotationalSweep` of the circle of radius 5 about (5, 0, 0) in the XZ plane (normal -Y), starting at (10, 0, 0) or (5, 0, 5), about the Z axis through the origin, by 90, 180 or 270 degrees, capped. Starting at the origin it builds (3 faces, volume turn * 2 pi 5 * pi 25).
- **How found:** SolidCraft (rig `sweeps/cov-revolve-circle-touching-its-axis`); fixed in the fork as tangency-labs/smlib@e4f1377 ("revolve: a curve touching the axis inside itself is split there").
- **Confirmed:** yes, in the port at parity with the pinned C++ (status 1001 for the first two starts).

The port keeps the pinned result by default. With the opt-in, default-off `Kernel::fixes.revolve_splits_curves_on_axis` (`crates/solidcore/src/kernel.rs`), the partial turn first runs `split_curves_on_axis` (`crates/solidcore/src/primitive/primitive_creation/p3/sweeps.rs`, the fork's `sm_SplitCurvesOnAxis`): it finds the points as `CheckCurveSweep` does (`IntersectWithLine` on the axis at the B-rep tolerance, ends excluded), splits each curve there (`CreateBySplitCurve`), and joins a closed curve's last piece back onto its first (`SmBSplineCurve::CreateByJoining`), so the circle stays one curve with its seam on the axis. `crates/solidcore/tests/wr_590_revolve_splits_curve_on_axis.rs` checks the nine turns with the fix on (3 faces, the Pappus volume), the upstream 1001 for the first two starts with it off, and that the start on the axis is the same either way.
