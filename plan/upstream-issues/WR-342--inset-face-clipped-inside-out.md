#### WR-342. `SmOffsetExecutive::BuildOffsetOfFaceuse` clips an inset face to its offset domain inside out
- **Severity:** Wrong result (the face gets no offset; the shell fails with `SM_ERR`)
- **Area:** Offset
- **Location:** `source/SMLib/src/SmOffsetExecutive.cpp`, `SmOffsetExecutive::BuildOffsetOfFaceuse`: `CreateCurvesFromFace(.., pFU->GetOrientation(), ..)` feeds the 2D-boolean branch taken when the face's UV domain is not contained in the offset surface's; the clipped faces' loops are read with `CreateCurvesFromFace(.., SM_OT_SAME, ..)`.
- **What happens:** the 2D boolean intersects the offset surface's domain with a planar face made (`SM_OT_SAME`) from the face's UV loops. Taken from an inset's `SM_OT_OPPOSITE` face use the loops run clockwise ((1,0) (0,0) (0,1) (1,1)), so that planar face is inside out, the intersection has no face, and the face gets no offset at all.
- **Trigger:** SolidCraft rig shell/4567 (after the axis fix of WR-343 / #973): a vase whose profile meets the axis at a slant, shelled 2 mm inward; the bottom's offset surface's domain is [0.0077, 1] × [0, 1] against the face's [0, 1]²: 1001.
- **How found:** SolidCraft regression rig on the SMLib fork (tangency-labs/solidcore#974); gdb on the fork's C++ build.
- **Confirmed:** on the fork's C++ build: the vase shelled 2 mm inward gives 11609.122935, agreeing to 7.8e-10 relative with an independent quadrature of the vase less the cavity inside the exact offset; the rig dump gives 13 faces with a clean check.
- **Fix (fork commit "SMLib: an inset face that does not fit its offset surface's domain is clipped right side out"):** when the face does not fit (and the operation is not a local operation), its loops are taken counterclockwise (`SM_OT_SAME`); the clipped faces' loops are read in the face use's orientation, which the offset face is made with.
- **Rust port:** opt-in `Kernel::fixes.offset_clip_right_side_out` (default `false`, upstream behaviour), read in `OffsetExecutive::build_offset_of_faceuse` and `build_boolean_offset_faces` (`crates/solidcore/src/offset/offset_executive/p1.rs`). Test `issue_974_inset_face_clipped_right_side_out` (a create_plane square's opposite face use against an offset plane whose domain holds a band of it), `#[ignore]`d: on that sheet the default path already clips to one offset face, so the fixture does not reproduce the inside-out clip and the fix is not yet exercised; it needs an inset face like the shell/4567 vase's bottom. No difftest case compares the opt-in path (the offset runners use the default kernel). Fixes tangency-labs/solidcore#974.
