# heal.heal_data_p2: both kernels spend minutes in Cache_FaceProps_Stage3's loop-bisector curve intersection on one corpus body (2026-11-01)

- **Unit:** `heal.heal_data_p2` (`HealData::cache_face_props_stage3`), reaching `query.face_p3` (`find_and_classify_loop_bisector_cached`) and the curve/curve global solver.
- **Input:** STEP corpus `ap203/nasty_cheese.stp`, body 0, built through `SmBrepConstructor` (`--step-case --constructor`). Both kernels build the same body (2 regions, 2 shells, 331 faces, 1148 edges, 792 vertices; manifold). Its volume query fails on both sides (`SM_ERR`).
- **What happens:** `SmApiHealBrep` runs for minutes on both kernels and gives no result inside the corpus limits.
  - C++: the shim's forked child is killed by its 120 s alarm inside `HealBrep`. The corpus record stops after the volume stage, with the crash index after the ops. This is the alarm, not a fault.
  - Rust: the `--step-case` child is killed at the corpus run's 600 s timeout (1089 s measured in a bisect run).
- **Where (sampled under gdb, two or three stops each, the same frames every time):**
  - C++: `SmBrep::HealBrep` <- ... `SmHealData::HealTgts` -> `Cache_FaceProps_Stage3` -> `SmFaceProps::SetProps_Stage3` -> `SmFace::ClassifyLoops` -> `sms_FindAndClassifyLoopBisector` -> `SmFace::CurveOnClassify` -> `SmCurveClassification::IntersectEdges` -> `SmCurve::GlobalCurveIntersect` -> `SmGlobalSolver::SolveIt` -> `SmGlobalSolver::SolveBranch` (18 levels) -> `SmCCIGlobalSolver::LocalSolve` -> `SmCurve::LocalCurveIntersect` -> `SmLocalSolveNd::SolveIt` (`SmCCIntersectENFO`).
  - Rust: `api_heal_brep` -> `heal_brep` -> `HealData::heal_targets_with` -> `cache_face_props_stage3` -> `FaceProps::set_props_with_seam` -> `query::face::p4::classify_loops_cached` -> `p3::find_and_classify_loop_bisector_cached` -> `curve_on_classify_mut` -> `CurveClassification::intersect_edges_mut` -> `Curve::global_curve_intersect_body` -> `CciGlobalSolver` `solve_it` -> `solve_branch` (18 levels) -> `local_solve` (`simple_coincidence_checker`, `local_curve_intersect`), evaluating a `CrvOnSurf` on a cone.
  - The subdivision is shallow (18 levels on both sides) but explored to full width: the loop bisector against one edge's curve-on-surface is never culled, so each solve runs on the order of 2^18 or more leaves, each with a local solve. On the Rust side one solve ends only at `MAX_SOLVE_BRANCHES` (2^23 branches, `geom::global_solver`), then the classification moves on. C++ has no bound.
- **Since:** tangency-labs/solidcore#2183. Before it, `Fix_DegenFaces`' squeeze left a sliver's two edges apart in Rust (its stitch glues were refused as nested edits), and the healed body (1 region, not manifold, volume 0) was reached in seconds. With the glue made, as upstream makes it, Rust's heal goes on to the classification C++ already spends its time in.
- **Verdict:** upstream behaviour, matched; no upstream defect is recorded (the solve does terminate). The corpus verdict for this body stays CRASH, because both sides time out; it is not a regression against C++.
- **Open:** a bound on this classification's solve that keeps the result would be an opt-in of its own, unless the SolidCraft fork has one (to be checked against tangency-labs/smlib's `SmGlobalSolver`, `SmCCIGlobalSolver` and `sms_FindAndClassifyLoopBisector`).
