# Findings

One file per finding: Rust-vs-C++ disagreements, upstream bugs, nondeterminism and other
facts later agents need. Every PR adds its own new file, so parallel PRs never conflict.
Never append to a shared file. Upstream C++ defects (UB, crashes, hangs, nondeterminism,
wrong results, wrong docs) also get their own file under
[`plan/upstream-issues/`](../upstream-issues/README.md) for the upstream maintainers.

- **Name:** `<unit id or general>--<short-slug>.md`, lowercase, e.g.
  `topology.brep_p3--turn-to-nurbs-uv-trim-notify.md`. Pick a slug nobody else will.
- **Content:** start with `# <unit>: <title> (<YYYY-MM-DD>)`, then the unit, inputs, both
  values, suspected cause and the PR.
- **Records are not edited later (like ADRs).** To update, resolve or supersede a finding,
  add an addendum: a new file `<same name without .md>--addendum-<YYYY-MM-DD>-<slug>.md`
  whose first line after the title is `Updates: <path>`. Fixing a typo in your own PR's
  file before it merges is fine.
- **References** from code, `crates/difftest/known_mismatches/<unit>.toml` or unit notes
  give the file path,
  e.g. `plan/findings/topology.brep_p3--turn-to-nurbs-uv-trim-notify.md`.
- **Older references** to `plan/findings.md: <heading>`: grep the heading under this
  directory (`grep -rlF '<heading>' plan/findings/`). The heading is the first line of its
  file.

## History

Until 2026-10-25 findings were sections of one shared file, `plan/findings.md`. On
2026-10-25 `scripts/split_archives.py` split it into one file per `## ` section here
(`<unit or general>--<slug>.md`, unit taken from the heading, `-2`, `-3`, ... for
repeated names) and deleted it; `python3 -I scripts/split_archives.py check` proves the
split lossless. Each file starts with the section's heading as `# <heading>`, followed by
the section verbatim. Their names do not carry the archive order. The archive's
introduction read:
