## Method

* **AST source.** libclang 21 (Python bindings) over `bin/cpp/compile_commands.json`, i.e. the exact
  flags of the reference C++ build (`-DNDEBUG -DNOMINMAX -DSM_GRAPHICS_CALLBACKS=1 -std=c++17`, so
  `SM_DEBUG_CODE`, `SM_USE_TBB`, `SM_USE_GLOBAL_CACHE` are *off*; `SM_GFX_CODE` is on). All 224
  SMLib + 13 SM_API TUs (plus the SM_API_test / prog_test TUs for test attribution) parse with zero errors.
* **Edges.** Every `CALL_EXPR`, function/method reference (`DECL_REF_EXPR`/`MEMBER_REF_EXPR`, which
  also captures function pointers and callbacks), `new` -> constructor, `delete` -> destructor of the
  static type (and of all derived classes), and constructor -> own destructor. Template members map
  to their primary template by qualified name.
* **Virtual calls (conservative).** An unqualified call to a virtual method reaches the method and
  *every* override in every (transitively) derived class (class-hierarchy analysis, CHA). Qualified
  calls (`Base::f()`) are non-virtual. The pip `libclang` bindings lack `clang_getOverriddenCursors`,
  so overrides are matched by USR method signature along the class hierarchy. RTA (dispatch only to
  classes whose constructor is reachable) is reported for information only; the CHA set is the plan.
* **Dead debug branches.** `if` statements whose condition is provably false in this build are not
  followed: never-written locals/file statics initialised to `FALSE`/`0` (the ubiquitous
  `SmBoolean bDebugMe = FALSE; if (bDebugMe) {...}` pattern), `*Debug*` flags and `DebugLevel()`
  comparisons against non-negative literals, combined with `!`/`&&`/`||`. 1135 such branches were
  pruned; they only draw/dump/print (`Draw`, `smgfx_*`, `Dump`, file I/O of debug snapshots).
* **Roots.** The SM_API entry points listed below plus `SmBrep::ReadFromFile` (the native .smb/.brp
  reader that every prog_test and pt_TestFiles fixture goes through; needed to feed difftests).

## Global state and nondeterminism hazards

## Caveats

* CHA over-approximates: e.g. `SmSurface::Evaluate`-style dispatch makes every surface subclass
  (including volume-deformation `SmCrvInVolume`/`SmSrfInVolume`/`SmBendVolume` types) in scope. Units
  whose code mostly fails RTA are flagged in their notes.
* Calls through macros are seen after expansion (e.g. `SER(...)`, `NER(...)`); calls inside
  `#ifdef SM_DEBUG_CODE` are not compiled and not seen, matching the reference build.
* Implicit destructor calls of stack objects are approximated by constructor -> destructor edges.
