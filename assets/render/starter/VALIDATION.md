reproduction. It does not claim a rendered SolidCraft scene or application-ready

## Checks completed

- **53 focused checks passed:** 21 surface, 13 environment and 19 lighting tests.
- All **240 PNG exports** decoded and reproduced with identical pixel arrays.
  Hashes, dimensions, channel depths, color/data roles, paths, positive normal
  hemisphere and height/normal physical-scale agreement were checked.
- All **240 PNG pixel hashes** matched between Linux and Windows. Compressed
  bytes matched for 112 maps; the other 128 differ only in encoding. The Linux
  encoding occupied 23,993,945 bytes, versus the submitted 23,879,602 bytes.
  PNG file receipts identify the submitted bytes; decoded-pixel receipts are
  the cross-platform reproduction authority.
- Surface boundary comparisons passed for all admitted patterns. Analytic tests
  cover both tangent axes, derivative magnitude, scale changes, multiple image
  resolutions, sRGB anchors, zero-height normals and full 16-bit PNG preservation.
- Both plain weave and the separate 2/2 twill pattern were checked for their
  actual periodic crossing sequence. Wrong cycle parity is rejected.
- All **24 HDR files** regenerated byte-for-byte and passed strict full-stream
  decoding. All decoded pixels exactly matched the separate FFmpeg floating-point
  RGBE decoder. The largest absolute quantization error was **0.46539607**;
  each error also satisfied its own shared-exponent quantization-step bound.
- All **24 HDR file hashes** also matched across Linux and Windows.
- HDR analytic checks cover cardinal orientation, exact latitude solid angle,
  pole/seam continuity, uniform-field `E = pi L`, unit directions and black vacuum.
- Lighting data regenerated byte-for-byte and matched across Linux and Windows.
  The worst higher-order area-quadrature
  difference was **0.01749%**, below the declared 0.15% convergence threshold.
  This is convergence evidence, not a rigorous mathematical error bound.
- Independent lighting checks cover six projected disks, a closed-form directional
  sphere response, inverse-square far field, area/range cancellation under uniform
  scene scaling, one-sided emission, solar-disk integration, EV ratios, colored
  emitters and passive cards. Source-color luminance is counted exactly once.
- Hostile data cases include duplicate JSON keys/IDs, nonfinite values, booleans,
  very large integers, unknown fields, malformed types, unsafe paths, oversized
  inputs, corrupted PNG/HDR streams, false semantic metadata and stale receipts.
- Original catalog validator: **0 errors, 0 warnings**. Prepared SELENE validator:
  **0 errors**, with `awaiting_native_source` and `runtime_ready: false` preserved.
- Exact asset attribution and whitespace are checked with the pack validator
  and the repository checks. No review media, bytecode, cache or native model is
  part of the resource collection.

The unlit material sheet, HDR field sheet and numerical Lambert-sphere sheet were
inspected from ignored `target/render-starter-review/`. These are diagnostic
visualizations, not SolidCraft renderer output. The wood, cork and regolith
resources remain visibly procedural approximations; no photorealism or calibrated
species/location identification is inferred from those images.

## Issues found and corrected during review

Independent review corrected periodic weave admission, separate twill semantics,
invalid object/type handling, false map metadata acceptance, seam-evidence checks,
oversized integer conversion and a colored-light test that counted color twice.
The submitted tests retain coverage of those cases. All 53 checks also passed
in the separate Windows environment.

Windows Git was observed converting hashed text sources to CRLF. Scoped
`.gitattributes` now fixes LF for the render authoring sources and catalog data,
and explicitly treats PNG/HDR as binary. JSON writers emit canonical UTF-8/LF
bytes. No global Git setting or other worktree was changed.

Eight convergence-diagnostic values differed between Linux and Windows by at
most `1.01e-15`. Their export now reports 12 decimal places, while convergence
acceptance continues to use the unrounded result. A threshold-boundary regression
checks that reporting precision cannot let a failing calibration pass. Source
gains and transforms retain their existing precision.

Two LED/aperture recipes place their source inside/intersecting the opaque
`0.25B` calibration sphere. STU-018 and STU-019 therefore retain null unresolved
gains and an explicit requirement for an aperture/diffuser fixture. STU-024
retains its dependency on the actual existing Sun's response. The generator
does not assign invented numbers to make these records look ready.
