Updates: WR-344

#### WR-344 (update, 2026-11-15). `offset_extended_edges_mated` is removed

With extended convex edges, `piecewise_merge` relates the mated offsets of a manifold edge instead of intersecting them again, except an edge whose mate failed in `EdgeuseOffset`, which is intersected even where it is a tangent sector (#1795). The fix is now unconditional and the flag is gone; SolidCraft already ran with it on. Removed: the field `UpstreamFixes::offset_extended_edges_mated`, SolidCraft's preset line, its entries in `fixes.json` and `issue_2260_gn_pipe_refined_range_end.rs`, the `flag` argument of `relates_mated_offsets` and every test setting of it.

- **Results:** none change in the goldens (measured: every goldens unit with this flag left out of a run with the batch's other flags on moves no row, and the run with only the retired flags on moves none attributable to it).
- **Tests:** the fix is pinned only by the unit test `fork_9d8ace9_unmated_tangent_sector_is_intersected` in `offset_executive/p1.rs`, which fails on the old predicate. No end-to-end test fails on the old path; the shell tests that run through it (`tests/wr_344_half_frustum_shell_keeps_its_rim.rs`, `tests/issue_1795_extended_edges_mated.rs`, `tests/issue_1818_mated_shell_wall.rs`, `issue_469_extended_offset_mated_edges_not_intersected_again`) are not pins of it. Removed with the upstream path: `wr_344_default_keeps_the_rim_on_exact_extensions` (it now duplicates the fixed test), `mated_offsets_alone_shell_the_square_to_circle_loft` (it duplicates `default_fixes_shell_the_square_to_circle_loft`), the ignored probe `issue_1795_extended_edges_mated` in `issue_1795_shell_hole_through_arc.rs`, and the flag-off assertions of `fork_9d8ace9_unmated_tangent_sector_is_intersected`.
