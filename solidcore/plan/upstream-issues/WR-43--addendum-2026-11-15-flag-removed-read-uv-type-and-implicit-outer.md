Updates: WR-43

#### WR-43 (update, 2026-11-15). `curve_bounded_surface_read_uv_type_and_implicit_outer` is removed

The fix is the default and its flag is gone (tangency-labs/solidcraft#14246, batch surface1). `CurveBoundedSurface::read_from_db` (`surface/curve_bounded_surface.rs`) always reads each UV boundary with the type in that boundary's own header and keeps the implicit-outer flag it reads. Upstream reads the UV boundaries with the last 3D boundary's type (0 when there is none, so every UV boundary then fails with `SM_ERR`), and it builds the surface with the flag `false` whatever the record says. Removed: the field `UpstreamFixes::curve_bounded_surface_read_uv_type_and_implicit_outer`, SolidCraft's preset line, its entries in `fixes.json` and `issue_2260`'s list, the `kernel_with_wr43` test helper and the default-path halves of the module's read tests.

- **Tests:** the read tests in `surface/curve_bounded_surface.rs` run on the default kernel. `read_ascii` now pins `implicit_outer() == true` (its stream says `1` in the implicit-outer line). `read_uv_without_3d_uses_type_zero` becomes `read_uv_without_3d_uses_its_own_type` and pins that the record reads: no 3D boundary, and one 2D UV boundary read with its own B-spline header. The goldens test `surface_curve_bounded_surface::wr43_tests::read_records_are_read_as_their_headers_say` replays every `read_db` case and accounts for each outcome from the record. A non-surface basis header is refused. Every record whose UV headers say B-spline curve reads, with or without 3D boundaries, and gives back the implicit-outer flag written and each UV boundary exactly as written: degree, knots, and each control point's coordinates and weight. A record whose UV headers say line has its B-spline bodies read as line data. Each boundary that reads is a line whose point starts with the body's first two values (last control-point index, degree). A refusal happens only with two or more UV boundaries, when the misaligned read misses the next header ("curve type not read", "curve dimension not read" or an unknown type).
- **Results:** 36 goldens rows of `surface.curve_bounded_surface` move, all `read_db` cases, each accounted for by the test above:
  - 16 records with B-spline UV headers and no 3D boundary now read (upstream: type 0, status 1001): gen0000, gen0042, gen0047, gen0048, gen0052, gen0079, gen0085, gen0109, gen0170, gen0188, gen0222, gen0266, gen0314, gen0328, gen0331 and `read_db_uv_without_3d_type_zero`; gen0297 (no boundaries at all) moves by its implicit-outer flag, now 1 as written (+1 in the block sum).
  - 13 records with line UV headers now read their boundaries as lines, where upstream read the B-spline body behind each header with the 3D type (or failed with type 0): gen0014, gen0182, gen0185, gen0186, gen0198, gen0206, gen0231, gen0245, gen0296, gen0319, gen0320, gen0390 and `read_db_uv_header_type_ignored`.
  - 6 records with line UV headers and two or three UV boundaries are now refused at the next header: gen0073 and gen0267 (1007, curve dimension not read), gen0101 and gen0308 (1007, curve type not read), gen0094 and gen0154 (1001, unknown curve type).
