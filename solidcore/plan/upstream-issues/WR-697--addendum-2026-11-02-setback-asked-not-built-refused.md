Updates: WR-697

#### WR-697 (update, 2026-11-02). A setback asked for at a corner that builds none is dropped without a word
- **Severity:** Wrong result (silent)
- **Area:** Fillets (corners)
- **Location:** `source/SMLib/src/SmFilletCorner.cpp`, `SmFilletCorner::Create` (the fork's, after `SmBlendCorner::ClassifyBall` and `ClassifySetBack`), and every corner but `SmFilletConvexNxNCorner` (to which `SmFilletConcaveNxNCorner` hands its setback corners) and the blend corner's Setback: they ignore `m_dSetBackDist`. Since dc757a6 the N x N corners ignore it too.
- **What happens:** a caller asks for a corner to be set back with `SmFilletExecutive::SetSetBackFill` before the corners are made, or with `AddSetBackVertex` and then `SmFilletCorner::SetSetBackDist` on the made corner. Only the Setback reads a `SetSetBackFill` request, and only the Setback and the N x N corners build a setback set on them. Elsewhere (a two-blend corner, an Nx1 corner, a Ball, ...; with the fork's dc757a6, an N x N corner too) the corner is built as if no setback were asked for, with no error. The fork refuses this only in its capi (`round_edges`, `SMLIB_ERR_UNSUPPORTED`, dc757a6); its SMLib builds the corner without the setback.
- **Source:** SolidCraft review of solidcore #2365 (the port of tangency-labs/smlib#125). This is solidcore-native, with no fork commit: solidcore does not port the fork's capi, so the refusal is made in the kernel. solidcore keeps the N x N setback paths that dc757a6 deletes (`WR-697--addendum-2026-11-02-smlib125-four-rounds-and-open-setbacks.md`), so those corners build their setbacks and are not refused.
- **Rust port:** under the same opt-in `Kernel::fixes.fillet_blend_corner`, with one comment (`SETBACK_NOT_BUILT`), `CornerUnsupported`, decided from the requests and the classification only, on one predicate, `blend_corner::setback::builds_setback`: the corner is the Setback, or an N x N corner (convex or concave) that no blend corner took. At both doors a caller asks for a setback through:
  - `SetSetBackFill` before the corners are made: in `FilletSession::create_corners`, after the Ball and Setback classifications, a vertex with a `set_set_back_fill` request whose corner builds no setback is `CornerCreation::Refused`.
  - `AddSetBackVertex` and `SetSetBackDist` on the made corner (`FilletSession::set_corner_setback`): `do_filleting` refuses first when any corner with a setback (`> 0`) builds none (`blend_corner::setback::asked_setback_not_built`).
  An N x N corner is refused at neither door, as before the port: it builds a setback set on it, and ignores a `SetSetBackFill` request (which only the Setback reads; `issue_2343_curved_setback`'s `without_its_flag_a_corner_beside_a_curved_face_builds_as_before` keeps that). Without the flag nothing changes.
- **Triggers:** a 40 x 40 x 20 box's corner (40, 40, 20) with two of its edges rounded 2, set back 4 by either door: built without the setback before, refused now. The box [0, 40]^2 x [0, 20] less the cylinder r 20 about (40, 40), at (20, 40, 20), rounded 2 (an N x N corner without `fillet_setback_beside_curved_faces`): set back 4 with `SetSetBackDist` it is the setback corner (16 faces) with the flag as without it.
- **Confirmed:** in solidcore. SolidCraft's seven rig cases that set back an N x N corner (three equal rounds at a box corner, a bar's corner beside a cylinder, a concave notch) build with the values they had before.
- **Tests:** `crates/solidcore/tests/fork_smlib125_open_setbacks.rs`: `setback_asked_where_the_setback_is_not_built_is_refused` (the fill's door), `setback_set_on_a_corner_that_builds_none_is_refused` (the corner's door), each flag on (refused) and flag off (built), and `nxn_corner_builds_the_setback_set_on_it`; `crates/solidcore/tests/issue_2365_nxn_setback_corners.rs`.
