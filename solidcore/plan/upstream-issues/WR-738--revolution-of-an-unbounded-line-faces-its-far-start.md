#### WR-738. `CreateCanonical` of a surface of revolution faces its profile's STEP start, so a revolved unbounded line that crosses the axis inverts no point of the nappe its origin lies on
- **Severity:** Wrong result
- **Area:** Surfaces and volumes
- **Location:** `source/SMLib/src/SmSurfOfRevolution.cpp:663-686`, `SmSurfOfRevolution::CreateCanonical` (def. `:639`): the frame's X axis points from the axis point to `pSweptCurve->EvaluateSTEP(sCrvIvl.GetMin())`, or to the point at 45% of the interval when that start is on the axis or within 1 degree of its direction. `STEPInversion` (def. `:484`) then rotates a point into the frame's +X half plane (`TransformPointToStartPlane`) and intersects it with the generator.
- **What happens:** for an unbounded profile (an `SmLine` made by `CreateCanonical`, as a STEP `LINE` is built) the STEP interval is `[-SM_INFINITE_PARAMETER, SM_INFINITE_PARAMETER]`, so the start is 1 234 567 along the line from its point. A line that crosses the axis has that start, and its point at 45% (-123 456.7), on the far side of the crossing: the frame faces the other nappe, and every point of the nappe the line's point lies on rotates into a half plane the generator does not reach there, so `STEPInversion` returns `SM_ERR` (1001). The surface's own evaluation is unaffected (`EvaluateSTEP` turns the generator by `u`, so `u = 0` is the profile itself, as in ISO 10303-42), so the point it evaluates at `(0, 1)` does not invert. Upstream notes the open case at `:679` ("one should intersect the rot axis with the curve here").
- **Trigger:** `Line::create_canonical((1, 0, 0), (1, 0, 1))` revolved about Z through the origin: X = (-1, 0, 0); `step_inversion` of `(2, 0, 1)` (the line's point at `s = 1`, STEP `(0, 1)`) fails with 1001, as do `(0, 2, 1)` and `(1/2, 0, -1/2)`. A line parallel to the axis, and a bounded segment, are not affected. Found by jyviko testing #2623 (tangency-labs/solidcore#2628, item 4).
- **How found:** read during porting (the Rust `create_canonical` is a line-for-line port of `:651-715`); reproduced in the port.
- **Confirmed:** no (the difftest's `surface.surf_of_revolution_p1` runner builds no unbounded profile; the port gives upstream's frame by default, `unbounded_line_crossing_the_axis_inverts_on_its_origin_side` with the flag off).
- **Rust port:** behaves as upstream by default. With `Kernel::fixes.revolution_frame_from_profile_origin`, `SurfOfRevolution::create_canonical` (`crates/solidcore/src/surface/surf_of_revolution/p1.rs`) takes the X axis from the profile's point at parameter 0 when its STEP interval holds it (the point the profile is defined from: a STEP line's `pnt`, a conic's point on its reference direction), else from its start as upstream; upstream's 45% point still serves when that point is on the axis. A profile whose interval starts at 0 (a B-spline on `[0, 1]`, a segment from `Line::from_points`) keeps upstream's frame bit for bit. Tests in `p1.rs`: the line above inverts `(2, 0, 1)`, `(0, 2, 1)`, `(1/2, 0, -1/2)` to `(0, 1)`, `(90, 1)`, `(0, -1/2)`; its mirror `(-1, 0, 0) + s (-1, 0, 1)` inverts `(-2, 0, 1)` and `(0, -2, 1)`; a line parallel to the axis inverts the same either way; the bounded frames are unchanged. Solidcore-native, no fork commit.
- **Not fixed here:** a profile that crosses the axis still inverts only on one side of it. The points of the other nappe (`(-2, 0, -3)`, the line's point at `s = -3`) rotate into the +X half plane where the generator is not, whatever the frame; `STEPInversion` intersects only the point turned onto the +X side, not also the one turned onto the -X side (STEP `u + 180`).
