#### WR-464. `SmOffsetGeometryCreation::FaceuseOffset` succeeds with no surface whenever the offset surface is missing, so any miss is read as a collapsed round
- **Severity:** Wrong result (a face that has lost its offset surface is silently dropped from the offset or mated across)
- **Area:** Offset
- **Location:** `source/SMLib/src/SmOffsetGeometryCreation.cpp`, `SmOffsetGeometryCreation::FaceuseOffset`: `if ( rNewSurface == NULL ) { return SM_SUCCESS; }` after `CreateOffsetSurface`; its callers `SmOffsetExecutive::DoSolidOffset` (skips the face) and `DoExtendedOffset` (`if (sOffsetSurface == NULL)`, mates the faces beside it at a sharp edge).
- **What happens:** the only offsets that give `SM_SUCCESS` with a `NULL` surface today are the radius tests of `SmCone` (and so `SmCylinder`), `SmSphere` and `SmTorus` (a convex round no thicker than the offset distance). Nothing says so: `FaceuseOffset` returns the same success for any other missing surface, which the callers read as a collapse.
- **Trigger:** none in the current surface kinds; any future (or fork) `CreateOffsetSurface` that returns `NULL` for another reason.
- **How found:** review of the #397 fix (tangency-labs/solidcore#1072).
- **Confirmed:** no (read at c9c5979; no trigger exists, so this is a robustness defect)
- **Fix (the fork's tangency-labs/smlib "an offset that collapses onto its spine is told apart from a missing one"):** `SmSurface::OffsetCollapses(distance, tol)` (cone, cylinder, sphere, torus from the offset radius, which their `CreateOffsetSurface` also uses; `FALSE` for every other surface) decides the collapse. `FaceuseOffset` reports it as an explicit flag, and fails on any other missing surface.
- **Rust port:** opt-in `Kernel::fixes.offset_missing_surface_fails` (default `false`, upstream behaviour). `Surface::offset_collapses` (`crates/solidcore/src/surface/surface/p1.rs`, with `Cone::offset_collapses`, `Sphere::offset_collapses`, `Torus::offset_collapses`) and the check in `OffsetGeometryCreation::faceuse_offset_with_backend` (`crates/solidcore/src/offset/offset_geometry_creation.rs`): `None` is a collapse only, any other missing surface is `SM_ERR`. The face-use result keeps `None` for the collapse instead of the fork's explicit flag, which is the same information once the flag is on. Test `collapse_thresholds_of_the_analytic_surfaces` (`crates/solidcore/src/offset/offset_executive/face.rs`: thresholds of the cylinder, cone, sphere and torus, with and without the flag). No Rust surface gives a `NULL` offset that does not collapse, so the failing branch is not reachable by a test. Fixes tangency-labs/solidcore#1072.
