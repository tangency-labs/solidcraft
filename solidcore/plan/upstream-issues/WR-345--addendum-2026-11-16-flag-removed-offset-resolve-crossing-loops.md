Updates: WR-345

#### WR-345 (update, 2026-11-16). `offset_resolve_crossing_loops` is removed

`DoExtendedOffset` now always rebuilds an offset face whose loops cross (`ResolveCrossingLoops`, `crates/solidcore/src/offset/offset_executive/crossing_loops.rs`) before the piecewise merge. The flag is gone. SolidCraft already ran with it on. Removed: the field `UpstreamFixes::offset_resolve_crossing_loops`, SolidCraft's preset line, its entries in `fixes.json` and the `issue_2260` list, and every test setting of it. The trimmed-edge test in `offset_geometry_creation.rs` (an inset shell's edge whose two ends are cut by its neighbours' offsets) no longer reads it either.

Two changes made the routine fit to be the only path:

- **An uncut loop of one edge use is not a stretch too short to build.** An edge use that no crossing cuts is one stretch, from vertex to vertex. On a loop of one closed edge (a hole's circle) the two ends meet, and the routine refused it as "three loops cross at one point" (`SM_ERR_BAD_INTERSECTIONS`). An uncut hole beside a crossing therefore made the whole offset fail. Only that case is exempt (the same vertex node at both ends); other short stretches are still refused (unit test `only_an_uncut_loop_of_one_edge_passes_the_length_test`). Test `an_uncut_hole_beside_a_crossing_is_kept_whole` (`tests/issue_865_whole_offset_of_holed_plate.rs`): #977's plate with a second hole, offset 1.5 inward, now gives a valid solid of the closed-form volume.
- **Unmerged offsets with crossing loops are refused.** With results not merged, `PiecewiseMerge` only stitches the offset faces. It never cuts the walls the crossing loops come from (here a hole's wall and a side wall) where they pass through each other. Without the routine, the stitched body kept a face whose loops cross (`SmFace` test #38). With it but without this refusal, the stitch enclosed no region. Either way no valid body can be built where the offset builds walls (a body that is a manifold solid, the local operation's included, or a sheet thickened), so such an offset is now refused as `OffsetFailure::LoopsCross { crossing: LoopCrossing::Unmerged }` (`SM_ERR_BAD_INTERSECTIONS`, 1027). Tests `crossing_loops_without_the_merge_are_refused`, `upstream_holes_crossing_the_sides_unmerged_are_refused` (the eleven goldens cases below: each refused, and its offset faces fail test #38) and the controls `loops_that_do_not_cross_still_offset_without_the_merge` and `upstream_holes_clear_of_the_sides_still_offset_unmerged`.

- **Results:** 11 `offset.offset_executive_p2` rows (`fuzz00035` and the `pe_Fillet_cyl_on_box_w_hole*` / `w_tan_hole*` cases whose loops cross). Each went from a body that fails `check_brep` Level 2 (test #38; `w_tan_hole2` also test #37) to the `Unmerged` refusal. 2 `topology.brep_local_operation` rows (gen0007, gen0018) go from refusal 1001 to refusal 1027 (`Unmerged`), with the input put back. 2 `topology.assert_valid` messages go from the shell's "not a manifold solid" refusal to the walls-touch refusal (fork a759622). No valid result becomes a refusal.
- **Removed tests:** `default_fixes_refuse_the_open_cavity_and_retain_the_input` (the flag-off half of `tests/fork_1b016ca_cavity_floor_under_opening.rs`).
