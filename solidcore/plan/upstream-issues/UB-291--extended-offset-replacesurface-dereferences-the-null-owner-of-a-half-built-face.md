#### UB-291. `DoExtendedOffset` keeps a face whose build failed, and `ReplaceSurface` dereferences its surface's null owner face (SIGSEGV)
- **Severity:** Crash / undefined behaviour
- **Area:** Offsets and shells
- **Location:** at the pin `3fd5b95`: `source/SMLib/src/SmBrep.cpp:26589`-`:26596`, `SmBrep::ReplaceSurface` (def. `:26573`): `pTopFace = pOld->GetFace()` is null and `pTopFace->SetSurface(pNewSurface)` dereferences it. It is reached from `source/SMLib/src/SmOffsetExecutive.cpp:1683` (`SmOffsetExecutive::DoExtendedOffset`, def. `:1105`, the per-face extension loop `:1659`-`:1729`). The half-built face comes from `SmOffsetExecutive::BuildOffsetOfFaceuse` (def. `:3643`), which calls `MakeFaceWithCurves` at `:3753` as `if (... == SM_SUCCESS) { ... }` with no else and returns `SM_SUCCESS`; and from `SmBrep::MakeFace` (def. `SmBrep.cpp:19061`), which restores the surface's earlier owner (null for a new offset surface) at `:19158` "regardless if MakeFaceTopology fails or succeeds", and on failure returns before `rpNewFace->m_pSurface = pSurface; pSurface->SetOwner(rpNewFace)` (`:19188`-`:19189`). The face `MakeFaceTopology` linked into the B-rep stays there, pointing at a surface that no face owns.
- **What happens:** a null pointer dereference. `MakeFaceTopology` fails, `MakeFace` and `MakeFaceWithCurves` return the failure, `BuildOffsetOfFaceuse` drops it, and `DoExtendedOffset` (`:1355`) goes on with the half-built face in `m_pOffsetBrep`. The extension loop takes that face and calls `ReplaceSurface(pF, pExtSurf, UNSURE, NULL, FALSE)`. `pOld = pF->GetSurface()` is the offset surface (an `SmSphere` here) with `m_pOwner == NULL`, so `SmSurface::GetFace()` returns null.
- **Trigger:** an `SmOffsetExecutive` (solid offset operation) over `SmOffsetGeometryCreation(0.4, -1e-300)`, with `SetExtendConvexEdges(TRUE)` and `SetCreateOffsetSolid(TRUE)`. Then `DoExtendedOffset` of `SmApiCreateSphere((0.5, 1, -1), 2.5)`, whose B-rep tolerance is set to 1e-6. The approximation tolerance's magnitude, 1e-300, becomes the offset B-rep's tolerance (`:1115`; WR-749). With that tolerance `SmBrep::FindInfiniteRegion` returns no region, `FindAndSetInfiniteRegion`'s `NER(pNewInfRegion)` (`SmBrep.cpp:8705`) returns 1006, and that fails `MakeFaceTopology` through `TestClosureSplitRegion`. The same offset with approximation tolerance 1e-6 (fixture `extended_sphere_outset`) succeeds, and the C++ and Rust agree on it. Any other failure of that face build reaches the same crash; the tiny tolerance is the known trigger.
- **How found:** generated difftest case (nightly fuzz of 2026-11-04, run 41821585108: `offset.offset_executive_p2` fuzz00167, base `extended_sphere_outset` with `/config/member_approx_tol = -1e-300`). gdb on the release harness: `SIGSEGV in SmBrep::ReplaceSurface` ← `SmOffsetExecutive::DoExtendedOffset` ← the shim's `eval_impl`. At the fault, `rbx` (`pTopFace`) is 0 right after `SmSurface::SetOwner(pNewSurface, pTopFace)`. A hardware watchpoint on the sphere's `m_pOwner` shows `MakeFaceTopology` setting it to the face and `MakeFace` resetting it to 0. Finish breakpoints show `FindAndSetInfiniteRegion` = 1006 → `TestClosureSplitRegion` → `MakeFaceTopology` → `MakeFace` → `MakeFaceWithCurves` = 1006, then `BuildOffsetOfFaceuse` = 1000. In the same run, the offset B-rep's `m_sThisZoneTol3d` at `FindInfiniteRegion` is 1e-300 (1e-6 in the base case).
- **Confirmed:** yes, crash in the C++ reference run (prebuilt release harness at the pin, x86-64 Linux, 2026-11-04), case `fuzz00167` of `offset.offset_executive_p2`. Tracked upstream as tangency-labs/smlib#135.
- **Rust port:** not affected. `make_face` keeps a face that failed after installation owning its surface (`topology/brep/p7.rs`), and safe Rust has no null owner. Since #2393 the port refuses the trigger's tolerance by name before building anything (`OffsetFailure::ToleranceUnresolved`, WR-749), so this case never builds a face. The difftest runner's crash trap (#2737: every C++ call reaching `DoExtendedOffset` runs in a fresh child) turns this crash into a rejected case. `fixtures/offset.offset_executive_p2/fuzz00167.json` is parked with `cpp_defect = "UB-291"`; its expected Rust result is that refusal, checked by `crates/solidcore/tests/issue_2393_extended_offset_tiny_approx_tol.rs`.
