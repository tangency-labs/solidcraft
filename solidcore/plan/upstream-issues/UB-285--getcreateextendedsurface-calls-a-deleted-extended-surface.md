#### UB-285. `SmOffsetExecutive::GetCreateExtendedSurface` calls through an extended surface that `DoExtendedOffset` deleted (shell of `Solids/nurb_fillet.smb`)
- **Severity:** Crash / undefined behaviour
- **Area:** Offset
- **Location:** `source/SMLib/src/SmOffsetExecutive.cpp`, in `SmOffsetExecutive::GetCreateExtendedSurface` (def. `:2237`). Its cache hit `m_vSurfExtSurf.At(pBase)` (`:2249`) returns a surface, and the virtual call `pExtendedSurface->GetNaturalUVDomain()` (`:2256`) jumps to a heap address. The cache is filled at `:2342`. `SmOffsetExecutive::DoExtendedOffset` (def. `:1105`) deletes surfaces in its per-face extension loop (`:1659`-`:1729`) and leaves their entries in the map: `delete pExtSurf` at `:1702` and `:1726`, `delete pOrigSurf` at `:1714`. Each delete carries the upstream comment "this leaves a stale pointer in m_vSurfExtSurf table". It was not established which delete leaves the entry that is read here, or whether the read is a second face on the same base surface or a new surface allocated at a freed key's address.
- **What happens:** a use after free. The cached surface was freed, so its vtable pointer comes from reused heap memory, and the indirect call executes a heap address (SIGSEGV with `pc == fault address`, a heap address).
- **Trigger:** `SmApiShellBrepFull(brep, -0.5, TRUE, TRUE, FALSE, open, result)` (extended convex edges, merged results, no offset solid) on `Solids/nurb_fillet.smb` (`upstream/TestFiles/pt_TestFiles`). `open` is one face, and 19 of the body's 20 faces crash (`GetFaces` order; all but face 4, which shells, and the port agrees with it). Distance -1.0 also crashes (faces 0 and 1 tried). -0.2 and +0.5 fail the shell without crashing (faces 0 and 1 tried). It still crashes with `MALLOC_PERTURB_=165`.
- **How found:** a builder's report, reproduced through the difftest harness. `topology.assert_valid` copy cases with `copy_op = 4` (the shim's `copy_operation`: `SmApiBrepCopy`, then `SmApiShellBrepFull` of the copy), `index` = the open face, `value = -0.5`. The C++ side kills the difftest process with SIGSEGV. There is no gdb on the machine. The stack was read by an `LD_PRELOAD` SIGSEGV handler that dumps return addresses from the faulting stack, then `addr2line` on the release harness binary: `GetCreateExtendedSurface` ← `DoExtendedOffset` ← `ShellBrep` ← `SmApiShellBrepFull` ← `copy_operation` (shim). The return address is the instruction after the second `call *0x1e8(%rax)` in `GetCreateExtendedSurface`, preceded by `rpExtSurface = pExtendedSurface`. That is the cache-hit branch, `:2255`-`:2256`.
- **Confirmed:** yes, crash in the C++ reference run (prebuilt release harness at the pin, x86-64 Linux, 2026-10-31). The use-after-free class comes from the call target and the stack, not from a sanitizer.
- **Rust port:** not affected (safe Rust; the extended-surface cache holds no raw pointers). The same shells return without a panic for all 20 open faces (checked once in release: 3 fail with `SM_ERR`, 17 build a body). `crates/solidcore/tests/ub_285_nurb_fillet_shell.rs` keeps faces 0 and 1 (skipped without the upstream checkout, as in CI's test job). No difftest fixture holds this input, so no guard is needed. A future fixture with it needs a `run_cpp` guard that returns `Output::rejected` naming UB-285, as UB-281 does in `topology.assert_valid`.
