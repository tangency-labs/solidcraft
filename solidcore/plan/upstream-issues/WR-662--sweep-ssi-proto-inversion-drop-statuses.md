#### WR-662. Sweeps, surface/surface intersection, proto-topology and analytic `STEPInversion` drop failed statuses and go on with unset values
- **Severity:** Wrong result
- **Area:** Primitives and sweeps; surface intersection; proto-topology; analytic surfaces
- **Location:** `source/SMLib/src/SmPrimitiveCreation.cpp` (about 250 dropped statuses: `CreateCylindricalBox`, `CreateLinearSweep`, `CreateSphereNoPole`, `CreateConeEllipticEnds`, `sm_CreateAnalyticRotationalSweep`, `Boolean2D`, `CreateTaperExtrude`, `CreatePipeSweep`, `CreateCurveSweep`, `sm_CreateRuledSurfaceFromOffsetCurve`, the rotational and repeated linear sweeps, `CreateBlendPrimitive`, `CreateCurveSweepFromEdges/Faces`), `SmTopologySweep.cpp` (`DoSweep`), `SmTransSweepGeometry.cpp`, `SmRotationalSweepGeometry.cpp`; `SmSurfaceIntersector.cpp` (`IsPointOnCurve`, `AddStartPoint`, `sm_ComputeCurveType`, the boundary start points), `SmProtoTopology.cpp` (`SetXSectInterval`, `CombineProtoVertex`, `CombineProtoEdge`, `Split`, `sm_AreSameCurve`, `IsInteriorPoint`, `sm_IsInterior`, `sm_AreOverlapping`, `sm_WhichPVToCombine`, `RemoveCoincidentNoEdgeProtoVertex`); `SmSphere.cpp`, `SmSurfOfRevolution.cpp`, `SmCone.cpp` (`STEPInversion` answers and their voided callers).
- **What happens:** a call fails (an evaluation, a copy, transform, trim, face construction, stitch or orientation; a drop or evaluation in a near-tangent intersection test; an inversion) and its status is not checked, so the operation reads an unset value: a sweep reports success without its caps, a start point of a separate nearby curve is taken as already traced, two start points are paired on an angle that stayed 0, a failed inversion reads as `SM_LT_EXTERIOR` and drops an intersection point.
- **Trigger:** mostly no valid input is known to fail these calls; the failures are injected in the tests below. A natural one: `SmApiCreateLinearSweep` of a circle and a separate line with caps succeeds with two walls and no caps.
- **How found:** code reading; the SolidCraft fork (tangency-labs/smlib) passes these statuses on in c8f6a31 (sweeps), bcc6f01 (surface intersection, proto-topology; its `ALIGN_DIR_WITH_PREVIOUS_POINT` part is `ssi_alignment_statuses`, WR-658) and dfc7cb6 (analytic inversion answers), tracked as #2009 group C.
- **Confirmed:** in the port, by injected-failure tests. The pinned C++ drops the statuses, so with the flags off the port matches it.
- **Rust port:** opt-in `Kernel::fixes.sweep_statuses_pass_on` (c8f6a31), `ssi_proto_topology_statuses_pass_on` (bcc6f01) and `analytic_inversion_answers_apart` (dfc7cb6), all off by default. `planar_path_sweep_statuses` now also returns the mitre's `BrepIntersect`/`GlobalCurveSolve` failures, as the fork does. Sites through `crate::error::passed_on` / `ignore_or_pass_on` / `ignored_or_pass_on`; the question-answering helpers answer "no" (or `None`) when a point cannot be evaluated. Not ported (left as upstream): SM_API's fixed-axis `SetCanonical` and validated `SetMinMax` (cannot fail); `create_plane_surface`'s `SetMinMax` (no kernel in the API); about 120 plain pass-on sites of `SmProtoTopology.cpp` and `SmSurfaceIntersector.cpp` (definition `Resolve`/`MergeIntoObject`, create/find/remove functions, `UpdateFaces`, the overlap-removal block, boundary trims and drops, `ComputeLawPointValues`, `AddPointToCurve`); `SmSphere::GlobalPointSolveSTEP` (no Rust counterpart); the fork's eager path normal in `CreateSweepAlongPlanarPath` (the port's lazy one avoids a failure on collinear lines). Tests: `crates/solidcore/tests/issue_2009_group_c_{sweep_statuses,sweep_p3,inversion}.rs`, `primitive::primitive_creation::p2::planar_path::audit_tests::{issue_2009_*,audit_483_failed_mitre_search_is_returned}`, `topology::proto_topology` and `intersect::surface_intersector::p1` unit tests citing bcc6f01, `surface::sphere::tests::inversion_location_passes_on_a_failed_inversion`.
