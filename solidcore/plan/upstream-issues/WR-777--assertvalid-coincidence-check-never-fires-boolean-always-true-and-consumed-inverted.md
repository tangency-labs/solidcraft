#### WR-777. `SmBrep::AssertValid`'s coincident-topology check never fires: `ContainsCoincidentTopology` returns TRUE unconditionally, and its result is consumed inverted

- **Severity:** Wrong result
- **Area:** B-rep validation (`AssertValid`)
- **Location:** `source/SMLib/src/SmBrep.cpp:30435`, `SmBrep::ContainsCoincidentTopology` (def. `:30407`); `:35373`, `SmBrep::AssertValid`.
- **What happens:** two coupled defects make the coincident-topology check a no-op, while its expensive search still runs.
  1. `ContainsCoincidentTopology` initialises the accumulator `SmBoolean bCheck = FALSE` (`:30435`). The intent, spelled out by the comment just above the return, is that `bCheck` means "all checks passed": it should start `TRUE` and be ANDed to `FALSE` by any failing `SM_ASSERT_PAIR_REPORT(..., SM_LEVEL_2, ...)`. Because it starts `FALSE`, `bCheck &= ...` stays `FALSE` forever, so `return !bCheck` (`:30842`) is `TRUE` unconditionally. The function always claims coincidence was found, whatever the search saw.
  2. `AssertValid` consumes that boolean inverted: `bRtn &= this->ContainsCoincidentTopology(-1,NULL,NULL,pAList)` (`:35373`) ANDs the "coincidence found" flag into the validity flag, where it should be `bRtn &= !…` (valid iff *no* coincidence). The correct check — `SM_ASSERT_BOOLEAN_REPORT(15, SM_LEVEL_2, (… == FALSE), …)` — is present but commented out (`:35374`), presumably because with defect 1 the predicate is always false and the assertion always fails.
- **Trigger:** any body with genuinely coincident topology (two coincident vertices/edges/faces, or an edge lying on a face it is not incident to) passes `AssertValid`; a body with none is reported "coincident" by the boolean. `AssertValid` also calls `ContainsCoincidentTopology` with the default `eTestLevel = SM_LEVEL_0`, so the level-2 reports are skipped regardless, and the `pCoinEnts1/2` output arrays are passed `NULL`, so the pairs are discarded. Net: the search runs and every result is thrown away.
- **How found:** reading the C++ while profiling why a SolidCraft design (a knurled grip) spends ~230 s of a 267 s rebuild in the per-feature `AssertValid` check, ~33 s of it in `ContainsCoincidentTopology`'s edge/face coincidence search.
- **Confirmed:** yes, in the Rust port, which matched the C++ line for line: `contains_coincident_topology` set `found` once to `true` and never changed it, and `assert_valid/brep.rs` did `rtn &= …found`. The fix (2026-11-12) makes `found` report whether a pair was found, and consumes it as `rtn &= !found` gated at level 2 with the test-15 report; it moves 50 `topology.assert_valid` and 36 `topology.brep_validation` golden cases (coincident bodies now fail, clean bodies report `found` false). Not run against a C++ build.
- **Fix:** initialise `bCheck = TRUE`; consume the result as "no coincidence" (`bRtn &= !ContainsCoincidentTopology(…)`), or reinstate the commented-out level-2 report. Both halves must change together; either alone makes the check either a permanent no-op or a false failure of every body.
- **Rust port:** fixed (was faithful to the bug). `found` now reports whether a pair was found, and `brep` reports the result as test 15 at level 2.
- **Results that change:** a body with coincident topology becomes invalid (the check fires), and a clean body stops being reported coincident by the boolean.
