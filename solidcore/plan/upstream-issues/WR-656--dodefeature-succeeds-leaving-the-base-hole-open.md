#### WR-656. `SmFeatureExecutive::DoDefeature` returns success with the base's hole open when no base patch could be built
- **Severity:** Wrong result (an open body, volume 0, reported as success)
- **Area:** Blends and defeaturing
- **Location:** `source/SMLib/src/SmFeatureExecutive.cpp`, `SmFeatureExecutive::DoDefeature` (def. `:1588`), which ignores the statuses of `PartitionFeature`, `BuildPatches` and `ApplyPatches` and returns `SM_SUCCESS` (`:1618`); `SmFeature::BuildPatches` (def. `:892`) sets `m_bBaseRebuilt = FALSE` when a loop's base patch fails (`:918`), and `SmFeature::ApplyPatches` (def. `:1119`) then copies nothing into the base (`if ( m_bBaseRebuilt && !m_bBaseWasApplied )`, `:1129`). `PartitionFeature` has already removed the feature's faces from the base.
- **What happens:** when no patch fills the void the feature leaves in the base, the base is handed back with the feature's faces cut out and the hole open. Nothing in the call's status says so; the caller can only see it in `GetBaseWasApplied` or by checking the body. `AssertValid` passes the open body.
- **Trigger:** a 30 x 20 x 10 box, `AddFeature({face 0}, SM_RB_EXTEND_SURFACE, SM_RB_FROM_OTHER_BREP)`, `DoDefeature`: status 1000, 5 faces, 12 edges, not a manifold solid, volume 0, no check failures (the four side faces extended do not close the top). In the port (flags off) the same holds for every planar face of a box, an L block, a stepped block, a plate with a pocket or a hole, two boxes and a boss on a plate; the side and cap faces of a cylinder and a cone; the boss's side face; and the 12 edge rounds of a box with every edge rounded r 3 (some of these take seconds or minutes first; HANG-52, #1972). Where a patch is built the call works: the hole's wall of the plate gives exactly 6000, a rim round of a cylinder adds back 51.53, a corner ball of the rounded box adds 1.68.
- **How found:** a private sweep of ordinary operations on ordinary bodies (not committed): 84 defeature cases returned success with a body that is not a closed solid.
- **Confirmed:** yes, on the C++ build: the sweep's native driver gives the box case above status 1000 and the same open body (5 faces, manifold 0, volume 0, `check_failures 0`). The other bodies were run on the port only.
- **Rust port:** behaves as upstream by default. With the opt-in `Kernel::fixes.defeature_refuses_open_base` (own design, not in the fork), `FeatureExecutive::do_defeature` refuses a feature whose `base_rebuilt` is false after `build_patches`, before its patches are applied: `SM_ERR` with the first base edge of the first loop whose base patch is not used, the base B-rep put back from a `Brep::clone_for_rollback` taken at the start of the call, and the executive's features, patches and marks dropped. A base rebuild type of `SM_RB_NONE` saves an empty patch and counts as rebuilt, so a hole the caller asks for is not refused. `OffsetFacesExecutive::take_off` (WR-615's mitred groups) takes that refusal as a base not applied and refuses as before. Test: `crates/solidcore/tests/wr_656_defeature_open_base.rs` (the box both ways, and the hole, rim round and corner ball unchanged with the fix).
