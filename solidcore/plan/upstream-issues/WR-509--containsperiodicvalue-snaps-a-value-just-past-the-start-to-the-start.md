#### WR-509. `SmExtent1d::ContainsPeriodicValue` sets a value just past an interval's start, given a period up, to the start, so a very short ellipse arc inverts every point to its start
- **Severity:** Wrong result
- **Area:** Geometry and tolerances
- **Location:** `source/SMLib/src/SmExtent1d.cpp:1236`, `SmExtent1d::ContainsPeriodicValue` (def. `:1186`).
- **What happens:** a value outside the interval is wrapped into `[m_dMin, m_dMin + dPeriod]`. When it then lies within the tolerance (`SM_EFF_ZERO_DEG`, 1e-4 degrees, by default) of the top of that period, and a period down is within the tolerance of `m_dMin`, it is set to `m_dMin`, not to its own value a period down. A value up to the tolerance past the start is taken back to the start. `SmEllipse::STEPInversion` takes its angle from `atan2` in `[0, 360)` and maps it through this function, so on an arc whose start is not in `[0, 360)` it returns the start for every point that close to it, and for an arc shorter than the tolerance for every point of it.
- **Trigger:** the 70.9232 x 16 ellipse where a plane cuts a cylinder, trimmed to 3.39e-6 of its NURBS parameter (8.6e-5 mm of a tube's wall cut by another tube's end plane): `SmEllipse` test 2 fails (2.1e-5 off) though its NURBS lies on the ellipse (#1518). In the port's tests, a 70.9232 x 16 ellipse on `[-10, -10 + 7e-5]` degrees inverts the points at a quarter, half, three quarters and the end of the arc to -10.
- **How found:** SolidCraft (tangency-labs/solidcore#1518; the fork's fix tangency-labs/smlib#46).
- **Confirmed:** in the Rust port, which matches the C++ source line for line (`Extent1d::contains_periodic_value`); tests `issue_1518_short_arc_inverts_each_point_to_itself` (`curve::ellipse::p2`) and `issue_1518_value_past_start_moves_down_a_period` (`geom::extent1d`). Not run against the C++ build.
- **Fix:** the fork moves the value down by the period and keeps it when that lies in the interval (within the tolerance of either end), as tangency-labs/smlib#46.
- **Rust port:** behaves as upstream by default. With `Kernel::fixes.periodic_value_past_start_moves_down`, `Extent1d::contains_periodic_value_with` (and the `clamp_periodic_value_with` and `is_value_on_periodic_boundary_with` built on it) applies the fork's fix. The callers that hold a kernel pass it: `Ellipse::step_inversion` and `drop_point_fast`, the cone's trim-domain test and ellipse trim intervals, `Plane::make_new_plane_ellipse`, the sphere's and the torus's iso curves, and the sphere's `AssertValid` tests 4 and 5. The kernel-less callers stay upstream: `Extent1d::are_disjoint_periodic`, `Extent2d::contains_periodic_point`, the ellipse's STEP evaluation, `transform_point_to_start_plane` and the cone's `angle_in_sweep`.
