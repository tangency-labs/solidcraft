#### WR-305. `SmFace::CurveOnClassify` classifies an interval running along a face edge as inside the face, leaving a sliver solid
- **Severity:** Invalid result (a solid 3e-8 thick; `SmFace` checks 33/34, "Face has (partially) Coincident Edges")
- **Area:** Boolean (curve classification)
- **Location:** `source/SMLib/src/SmFace.cpp` (`SmFace::CurveOnClassify`, the per-interval loop before `ClassifyFaceInterval`); `source/SMLib/src/SmCurveClass.cpp` (`SmCurveClassification::CheckIntervalCoincidence` is dead code: its call in `CleanupAndValidate` is commented out).
- **What happens:** a curve can meet a face edge at two separate solutions: a tangent point (`IntersectEdges`) and, within tolerance, the edge's end vertex (`IntersectVertices`). The interval between them has both ends on the edge, and stays within tolerance of it. `ClassifyFaceInterval` still puts its middle inside the face, so the boolean splits the face along a curve within tolerance of its own boundary.
- **Trigger:** the column [0, 1.5]^2, z -3.9..3.2, minus an r 1.5 cylinder about x = 0.0003, y = 0, z -4..3.5. On each cap the cylinder's circle is tangent to the edge y = 1.5 at x = 0.0003 and passes 3e-8 from its vertex (0, 1.5) (intersection tolerance 2e-5). SMLib keeps a second solid 3e-8 thick whose caps have coincident edges.
- **How found:** SolidCraft regression rig case booleans/1279 on the SMLib fork (tangency-labs/solidcore#1057).
- **Confirmed:** no (read at c9c5979 `source/SMLib/src/SmFace.cpp:8817` and `source/SMLib/src/SmCurveClass.cpp:14059`-`14060`; reproduced on the SolidCraft fork build: the capi test `booleans/cylinder_grazing_box_edge` fails before the fix and passes after, with volume 7.1 (2.25 - the integral of sqrt(1.5^2 - u^2) over u = -0.0003..1.4997), and the rig's operands give one manifold solid with a clean check, two solids with 11 failures before). The Rust test below was not run against any C++ build.
- **Fix:** the fork's `SmCurveClassification::ClassifyEdgeInterval`, run on each interval before `ClassifyFaceInterval`. It applies to 3D classification curves only, when the interval's middle is not yet classified. Both ends must lie on one edge E: each classifies to E or to one of its vertices, and at least one to E itself. If the interval's midpoint then drops onto E (global solve, no guess) within `GetXSectTol3d(SrcZoneTol3d, ZoneTol3d(E))`, the middle classifies to E.
- **Rust port:** opt-in `Kernel::fixes.classify_edge_interval` (default `false`, upstream behaviour). The new function is `CurveClassification::classify_edge_interval` in `crates/solidcore/src/intersect/curve_class/p3.rs`. It is called from `curve_on_classify_mut` in `crates/solidcore/src/query/face/p2.rs`. Test: `crates/solidcore/tests/issue_1057_cylinder_grazing_box_edge.rs`. Default off, so no difftest case changes. Fixes tangency-labs/solidcore#1057.
