#### UB-286. `sm_CreateBezSegments` writes through a null next-segment pointer for a one-span curve whose end is not clamped
- **Severity:** Crash / undefined behaviour
- **Area:** Curves
- **Location:** `source/SMLib/src/SmNurbsCrv.cpp`, `sm_CreateBezSegments` (def. `:478`), called by the B-spline branch of `SmCurveCache`'s Bezier span build (`source/SMLib/src/SmCurveCache.cpp:1299`). The function keeps `NQw = NULL` and sets it to the next segment's control points only `if( iq LT nsp-1 )`. After each segment's end knot run it copies control points through `NQw` whenever `ie LT m`: `InitCP(Qw[p],&NQw[save])` in the knot insertion branch and `InitCP(Pw[ie-p+i],&NQw[i])` after it.
- **What happens:** for a curve with exactly one non-zero span (`N_BasisGetSpanCount`: the `i` in `p..m-p` with `U[i] != U[i+1]`), `NQw` is never set. If the knots after that span's end run on to a different value (the end is not clamped), the loop leaves the run with `ie < m` and writes through the null `NQw`: SIGSEGV, a write to address 0. With two or more spans, `NQw` still points at the last segment's own control points, and the same writes overwrite them without crashing. The caller already refuses a curve without a span (`NonZeroSpanCount < 1` is `SM_ERR`).
- **Trigger:** any curve cache of such a B-spline curve. Nightly fuzz case `topology.proto_topology_p2` fuzz00353 (`--fuzz 600 --seeds 40`; base `gen0683`, mutation `/objects/2/curve/bspline/u/9 = -0.0`) gives a degree-4 curve the knots `-4.77 ×5, -3.77 ×4, -0.0`: the last knot no longer closes the end run, so `ie` stops at 8 of `m` 9. The knot vector is still non-decreasing; #1967's sweep listed the case as "non-monotone knots", which it is not.
- **How found:** #1967's fuzz sweep left it open as an FFI guard gap. Reproduced on main with the nightly command. The kernel log names the fault: `segfault at 0 ... error 6` (a write) at file offset `0xbfd3d2f` of the difftest binary. That is virtual address `0xbfd4d2f`, which `addr2line`/`nm` resolve to `sm_CreateBezSegments(curve*, SmTArray<curve*>&) + 0x54f`. Reading the function gives the condition above.
- **Confirmed:** yes, crash in the C++ reference run (prebuilt release harness at the pin, x86-64 Linux, 2026-11-01).
- **Rust port:** not affected. `nurbs::nurbs_crv::create_bez_segments` holds the next segment as an `Option` and returns an index error when it is unset, where upstream writes through `NULL`. The fuzz case returns without a panic.
- **Guard:** `solidcore_ffi::validate::bez_segments_write_null` replays `sm_CreateBezSegments`' indices: the span count, the skip over a first knot's over-multiplicity, and the first segment's end run. The proto script's curve validator (`topology.proto_topology_p1`, shared by p2 and p3) refuses exactly those curves, and the fuzz case is in `crates/difftest/tests/fuzz_corpus/topology.proto_topology_p2.json`. Other units that send B-spline curves to a C++ curve cache can use the same check.
