#### UB-274. `SmOffsetGeometryCreation::MateEdges` reads the surface of a faceless offset edgeuse
- **Severity:** Crash / undefined behaviour
- **Area:** Offset
- **Location:** `source/SMLib/src/SmOffsetGeometryCreation.cpp:1838`, `SmOffsetGeometryCreation::MateEdges` (def. `:1802`); the same pattern for the first edgeuse at `:1835`. Reached from `SmOffsetGeometryCreation::EdgeuseOffset` (`:2301`, the extend-convex branch) <- `SmOffsetExecutive::BuildOffsetOfEdgeuses` (`SmOffsetExecutive.cpp:3070`) <- `SmOffsetExecutive::DoExtendedOffset`.
- **What happens:** `MateEdges` checks only that its four edgeuse pointers are non-NULL (`NER`, `:1812-1815`), then calls `pOffsetEdgeuse->GetFace()->GetSurface()` and `pOtherOffsetEdgeuse->GetFace()->GetSurface()`. `SmEdgeuse::GetFace` (`SmEdgeuse.cpp:332`) returns NULL for an edgeuse that is not a loopuse edgeuse or has no loopuse, and nothing checks it. In the trigger the first `GetCreateExtendedSurface` call returns `SM_SUCCESS`, and the process faults on the inlined `GetSurface()` read (`mov 0x98(%rax)` right after `call SmEdgeuse::GetFace`) of the second: `pOtherOffsetEdgeuse` (the edgeuse `SyncronizeOffsetEdgeuses` mapped to the radial mate) has no face. Which offset edgeuse is faceless and why the mapping returns it was not traced.
- **Trigger:** `Fillet/box_extrusion1.smb` (whole body, no shell faces), `SmOffsetExecutive` solid offset with distance 7.25, inset, extend convex edges on, merge results off, B-rep tolerance and member approximation tolerance `3.51852241715e-4` (difftest unit `offset.offset_executive_p2`, operation `solid`).
- **How found:** crash in the C++ reference run (offset coverage sweep, difftest PR #1689). Re-run alone in a fresh process; SIGSEGV backtrace from an `LD_PRELOAD` handler, frames resolved with `addr2line` and the faulting instruction read from the disassembly (the prebuilt reference libraries have symbols but no line info).
- **Confirmed:** yes (SIGSEGV in `MateEdges` <- `EdgeuseOffset` <- `BuildOffsetOfEdgeuses` <- `DoExtendedOffset`, reproduced alone). The NULL `GetFace()` is read from the disassembly, not from a debugger.
- **Fix direction (upstream):** `NER` the two faces (and their surfaces) before `GetCreateExtendedSurface`, as the port does.
- **Rust port:** no crash. `OffsetGeometryCreation::mate_edges` (`crates/solidcore/src/offset/offset_geometry_creation.rs`) takes the faces as `Option`s and returns `InvalidInput` ("edge use without face") for a faceless edgeuse. The Rust side of the trigger runs to completion (checked with the C++ call skipped).
