#### WR-772. `SmTopologySolver::MayContainAnswer` culls directed answers by their in-plane offset

- **Severity:** Wrong result
- **Area:** Solvers
- **Location:** `source/SMLib/src/SmTopologySolver.cpp`, `SmTopologySolver::MayContainAnswer`, the `SM_SO_DIRECTED_MINIMIZE`, `SM_SO_SIGNED_DIRECTED_MINIMIZE` and `SM_SO_DIRECTED_MAXIMIZE` arm, at v1.0.1 (`3fd5b9548d19aa8c12c29bc9637a96d42a06f8a5`).
- **What happens:** A directed answer is a difference `D` whose view projection `Q = N x D x N` (normal `N = m_cpOptVectors[0]`) is parallel, within 2 degrees, to the direction `V = m_cpOptVectors[1]` (`SmTopologySolver.cpp:175-182`). Such differences lie, up to that angle, in the plane spanned by `N` and `V`. The arm's comment says it tests whether the other box centre is farther from that plane than the two radii. The code instead builds the plane through the first centre with normal `V x N` and projects the second centre *onto* it. It then compares the distance from that projected point to the first centre, which is the in-plane offset, with the sum of the radii. The in-plane offset is the directed answer itself, so every branch whose directed answer is farther than the two bounding radii is culled. The min/max tests that follow also use the in-plane offset unscaled, against answers measured as `|N x D x N|`.
- **Trigger:** View normal Z, direction Y. The point (0, 0, 0) against a vertex at (0, 10, 0): `D = (0, 10, 0)` projects to itself, which is parallel to Y, so it is a directed answer at distance 10. The plane normal is `Y x Z = X`. Projecting (0, 10, 0) onto the plane x = 0 leaves it unchanged, at in-plane offset 10 from the origin, which exceeds the radii 0 + 0. The branch is culled for all three operations.
- **How found:** Following a review question on PR [tangency-labs/solidcore#3161](https://github.com/tangency-labs/solidcore/pull/3161) about the directed arm. On main, 52 of the 60 directed (`operation` 11, 12, 13) shell-vertex records in `intersect.topology_solver_p2` return no answer. Admissible directed answers exist in them, for example a vertex at (-0.7, 0, 0) from the origin for view Z and direction X.
- **Confirmed:** yes, from the pinned source. No C++ build was run. The Rust port reproduced the arm exactly. The Rust test `directed_culling_keeps_admissible_answers_and_culls_the_rest` in `intersect/topology_solver/p1.rs` fails on the ported arm (DirectedMinimize culls the answer at distance 10).

The Rust fix encloses `Q` over every pair of box points in the double-cross metric with outward-rounded intervals. It culls a branch only when no pair can be within the 2-degree direction test, or when every admitted value is more than the query tolerance worse than the best answer. For the signed operation, whose sign also follows the operand order, the value bound is `-|Q|` at most.
