Updates: WR-89

#### WR-89 (update, 2026-10-31). Opt-in sampling of the requested B-spline knot spans

- **Status in the port:** `Kernel::fixes.gap_samples_use_trimmed_spans`, off by default. The default retains the pinned C++ behavior, including its first-span sampling and whole-knot-range normalization.
- **Location:** `source/SMLib/src/SmGap.cpp:1751-1890`, `SmGapFunction::BuildSampleSet` at v1.0.1 (`3fd5b95`); `crates/solidcore/src/heal/gap.rs`, `GapFunction::sample_normalized_values` and `trimmed_span_values`.
- **What changes:** after the existing ordered-knot lookup and sample-count adjustment, the opt-in walks only the spans between the requested interval's start and end indices. It normalizes each sample against that requested interval before `evaluate_samples` maps it back. Both surface directions use the same rule. The first and last normalized samples are exactly 0 and 1; a requested end coalesced with a nearby knot still uses the caller's exact end. Sample counts, row-major traversal, previous-sample guesses, tolerance tests, first-over-tolerance stopping and existing sample-cache semantics are unchanged. Set the flag before the gap function is first sampled; changing a kernel flag does not invalidate already-built samples.
- **Why it matters:** a degree-1 curve on `[10, 16]` whose gap to the origin or XY plane is a triangle of height 10 at parameter 15 is sampled over `[14, 16]`. The pinned algorithm finds only `20/3` (about 6.667), missing the peak. With the opt-in the endpoints, span centers and knot 15 are sampled and the maximum is 10. `topology::edgeuse::p1::calc_max_edge_face_gap` already forwards its kernel into this curve/surface gap function; no caller interface changes are needed.
- **Regression evidence:** `wr89_trimmed_curve_finds_the_missed_gap_peak` checks the independently specified triangle's five gap lengths and its first gap over tolerance. `wr89_curve_surface_gap_finds_the_peak_with_the_edge_face_sample_count` checks the same geometry against a plane with the production caller's requested count of 20. `wr89_curve_samples_include_trim_ends_and_span_centers` covers knot-aligned and interior trims, starts at the first knot, increased sample counts and ends within knot-coalescing tolerance. `wr89_surface_grid_uses_both_trimmed_knot_ranges` checks an independently specified 5-by-7 grid on a nonuniform B-spline plane over shifted U and negative V domains, including evaluated distances. `wr89_preserves_full_domain_sampling_and_unsupported_input_errors` checks a full-domain control and the existing degenerate/count guards. Before the sampling correction, three of the four initial tests failed on their enabled-path assertions; the full-domain/error control passed.
- **Native evidence:** at `b6adc4a6f` (merged with main `f560e69d2`), `heal.gap` passes all 749 cases with values, zero failed/deferred cases and `max_rel_err=0`; `topology.edgeuse_p1` passes all 5,586 cases (5,558 with values), zero failed/deferred cases and `max_rel_err=0`. `fixtures/heal.gap/wr89_trimmed_spans.json` adds default-parity cases for the triangle, early stopping, triangle-to-plane gaps and the trimmed surface grid; they compare 92, 92, 348 and 572 values respectively. The enabled correction is tested against independent geometry expectations, not against the defective pinned C++. The full default gate passes 280/280 units, with zero partial or failed units.
- **Scope:** WR-89 only. WR-88's V stride for surfaces outside the B-spline branch and WR-90's `GapArray::append` maximum-index issue remain independent. This restores the intended span sampling; a finite sample grid is still an approximation to the continuous maximum. No complete healing or stitching workflow with the flag enabled is claimed here.
- **Tracking:** tangency-labs/solidcore#1985. WR-89 is a file record; GitHub issue #89 is unrelated.
