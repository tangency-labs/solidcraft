Updates: WR-405

#### WR-405 (addendum 2026-11-02). The default path's off result measured through the public sweep: 12 faces, volume 122, and the check passes it

- **Measured, not assumed.** The record's off result was read from the C++ and reported in the SolidCraft fork, not run (`Confirmed: no`). Building the record's case in the port with `Kernel::fixes.join_touching_loops = false` (the default) now measures: `Surface::create_plane_with_3d_curves` returns `outer_loop_counts = [2]`, `loop_counts = [5, 3]` (the hole is a second outer loop), and the public capped sweep `create_linear_sweep(curves, +z, 2.0, true)` builds **12 faces**, `brep_volume` **122.0** (1e-6) and `check_brep` `Level2` with **0 failure lines**. The inputs are the record's: the 10 x 6 outline `(0,0) (10,0) (10,6) (0,6) (0,3)` and the triangular hole `(0,3) (2,2.5) (2,3.5)`, as line segments, extruded 2 up.
- **The record's face count holds; its description of the body's material does not.** 12 faces matches, and 12 = 6 + 6 is consistent with the plate's solid (six faces) plus the prism's (six): the enclosed volume is 122 = (60 + 1) x 2, the plate plus the 1 mm^2 triangular prism, not a 2-unit separate body around which the plate's faces wrap as a sheet. Only the face count, volume and check were measured; the face arrangement was not inspected beyond that corroboration.
- **The check passes the wrong body**, as the record says: `check_brep` `Level2` reports no failure for the 12-face/122 body, so validity cannot detect the defect.
- **With the flag on** the same case is one loop (`outer_loop_counts = [1]`, `loop_counts = [8]`), 10 faces, volume 118.0, and the `Level2` check is clean too. The on/off difference is isolated to `join_touching_loops`: nothing else changes between the two runs.
- **Limits.** Measured in the Rust port's default path only (the port of upstream `CreateFacesWithCurves`' placement), not compared against the pinned C++ build; no tolerance, fixture or kernel behaviour changed.
- **Tests:** `surface::surface::p2` `issue_892_only_join_touching_loops_changes_the_sweep` asserts both settings' loop counts, face counts, volumes and check results (the existing `issue_892_hole_touching_outline_is_one_loop` keeps the opt-in result).
