#### Updates: WR-80 (2026-11-05). The fix is the default; `ssi_no_reverse_of_empty_trace` is retired

- **Change:** the "something was traced" condition of the 2026-10-29 addendum is now the only path (AGENTS.md §4b). Both reverse traces, `SurfaceIntersector::do_intersection_in` (`intersect/surface_intersector/p5.rs`) and `find_interior_curves` (`p4.rs`), run only after a `TraceCurve` that produced points. Both are one method, `SurfaceIntersector::trace_back` (`p4.rs`), which holds the check once. `UpstreamFixes::ssi_no_reverse_of_empty_trace` and the old path are deleted (PR #1285, #391).
- **Tests:** `crates/solidcore/tests/wr_80_ssi_empty_trace_not_reversed.rs` runs `c2n_quartic_contact_parabola` on the default kernel, through `do_intersection_in`. On the old path it fails with `SM_ERR_NULL_POINTER` from `reverse_curve_direction`. Now it completes: every curve point sampled (65 per curve) lies within the tolerance `1e-6` of both sheets (the first-order distance to each graph: the height over `sqrt(1 + |grad|^2)`; a curve displaced by `9e-6` from the parabola fails), and the curves' x-extents join into one interval from `x = -1` to `x = 1`, with no gap. The unit test `p4::tests::empty_trace_is_not_traced_back` calls `trace_back` on an empty trace; without the check it fails with `SM_ERR_NULL_POINTER`.
- **`find_interior_curves` on the default kernel:** no case is known that reaches its trace-back with an empty trace. There, a start point is skipped when it lies on a found curve, and a crossing start point always starts the curve. Only a tangent start point can leave the curve empty: one whose mean point (`crv_pos`) lies on a found curve while its point on the first surface does not. A probe with two planes found none: parallel planes within the tolerance give no local solution, crossings at 1e-2 to 1e-5 rad give `Crossing` points, and at 1e-7 rad `compute_point_values` fails in `compute_singularity_point` and the start point is skipped. The shared method makes this path the tested one.
- **Cases this moves** (ssi-corpus, approx tol `1e-6`, `--ssi-corpus --jobs 4`, base `554443501` with the pinned C++ reference `cpp-ref-v1-3fd5b9548d19-726643fb17a52b7d`): the C++ answers `ERROR` (`SM_ERR_NULL_POINTER`) for both, as it did; solidcore no longer does.
  - `c2n_quartic_contact_parabola`: Rust `ERROR` -> `WRONG TOPOLOGY`. The intersection completes on the contact parabola; the extra curves are duplicate traces of the tangent curve (WR-76), not this defect.
  - `y23_t2_ex5_two_loops`: Rust `ERROR` -> `INCOMPLETE`. The intersection completes; it does not yet cover both loops through the singular points (the singular-crossing work of WR-77).
  - Corpus totals, Rust: `ERROR=2 INCOMPLETE=25 WRONG_TOPOLOGY=10 PASS=82` -> `INCOMPLETE=26 WRONG_TOPOLOGY=11 PASS=82`; parity with C++ `119/119` -> `117/119`, the two cases above. Every other case's Rust output is unchanged.
- **Difftest units** (same base and reference): `intersect.surface_intersector_p4` 1542/1542, `intersect.surface_intersector_p5` 1731/1731, `intersect.adv_surface_intersector` 1949/1949, `surface.surface_p2` 17585/17585, the same counts as main's CI reports; none of their generated cases reaches an empty trace.
- **Not covered:** `SmAdvSurfaceIntersector`'s own trace-back (`intersect/adv_surface_intersector.rs`, upstream `SmAdvSurfaceIntersector.cpp`) also reverses without checking for points. A read of the code suggests it is reachable only through `TraceCurve`'s tangent-start branch; no case reaching it is known, so it is left unchanged here.
