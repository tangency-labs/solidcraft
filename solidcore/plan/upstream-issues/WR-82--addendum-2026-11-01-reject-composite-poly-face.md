#### WR-82 (addendum 2026-11-01) — Unconditional composite-face rejection and regression coverage (#2170)

- **Updates:** WR-82 (`plan/upstream-issues/WR-82--smcpolyface-addpolyface-accepts-a-composite-face-so.md`).
- **Severity:** Wrong result (stack overflow / crash on misuse).
- **Area:** Intersection / `query.poly`.
- **Location:** `source/SMLib/src/SmPoly.cpp:13157-13188` (`SmCPolyFace::SmCPolyFace`, `SmCPolyFace::AddPolyFace`), `:13227-13241` (`SmCPolyFace::CalculateBoundingBox`), `:13273-13290` (`SmCPolyFace::GetPolyEdges`), `:13368-13385` (`SmCPolyFace::GetPolyLoops`), `:14526-14541` (`SmCPolyFace::GetNormal`), and `source/SMLib/inc/SmPoly.h:3097-3100` (`SmCPolyFace::GetOKBackPtrs`) at v1.0.1 (`3fd5b95`).
- **Root cause:** `SmCPolyFace::AddPolyFace` (`SmPoly.cpp:13177`) accepts any `SmPolyFace*` without checking whether `pPolyFace` is already an `SmCPolyFace` (`pPolyFace->GetType() == SmCPolyFace_TYPE`), appends it to `m_vPolyFaces`, and assigns `pPolyFace->m_pCPolyFace = this` (overwriting a composite face's self-identifying `m_pCPolyFace == this` pointer). Because `SmCPolyFace`'s virtual overrides (`GetPolyEdges`, `GetPolyLoops`, `GetNormal`, `CalculateBoundingBox`, `GetOKBackPtrs`) recursively invoke the same virtual method on every member in `m_vPolyFaces` (or `m_vPolyFaces[0]`), a self-cycle (`c->AddPolyFace(c)`) or mutual composite cycle (`c1->AddPolyFace(c2); c2->AddPolyFace(c1)`) recurses without bound until stack overflow. Upstream callers (`SmLineSegClass.cpp:1879-1883`) only ever add plain shell faces.
- **Unconditional resolution (`AGENTS.md` §1 & §4b):** Under `AGENTS.md` §1 (`wasm32` stack-overflow safety against unbounded input-driven recursion) and §4b (crash, UB, and stack-overflow fixes are unconditional rather than gated behind `UpstreamFixes`), `PolyBrep::add_cpoly_face` and `PolyBrep::cpoly_add_poly_face` (`crates/solidcore/src/query/poly.rs`) unconditionally check `face.composite.is_some()` first and return `Err(SolidError::InvalidInput)` (`nested_composite`) before allocating a face slot, modifying `cpoly_list` or `members`, or overwriting `cpoly_face` back-pointers. Because no constructor or mutator in `query::poly` ever converts an existing plain `PolyFaceId` into a composite face, composite membership stays strictly one level deep across all `PolyBrep` operations while keeping full difftest parity on valid shell-face composites.
- **Regression tests (`#2170`):** `crates/solidcore/src/query/poly.rs`:
  - `tests::wr82_rejects_self_and_nested_composite_faces_preserving_state`: verifies `PolyBrep::add_cpoly_face(c1)` returns `Err(SolidError::InvalidInput)` without allocating a dangling composite or overwriting `c1`'s `cpoly_face` back-pointer, rejects self-cycles (`cpoly_add_poly_face(c1, c1, false | true)`) and nested / mutual 2-cycles (`cpoly_add_poly_face(c1, c2, false)` and `cpoly_add_poly_face(c2, c1, true)`) while leaving `c1` and `c2` member lists (`[f1]`, `[f2]`) and back-pointers untouched, and confirms composite queries still terminate cleanly.
  - `tests::wr82_valid_multi_face_composite_queries_succeed`: adds a third shell face `f3` into `c1` via `cpoly_add_poly_face(c1, f3, false)` and verifies `face_poly_edges`, `face_poly_loops`, `face_normal`, `face_bounding_box`, `face_ok_back_ptrs` (`true` with valid back-pointers), `face_compute_sphere_bound`, and `cpoly_faces_of_composite` complete cleanly with expected multi-face results.
