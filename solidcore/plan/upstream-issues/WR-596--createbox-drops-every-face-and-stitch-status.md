#### WR-596. CreateBox drops every face and stitch status and returns success with whatever faces it made
- **Severity:** Wrong result (a body that fails its own check is returned as a box: a box far smaller than the tolerance comes back with 4 faces and 8 loop-orientation failures)
- **Area:** Primitive creation
- **Location:** `source/SMLib/src/SmPrimitiveCreation.cpp`, `SmPrimitiveCreation::CreateBox` (def. `:270`). Each of its six `CreateFaceFromSurface` calls and its `StitchAndOrient` (`:373`) are made without reading their statuses, and the function returns `SM_SUCCESS`.
- **What happens:** a plane that cannot be made into a face, or a face whose making fails after the face was made, is not reported. For a box far smaller than the tolerance, the top face closes up on the bottom one, and SMLib's test of the closed shell fails (`SM_ERR`) after the face is made. `CreateBox` goes on and `SmApiCreateBox` returns success. The body has 4 faces and fails `AssertValid` (`SmTrimmingTools` tests 3 and 4, loop orientation and zero area, on each face).
- **Trigger:** `SmApiCreateBox` with origin `(0x1.e3e3e2a292902p-28, 0x1.e3e3e3e3e3e3ep-28, 0x1.e3e3e3e3e3e3ep-28)` and size `(0x1.e3e3e3e3e3e3cp-28, 0x1.fe0f5053e3e3ep-16, 0x1.e3f3e3e3e3e3ep-28)`, from SolidCraft's smlib_fuzz (leak-000bffce).
- **How found:** the SolidCraft fork's C API smoke test (`capi/tests/smoke.c`) expects `smlib_make_box` to return 1001 for this box. The fork's fix makes `CreateBox` return each status through `AddBoxFace`. A plane or face that cannot be made returns its status. A face made before its making fails keeps its plane and returns that status. A side of zero extent gets no face. `StitchAndOrient`'s status is returned too. These are tangency-labs/smlib@0df62c8 and tangency-labs/smlib@35008b1 (tangency-labs/solidcore#377, far boxes) and tangency-labs/smlib@449c81c (the face keeps its plane). The port's `solidcore-smlib-api` smoke test `tiny_box_is_sm_err` found that solidcore, like pinned SMLib, returns success.
- **Confirmed:** by reading the pinned source (`CreateBox` has no `SER` on any of these calls). The port matches it: solidcore returns a 4-face body under its default kernel and under every single SolidCraft-preset flag (diagnostic run on the port). A difftest fixture, `fixtures/primitive.api_primitives/wr596_tiny_box.json`, compares this box against the C++ reference.
- **Rust port:** behaves as before by default. With `Kernel::fixes.box_face_failures_propagate`, `PrimitiveCreation::create_box` (`primitive/primitive_creation/p1/primitives.rs`) returns the status of each plane, face and the stitch, and makes no face on a side of zero extent, as the fork's `AddBoxFace` does. The flag is in the SolidCraft preset (`UpstreamFixes::solidcraft`, fork bucket).
