Updates: WR-344

#### WR-344 (update, 2026-10-31). The fork's fix lets a shell return a wall that is no solid

- **Severity:** Wrong result (a false success: `SM_SUCCESS` with a body that bounds nothing)
- **Area:** Offset
- **Location:** the fork's `SmOffsetExecutive::PiecewiseMerge` change (tangency-labs/smlib@85bbfaf) together with `SmOffsetExecutive::ShellBrep` (`source/SMLib/src/SmOffsetExecutive.cpp`), which returns the result of the final `SmMerge::ManifoldBoolean(SM_BO_DIFFERENCE)` without asking whether it is still a closed solid.
- **What happens:** with the mated pairs left out of the merge, an extended offset that upstream's merge refuses (`SM_ERR`, 1001, in `SmMerge::MakeFaceuse`) gets through it as a closed manifold body; the shell's difference with that offset then succeeds with a wall that is not a manifold solid and has no volume. Upstream never gets there: it refuses the shell.
- **Trigger:** tangency-labs/solidcore#1818. A ruled loft (`SmApiCreateSkinPrimitive`, degree 1, capped) from a 40 x 40 square at z = 0 to a circle r 15 at z = 60, four curves a section (the circle's quarter arcs start at -135 degrees, so the four side faces meet along lines from the square's corners and are tangent at the top), shelled 1 inward open at its top (`SmApiShellBrepFull(b, -1, TRUE, TRUE, TRUE, [top])`). The offset (6 faces, closed, manifold) is accepted; the result has 10 faces, 16 edges, 16 vertices, is not a manifold solid, has volume 0, and the pointer check reports eight edges whose ends lie 15.42 from their vertices. Pinned upstream: 1001 in `MakeFaceuse`.
- **How found:** SolidCraft rig report (tangency-labs/solidcore#1818, MarkusReichart).
- **Confirmed:** yes. The pinned C++ (3fd5b95) with only 85bbfaf's one-line change applied to `SmOffsetExecutive.cpp` (rebuilt into a private copy of `libSMLib.a`) returns `SM_SUCCESS` with the same body as the Rust port under `Kernel::fixes.offset_extended_edges_mated`: `offset.offset_executive_p2` case `issue1818_square_to_circle_loft_api_shell_1_top` passed (status, counts and geometry identical, max_rel_err 0) with the Rust flag on against that build. The unmodified pinned C++ refuses (1001), as the default Rust does. The fork's `ShellBrep` on its main (83748ba) still has no check of the final result; its C API refuses the body in `finish` (`SMLIB_ERR_NOT_SOLID`, a solid input must give a closed manifold solid), which is why SolidCraft reports a refusal. Later fork changes refuse this input earlier: with WR-578's loop-gap closing (7ff0a94) the offset fails in `CloseLoopGaps` (1001).
- **Fix (port, opt-in):** under `Kernel::fixes.offset_extended_edges_mated`, with extended convex edges, `OffsetExecutive::shell_brep` of a closed manifold solid refuses a final result that is no closed manifold solid with `SM_ERR`, as WR-454's (`shell_empty_cavity_fails`) and WR-578's (`offset_closes_loop_gaps`) opt-ins refuse an offset that is no closed solid. This moves the fork C API's `finish` check into the shell for this flag; it departs from the fork's SMLib, which returns the body. Default path unchanged (upstream refuses this shell already). Test `crates/solidcore/tests/issue_1818_mated_shell_wall.rs`. The underlying offset defect (why the offset of this loft carries edges 15.42 from their vertices on both paths, which is what the merge refuses) is not fixed here.
