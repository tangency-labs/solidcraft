#### WR-705. The API offset and shell return their result with tolerances under the gaps their construction left
- **Severity:** Wrong result
- **Area:** Offset
- **Location:** `source/SM_API/src/SmApiBrep.cpp`, `SmApiShellBrepFull` (`:2350`) and `SmApiOffsetBrepFull` (`:2438`), the API offset, shell and thicken; they return the `SmOffsetExecutive` result as built.
- **What happens:** the offset builds its faces' edges and vertices at the tolerances its construction sets (the B-rep's zone tolerance, or with WR-671 the original's) and never measures the gaps its intersections and fits leave against them. A gap larger than half a vertex's tolerance is a list-2 Bad Gap in the check, although `SmBrep::ValidateAndUpdateTolerances(FALSE)` would grow the vertex to cover it. Each caller has to run the update itself before the result checks clean.
- **Trigger:** the patch sheet `fixtures/topology.assert_valid/data/issue2111_patch_sheet.smb` copied and offset by d = 0.5 (extended, merged) with `offset_edges_keep_source_tolerance` (WR-671): `check_brep(Level2)` reports 4 vertex/edge Bad Gaps (6.0e-5 to 6.8e-5 against vertex tolerances of 8.3e-5 and 8.4e-5), 5 failures in all.
- **How found:** tangency-labs/solidcore#2111 (SolidCraft ran the update after the offset, WR-679); moving that call into the offset was decided for SolidCraft. Neither the pinned SMLib nor the SolidCraft fork (tangency-labs/smlib main 83748ba, replay/1.0.1 2136965) calls `ValidateAndUpdateTolerances(FALSE)` or grows tolerances in `SmOffsetExecutive`, `SmOffsetGeometryCreation` or the SM_API offset and shell entry points; its only update-mode call is `SmBrep::Validate`'s old-style check. This call site is solidcore's own.
- **Confirmed:** in the port, `crates/solidcore/tests/issue_2111_offset_patch_sheet_gaps.rs` (`offset_updates_its_result_tolerances`, `offset_without_the_update_keeps_its_gaps`). Not a C++ defect run in difftest: the flag is off in every difftest case.
- **Fix (opt-in):** `Kernel::fixes.offset_updates_result_tolerances`. `api_offset_brep_full` and `api_shell_brep_full` run `validate_and_update_tolerances(result, FALSE, no reports, level 0)` on their result before returning it; errors (broken topology links) are returned. The update grows a vertex for a gap between half its tolerance and all of it only with `validate_tolerances_fixes_reported_gaps` (WR-679), so the d = 0.5 offset above checks clean (0 failures) with WR-671, WR-679 and this flag, and keeps its 4 Bad Gaps with WR-671 and this flag alone. With the flag off the offset and shell are unchanged.
