Updates: WR-96

#### WR-96 (update, 2026-11-15). `curve_loop_start_after_previous_end` is removed; a later loop starts after the previous loop's end

`CurveLoops::loop_start_end` (`topology/trimming_tools/curve_loops.rs`) always gives loop `j` the curves `sum(c_0..c_{j-1}) ..= sum(c_0..c_j) - 1`. `loop_start_end` and `find_adjacent_loop_curve` no longer take the kernel; `sample_nearby_points` still does, for its evaluations. Removed: the field, SolidCraft's preset line, the rig's `fixes.json` entry, the flag-list test entry, and `default_ranges_keep_pinned_cpp_results` with the flag-off half of the adjacency test.

- **Defaults:** SolidCraft's preset had the flag on, so the app's results don't change. `Kernel::default()` changes: the second and later loops no longer start on the previous loop's last curve, so adjacency and sampling wrap within their own loop.
- **Goldens:** `topology.trimming_tools`, 14 cases: the record's `loops_start_end_second_loop` (counts `[3, 4]`: the second loop's start goes from 2 to 3) and 13 generated `loops` programs (`gen0117`, `gen0229`, `gen0417`, `gen0433`, `gen0439`, `gen0540`, `gen0604`, `gen0632`, `gen0868`, `gen1009`, `gen1076`, `gen1108`, `gen1159`). Their ops (`start_end`, `adjacent`, `sample`, `same_side`, `update`, inserts) reach the retired code only through `GetLoopStartEnd`; the integer moves are a later loop's start index going up by one, and the float moves are samples taken on the adjacent curve of the right loop instead of the previous loop's last curve. Measured with a temporary runner on every curve-loop state a `loops` program of the unit queries (528 states, the 14 moved cases among them): `loop_start_end` for every index (and two past the end) equals the closed form; `find_adjacent_loop_curve` at each curve's start, end and far outside equals the closed-form neighbour that wraps within the loop; and each `sample_nearby_points` pair equals the two points evaluated directly on that curve and neighbour. All 528 agree bit for bit.
- **Tests:** `wr96_curve_loop_start.rs` checks the ranges of counts `[3, 4, 1]` against the closed form, and adjacency and sampling at both ends of the second loop; the in-file `start_index_and_start_end` now expects `(3, 6)` for the second loop of `[3, 4]`.
