#### UB-290. `SmEdge::IsTopological` calls an edge removable whose one face `SmBrep::DeleteEdge` then merges into itself and deletes
- **Severity:** Crash / undefined behaviour
- **Area:** Topology editing, reached from the Boolean post-process
- **Location:** `SmEdge::IsTopological` (`source/SMLib/src/SmEdge.cpp:4986`) reads edge uses 0 and 2 of the radial list; `SmBrep::DeleteEdge` (`source/SMLib/src/SmBrep.cpp:5752`) reads the primary edge use and its radial (`GetRadial`), which for a non-slit edge is list member 3. `SmMerge::BooleanPostProcess` (`source/SMLib/src/SmMerge.cpp:881`, `:1040`) calls `DeleteEdge` on every edge `IsTopological` accepts, then sets the domain of `pSurfToKeep->GetFace()`.
- **What happens:** for an edge with one face on both sides whose primary edge use and its radial partner lie in the face's two loop uses (the face's loop use runs the edge twice the same way, so the radial pairing runs between the face's two sides), uses 0 and 2 are in one loop use and look like a slit: `IsTopological` returns TRUE. `DeleteEdge` sees the primary and its radial in two loop uses, so no loop split, and merges the face into itself, deleting it together with the surface it was asked to keep. What follows reads the deleted face.
- **Trigger:** tangency-labs/smlib#79's capi test `middle_edge_of_an_arc_tangent_chain_r0_25` (SolidCraft #851's arc part, its top front edge rounded R2, then the edge between that round and the arc wall rounded r0.25): the fork's blend leaves such an edge in the arc wall and the fork's build crashes, SIGSEGV in `SmMerge::BooleanPostProcess` (the fork's commit 8d0fbff). The fork's blend is not in the pinned build; solidcore's regression test `crates/solidcore/tests/issue_2273_slit_edge_is_topological.rs` builds the pairing directly. It takes the slit left in a cylinder wall by tangency-labs/solidcore#1120's union, then swaps the last two members of the slit's radial list along with their orientations and trim curve, so `[a, a', b', b]` becomes `[a, a', b, b']`.
- **How found:** porting smlib#79 (tangency-labs/solidcore#2273).
- **Confirmed:** yes, on the pinned build, but not as a crash. That body, written as an ASCII `.smb` and run through `SmMerge::BooleanPostProcess(TRUE)` with editing enabled (the `boolean.merge_p1` shim, op 1), returns `SM_ERR_NULL_POINTER` (1006) with the body half edited: 20 edge uses become 17 (an odd count), 5 edges become 4 and 4 vertices become 3. Before the fix, the Rust port took the same path: `IsTopological` returned true and `DeleteEdge` failed with `NotFound` partway through the merge.
- **Fix:** smlib@8d0fbff, ported unconditionally (a crash and a corrupt body): before any sampling, `IsTopological` returns FALSE when the primary edge use and its radial are on the same face in different loop uses. A slit with both in one loop use is still removable (`DeleteEdge` splits it off the loop).
