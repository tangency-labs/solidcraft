#### UB-276. `SmPolyBrep::CombineCoincidentVertices` lists a slit PolyFace twice, and `SmPolyIntersector::CheckForSqueezeVertices` squeezes it again through its deleted PolyBrep
- **Severity:** Crash / undefined behaviour
- **Area:** Booleans
- **Location:** `source/SMLib/src/SmPoly.cpp:7714`, `:7755` and `:7757`, `SmPolyBrep::CombineCoincidentVertices` (def. `:7565`): `rFacesUpdated.Add(...)` for every PolyFace attached to a deleted PolyEdge, and for the common and new PolyFace. `source/SMLib/src/SmPolyIntersector.cpp:371`, `:489`, `:636` and `:805`, `SmPolyIntersector::CheckForSqueezeVertices` (def. `:227`): `pF->GetPolyBrep()->SqueezeFaceIfDegenerate(pF, ...)` for every listed face (`SmPoly.cpp:19276`).
- **What happens:** the deleted PolyEdges are the common PolyEdge and all its radial partners. A PolyFace that holds both a deleted PolyEdge and one of its radial partners (a slit) is added once per edge, so it is listed twice; the doc of `rFacesUpdated` already warns that entries "may be stale". `CheckForSqueezeVertices` squeezes each listed face. The first call squeezes the face and deletes it; the second reads the deleted face, whose PolyBrep is NULL, and calls `SqueezeFaceIfDegenerate` on `this == NULL`.
- **Trigger:** prog_test `my_poly_boolean_regression` -> `my_test_ppu` (a polygon union), once the tessellation is fine enough to produce the slit: in the SolidCraft fork, after tessellated triangles are kept within the chord tolerance (tangency-labs/solidcore#390).
- **How found:** crash in the fork's prog_test run on Linux GCC aarch64 (tangency-labs/solidcore#810, filed by jyviko): SIGILL in a garbage jump from `SmPolyBrep::SqueezeFaceIfDegenerate (this=0x0)` <- `SmPolyIntersector::CheckForSqueezeVertices` <- `SmPolyIntersector::MergeLineSegClasses` ... `SmPolyMerge::ManifoldBoolean (SM_PBO_UNION)`. On macOS the freed memory still read as before, so the run passed there by chance.
- **Confirmed:** in the fork build (backtrace above); not at the pin, where the stock tessellation does not produce the slit. The reference build here is not run on it (no shim reaches the polygon Boolean).
- **Fix (fork):** list each face once (`AddUnique` at the three sites). `SqueezeEdge` deletes no faces and a squeeze deletes only its own face, so a list without repeats has no stale entry.
- **Rust port:** not affected; nothing to fix. `SmPolyBrep::CombineCoincidentVertices`, `SmPolyBrep::SqueezeFaceIfDegenerate` and `SmPolyIntersector::CheckForSqueezeVertices` belong to no unit in `harness/callgraph/units.json`: the polygon Boolean is outside the port (`plan/closure.md`, Provably unused), and `query.poly` ports only the PolyBrep queries. The ported B-rep counterparts, `SmBrep::CombineCoincidentVertices` and `SmTopologyIntersector::CheckForSqueezeVertices` (`crates/solidcore/src/boolean/topology_intersector/p2.rs`), return deleted edges and vertices, not a list of updated faces, and squeeze no faces, so the double listing has no analogue. If the polygon Boolean is ever ported, its porter should take `AddUnique` with it (unconditional, crash class). Findings: `plan/findings/general--polybrep-slit-face-listed-twice-not-ported.md`. Refs tangency-labs/solidcore#810.
