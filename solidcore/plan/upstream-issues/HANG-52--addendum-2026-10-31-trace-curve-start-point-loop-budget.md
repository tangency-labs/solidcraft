Updates: HANG-52

#### HANG-52 (update, 2026-10-31). Another trigger of the same defeature path: the start-point loop of `SmSurfaceIntersector::DoIntersection` has no bound on its trace work
- **Trigger:** a 30x20x10 box with all edges filleted at r3 (`create_box` + `fillet_edges(r = 3)`), `AddFeature({face 14}, SM_RB_EXTEND_SURFACE, SM_RB_FROM_OTHER_BREP)`, `DoDefeature`. It finishes, slowly: 645 s on the C++ reference (v1.0.1, 3fd5b95, private driver, one run), 992 s in the Rust port (release, same machine, one run). Both return success with the same open body: 25 faces, 48 edges, not a manifold solid. Faces 0-13 of the same body return in 0.1 to 0.5 s in the port. It is the same API path as the two HANG-52 triggers; whether they share this cause was not checked (the record's location is "not isolated").
- **Location (Rust backtrace):** `SmSurfaceIntersector::TraceCurve` (the step-growing loop, `SmSurfaceIntersector.cpp` about 5055-5526) <- `DoIntersection`'s start-point loop (about 6514-6628) <- `GlobalSurfaceIntersect` <- `SmFace::Intersect` <- `ManifoldBoolean` (the feature executive's `ExtendSurface` rebuild).
- **Mechanism (measured, Rust):** over faces 0-13 and the 119-case SSI corpus one trace takes at most 498 `ComputeNextPoint` calls and one whole start-point loop at most 525. On face 14 the traces run 15,000 or more calls each and end at `TraceCurve`'s own 5000th-point `SM_ERR` (`SmSurfaceIntersector.cpp:5517-5519`), and there are 40+ start points: about 600,000 calls, about 1 ms each. `DoIntersection` ignores a failing `TraceCurve` (`if (TraceCurve(..) == SM_SUCCESS)`, line 6538) and goes on to the next start point, so nothing bounds the total. The trace creeps toward a boundary of surface 2 (its v shrinks geometrically, steps near 1e-7); why it never snaps to the boundary is **not known**.
- **Stale points (C++ is the same):** after the 5000-point `SM_ERR` neither `TraceCurve` nor the `DoIntersection` loop clears `m_vCurvePoints` (line 6538 skips `FlushCurve`, the only clear at 5686), so the next start point's `TraceCurve` finds a non-empty list, skips its start-point set-up (4974) and continues from the stale tail. The Rust port does the same, as it should; it is not changed here. Plausibly the 40+ "traces" are one stuck trace continued again and again (the point lists grew by 5001 each time, 0, 5001, 10001, ...); not verified beyond that.
- **Rust port:** default unchanged. With the opt-in `Kernel::fixes.ssi_start_loop_trace_budget`, the trace steps of one start-point loop together are bounded: `p4::MAX_START_LOOP_TRACE_STEPS` = 50,000 (95 times the largest measured loop; a trace upstream completes needs about 3 calls a point, so up to about 15,000 on its own; about 12 times below face 14's total). When it runs out, `DoIntersection` fails with the existing too-many `InvalidInput` error, also from the reverse trace; the loop's ignoring of a failed trace's status does not swallow it. It is a flag because the C++ finishes this case: under AGENTS.md section 4b this is a time limit that can change an intersection's result, not a hang fix.
- **What face 14 returns with the flag:** `DoDefeature` returns `Ok` after 46 s in release, with the default run's face and edge counts (25, 48). The intersection's error reaches `ManifoldBoolean` through `manifold_xor`, which ignores its status as `SmFeatureExecutive` does (the primary body is kept); that decides what the feature executive reports, and it is not changed here. The flag saves time; it does not make this defeature succeed (the open body is #2001).
- **Regression:** `do_intersection_bounds_its_start_point_loop_traces_when_opted_in` (`p5.rs`, through `DoIntersection`, fast: flag off is not bounded, flag on with a limit of 1 fails, flag on with the real limit gives the flag-off curves); `trace_steps_are_bounded_by_the_start_point_loop_budget` (`p4.rs`, trace level, fast); `crates/solidcore/tests/hang52_defeature_trace_budget.rs` runs face 14 end to end with the flag (`#[ignore]`: 46 s release, 27 min dev) and checks the counts above, which the default run also gives; only the running time tells them apart.
- **Confirmed:** both engines run on face 14 to completion, as above. The step counts and the mechanism are measured in Rust only; the C++ mechanism is read from the source.
