Updates: WR-716

#### WR-716 (update, 2026-11-23). `fillet_chamfer_corner` is removed; the chamfer-corner event is the only chamfer corner it classifies

A corner where every blended edge is chamfered now always goes to the blend corner's chamfer event (`crate::blend::blend_corner::chamfer`, from `FilletSession`'s corner build in `crates/solidcore/src/blend/fillet_executive/session.rs`), and the flag is gone. Removed: the field (`crates/solidcore/src/kernel/fixes/fillet_chamfer_corner.md`), its doc lines, `solidcore-ops`' refusal of `ChamferCorner::Facet` without the fix, and the tests' flag-off halves.

- **What stays pinned:** the pinned 3x3 corner's chamfer branch is not deleted. A corner the event declines still builds there, as the retirement plan above says: a chamfer edge that is not straight, a face that is not a plane, a chamfer that is not of constant width. Deleting it would turn those valid corners into refusals.
- **No type asked, no new refusal:** with the flag gone, `Kernel::default()` callers reach the event's refusals, where before the pinned branch built a corner. So the session's corner type is now unset unless the caller calls `set_chamfer_corner` (`solidcore-ops` now always asks the type its caller chose, the Mitre by default, so a SolidCraft design keeps its refusals with their fits), and with no type asked `classify_chamfer` takes the type that exists instead of refusing:
  - four or more chamfers whose crossings lie in one plane: the Facet (the mitre of four is not built). At the pyramid's apex that is 3776/3, the volume the pinned corner built there before.
  - three chamfers whose mitre point is outside the corner (widths 1, 1, 3 at a box corner), and at four or more chamfers ends that overlap or a facet that would cut them: no event closes the corner, so it is declined to the pinned one, as before. At the 1, 1, 3 corner that builds a valid closed body; its patch is not the mitre polytope and has no closed form, so the test pins its validity, not a volume.
  - chamfer planes so nearly coplanar that their meeting is not determined to the part's rounding: still refused (`CornerUnsupported`). The pinned corner built nothing there either (the `low_apex(1/100)` case failed in skinning).
  An explicitly asked type is still refused where it does not exist, with its fit. Mixed convexity is refused only where the corner is a bevel, as before; elsewhere it keeps the pinned corner.
- **The default corner type is the mitre** (`BlendChamferCorner::Mitre`: ops' default, and the session's where it exists with no type asked). A box corner of three chamfers is exactly the box cut by the three chamfer planes, and it removes nothing the caller did not ask for. `fillet_edges` and `fillet_edges_per_edge` with linear sections at such a corner now build that mitre: before, they reached the pinned branch's non-bevel route and built a triangular facet (or, for unequal chamfers, a four-sided B-spline patch). SolidCraft already ran with the fix on and ops asks its type, so its results do not change.
- **Tests:**
  - `wr697_ball_corner::per_edge_linear_chamfers_at_a_corner_are_the_mitre` builds the 2/3/4 corner's mitre with every fix and with none.
  - `wr697_ball_corner::no_type_asked_the_coplanar_apex_is_the_facet`, `no_type_asked_a_mitre_point_outside_the_corner_is_the_pinned_corner` and `no_type_asked_a_nearly_flat_apex_is_refused` pin the three cases above, the first two with every fix and with none.
  - `solidcore-ops` `blend_chamfer_corner::the_box_corner_s_mitre_and_facet_need_no_fix` builds the mitre and the facet with no fixes set.
  - `wr_657_offset_splits_corner_vertices` pins the offsets and shells of the box with three and with twelve chamfered edges at their mitre corners. `wr_657_closed_forms_replay` recomputes every pinned volume apart from the kernel, as the volume of the convex polytope the faces' moved half-spaces cut out.
  - Rig `3655-chamfer-all-box-edges-pick-order` expects the mitred box, 15000 - 0.5 * 2.5^2 * 330 + 6 * 2.5^3 = 14062.5 (before: the facet's 14052.083333, 8 d^3/12 less). `wr_657_offset_splits_corner_vertices::issue_3655_mitred_box_closed_form` replays it.
