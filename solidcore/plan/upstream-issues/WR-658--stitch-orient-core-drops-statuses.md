#### WR-658. The B-rep's edits, `StitchAndOrient`, the offset/shell stitches and the Boolean merge, stitch and topology-intersection passes drop failed statuses and report success
- **Severity:** Wrong result
- **Area:** Topology / B-rep edits, stitching
- **Location:** `source/SMLib/src/SmBrep.cpp` (442 dropped statuses, among them `SmBrep::StitchAndOrient`'s two `StitchFaces` passes and its `OrientTrimmedSurfaces`, the list edits of `DeleteFace`, `DeleteEdge`, `DeleteVertex`, `GlueVertices`, `CombineCoincidentVertices`, the trims and interval edits of `MakeVertexSplitEdge`, `MateLaminaEdgeToSurface` and `CreateEdgeEdgeBlend`, `CalculateTightBoundingBox`, `FindInfiniteRegion`, `ShrinkGeometry`, the angle/`SetCanonical` steps of the matrix `Transform`).
- **What happens:** a call fails (an evaluation, a list edit, a trim, a stitch pass, the orientation) and its status is not checked, so the operation goes on with an unset or stale value and returns `SM_SUCCESS`. No crash: a wrong success.
- **Trigger:** no valid input is known to fail these calls; the failure is injected (an edge without curve, a face without surface, a zero matrix row). See the tests below.
- **How found:** code reading; the SolidCraft fork (tangency-labs/smlib) passes these statuses on in 60a8a51 (SmBrep), 4803d6d (offsets, shells and SM_API's `SmApiStitch`, `SmApiProjectBrepOntoPlane`, `SmApiCreateSilhouetteCurves`) and e7ebc8d (Boolean merge, stitch, topology intersection), tracked as #2009 group A.
- **Confirmed:** in the port, by injected-failure tests (each fails with the flag on and the fix removed). The pinned C++ drops the statuses, so with the flag off the port matches it.
- **Fix (fork):** tangency-labs/smlib@60a8a51 wraps each dropped status in `SER` in functions that return `SmStatus`; where the function cannot return one it fails softly: `IsDegenerate` is `FALSE` without a box, `SetTolerance`'s old-tolerance path treats a box it cannot compute as no size, `sm_RedistributeSeamUVTrimCurves` swaps nothing without its four edge uses, their trim curves and end points. Kept dropped: `ShrinkGeometry` in `RotateSection`, the void list getters, `AssertValid`, `Dump`.
- **Rust port:** opt-in `Kernel::fixes.brep_edit_statuses_pass_on` (default `false`, upstream's behaviour), at each site through `crate::error::passed_on` / `status_passed_on`, which leave the site's own ignore policy unchanged with the flag off. Sites (60a8a51) in `crates/solidcore/src/topology/brep/{p1,p2,p3,p4,p5,p6,p7,p8,p9,p10,mirror}.rs` and `crates/solidcore/src/query/brep.rs`; (4803d6d) `offset/offset_executive/p1.rs` (`PiecewiseMerge`'s `StitchIntoShell`/`StitchIntoSolid`, `ShrinkGeometry`, `RemoveFaces`, `DeleteFaces`, the boolean offset face's edits), `offset/offset_geometry_creation.rs`, `curve/offset_curve.rs`, `surface/offset_surface.rs`, `heal/stitch/p1.rs` (`api_stitch`), `topology/api_projection.rs`. The fork's `HaveTangentGaps` change is `offset_tangent_gap_statuses` (addendum `plan/findings/general--status-audit-483--addendum-2026-10-31-fork-soft-statuses.md`). (e7ebc8d) `boolean/merge/{p1,p2,p3,p4}.rs` (the merge's intersection passes, stitches, `MergeBrep`, `StitchAndOrient`, `RemoveFaces`, `CopyFaces`, `SetRegions`, `FindAndSetInfiniteRegion`, `PropagateOtherSrcRegionAttribs`, `OrientSheetSurfaces`, `DeleteStaleCaches`, the wire shell transfer), `boolean/topology_intersector/{p1,p2,p3}.rs` (relations, proto-topology creation, boxes, classifications, `GlueVertices`, `UpdateObjectTolerance`, `MakeEdgeInFace`, `GlueEdgesGeneral`, `DeleteFace`), `heal/stitch/{p1,p2}.rs`, `intersect/adv_surface_intersector.rs` and its `tangent_contacts.rs` (captured when the intersector is built). The fork's `ALIGN_DIR_WITH_PREVIOUS_POINT` change is `ssi_alignment_statuses` (addendum `plan/findings/general--status-audit-483--addendum-2026-10-31-fork-soft-statuses.md`). Statuses the fork still only tests or drops (`sm_CheckInteriorEdge`'s, whose `bInterior` decides; `ResolveProtoTopology`'s warnings; `SetTolerance`, a void) stay as they are. The SM_API fillet wrappers already return `StitchAndOrient`'s result in the port; the offset executive's own `StitchIntoSolid` calls stay asserted-only, as in the fork. Fork sites whose Rust counterpart already propagates or cannot fail (arena list edits, getters) need no change. Tests: `crates/solidcore/tests/issue_2009_group_a_statuses.rs`, `topology::brep::p5::tests::stitch_and_orient_passes_on_*`.
