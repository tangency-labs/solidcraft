Updates: WR-254

#### WR-254 (update, 2026-11-17). An analytic corner error with no upstream status is passed on

Updates `WR-254--smfilletcorner-makeanalyticcornersurface-reports-its-ser-ner--dup2.md`, not `WR-254--manifoldboolean-keeps-a-face-lying-in-the-slicing-sheet-in.md` (the other record that shares the ID).

- **Change:** `FilletCorner::make_analytic_corner_surface_with` (`crates/solidcore/src/blend/fillet_corner/p2.rs`) read every error whose `SolidError::upstream_status` is `None` (such as `NotFound` or `Degenerate`), other than `Unported`, `Cancelled`, `InvalidInput` and `PortInvariant`, as `Ok(true)`: "an analytic surface was made", although none was added. `CreateCornerPatch` then skipped the Coons patch and `MakeFaceBrep` returned at once on the empty surface list, so the corner reported success with no surface and no face, the hole this record's fix closed for the `SER` / `NER` exits. Upstream has no such exit, so there is no upstream `FALSE` to patch over, and these errors are now passed on. The `SER` / `NER` exits still read as `FALSE`; `Unported`, `Cancelled`, `InvalidInput`, `PortInvariant` and a certificate past its work budget still propagate.
- **Results:** none move. A probe in the old arm, run with every goldens unit on main (283 units, all passing) and the kernel rig (1115 cases, none failing), found no case that reaches it. The goldens cases that reach the upstream-status arm are the 15 rows listed in the 2026-11-14 addendum (`blend.fillet_corner_p2` 7, `blend.fillet_corner_p3` 8), unchanged.
- **Test:** `analytic_corner_surface_passes_on_an_exit_without_upstream_status` (`crates/solidcore/src/blend/fillet_corner/p2.rs`): a chamfer corner whose rail-rail interpolating arc names an original face the target lacks fails with `NotFound` for that face, after the arc's curve was deleted to be recomputed. The analytic corner and the corner patch both pass the error on, with no surface and no corner face; before, both reported success.
