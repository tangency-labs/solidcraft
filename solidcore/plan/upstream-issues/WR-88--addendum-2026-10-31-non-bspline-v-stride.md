#### WR-88 (update, 2026-10-31). Opt-in normalization of non-B-spline surface V sample stride

- **Status in the port:** `Kernel::fixes.gap_samples_non_bspline_v_stride`, off by default. The default retains the pinned C++ behavior, including its array-index-based numerator `jj / (cv - 1)`.
- **Location:** `source/SMLib/src/SmGap.cpp:1903-1907`, `SmGapFunction::BuildSampleSet` at v1.0.1 (`3fd5b95`); `crates/solidcore/src/heal/gap.rs`, `GapFunction::sample_normalized_values`.
- **What changes:** when `gap_samples_non_bspline_v_stride` is true, the interior V sample parameters are normalized by `(jj - cu) / (cv - 1)` instead of `jj / (cv - 1)`. The array index `jj` runs from `cu + 1` to `cu + cv - 2`; subtracting `cu` recovers the true 0-indexed internal V sample number `(1, 2, ..., cv - 2)`, resulting in interior normalized V parameters in `(0.0, 1.0)` evenly spaced by `1 / (cv - 1)`. The boundary samples at indices `cu` (`0.0`) and `cu + cv - 1` (`1.0`), the U direction normalization, sample counts, row-major traversal, previous-sample drop guesses, tolerance checks, early-stopping behavior, and sample caching remain unchanged.
- **Why it matters:** when evaluating gaps across non-B-spline surfaces (e.g. `SmCurveBoundedSurface` or other non-NURBS representations) with `cv > 2`, the upstream loop divides the flat array index `jj` (which includes `cu`) by `cv - 1`. Because `jj >= cu + 1`, the interior V parameters are well above 1.0. For example, on a bilinear patch with `cu = 5, cv = 3` and domain `[0, 1] x [0, 1]` where `z(u, v) = 10 * v`, upstream evaluates the interior V sample at `v = 3.0`, placing the evaluated point at `(1.0, 3.0, 30.0)` and reporting an extrapolated gap of `sqrt(910) ≈ 30.17` to the origin instead of the true maximum gap of `sqrt(102) ≈ 10.10` on the actual surface boundary. With the opt-in fix, `v` evaluates at `0.5`, points remain strictly within the surface domain `[0, 10]`, and the correct gap is computed.
- **Regression evidence:**
  - `wr88_non_bspline_surface_v_stride_default_matches_upstream_extrapolation`: verifies that default kernel reproduces pinned C++ behavior (`[0.0, 2.0, 7/3, 1.0]` for `cu = 5, cv = 4` and `[0.0, 2.0, 1.0]` for `cu = 3, cv = 3`).
  - `wr88_non_bspline_surface_v_stride_opt_in_normalizes_within_unit_domain`: verifies that opt-in kernel normalizes V samples strictly within `[0.0, 1.0]` (`[0.0, 1/3, 2/3, 1.0]` for `cu = 5, cv = 4` and `[0.0, 0.5, 1.0]` for `cu = 3, cv = 3`).
  - `wr88_boundary_conditions_cv_counts_and_cu_independence`: checks boundary conditions `cv = 1` and `cv = 2` (where no internal loop runs, so default and opt-in agree), and proves that opt-in V samples are completely invariant to changes in `cu` (`cu = 2, 4, 10`), whereas default V samples shift erroneously with `cu`.
  - `wr88_non_unit_domain_and_gap_evaluation`: checks end-to-end 3D surface point evaluation and gap distances on a non-B-spline patch with a height slope along V, confirming that default evaluates extrapolated space (`z = 30.0`, gap ~30.17) while opt-in evaluates within domain (`z <= 10.0`, max gap ~10.10).
- **Native evidence:** the default behavior is verified against the pinned C++ reference by the existing difftest fixture `srf_pt_curve_bounded_v_stride` (`fixtures/heal.gap/upstream.json`, `cu = 5, cv = 4`), which passes with `max_rel_err = 0`. The opt-in fix is verified against independent mathematical expectations.
