#### UB-288. `sm_CrvEval` reads before the control points of a curve with fewer than p + 1 of them, at the NaN parameter `CreateOrientedTrimBoundary` gives an edge whose limits were never set
- **Severity:** Undefined behaviour (out-of-bounds read; no crash seen)
- **Area:** NURBS evaluation, reached from face properties
- **Location:** `sm_CrvEval` (`source/SMLib/src/SmNurbsCrv.cpp:1424`), after `sm_BasisEval` (`:1343`) and `N_BasisFindSpan` (`source/SMLib/src/NL_BasisBasic.cpp:1429`). For a NaN parameter every comparison in `N_BasisFindSpan` is false: no early return, and the bisection loop does not run, so the span is the initial `mid = (p + (m - p)) / 2`. For a degree-3 curve with two control points (`n = 1`, `m = 5`) that is 2, below the degree, and `sm_CrvEval` reads `Pw[spn - p] = Pw[-1]`. The basis values are NaN, so the result is a NaN point, returned with success.
- **Call path:** `SmBSplineCurve::EvaluatePoint` (its `ClampValue` keeps NaN) <- `SmFace::CreateOrientedTrimBoundary` (`source/SMLib/src/SmFace.cpp:7333`; the reversed-edgeuse branch, `ReverseParameterization(sIvl, sIvl)` then `EvaluatePoint(sIvl.GetMin(), ..)`) <- face properties <- `SmApiBrepComputeArea`.
- **How the NaN arises:** an edge whose interval was never set keeps `SmExtent1d`'s empty default (min 1e20, max -1e20). `SmEdgeuse::GetOrCreateUVTrimCurve` builds a UV trim curve for it with all knots 1e20 (degree 3, two control points). `SmBSplineCurve::ReverseParameterization` divides by `max - min` of that zero-length natural interval, `0 / 0`, so the reversed interval is NaN.
- **Trigger:** STEP Tools corpus `ap203/st203-bapl.stp`, body 0, built through `SmBrepConstructor` (`difftest --step-case .. --constructor`). Two constructor calls fail on both kernels (the first `SetLimits`-type call, op 15, with status 1007), which leaves two edges with unset intervals, on faces 40 (a cone) and 42 (a plane) of 43. The area stage reaches them.
- **How found:** the Rust area failed where the C++ area succeeded. A probe on the Rust side recorded the failing evaluation (t = NaN, interval 1e20..1e20, degree 3, two control points, all knots 1e20) and its caller. A both-kernel dump of the two faces' UV trim curves, made as `CreateOrientedTrimBoundary` makes them, was identical, so both kernels build the same curve and reach the same evaluation (probe batches 54j26, 54j3555).
- **Confirmed:** the read before `Pw[0]` is read from the code for this input, not observed. The C++ run completes and its area is finite.
- **Rust port:** no read out of bounds. `crv_eval`'s span bounds check returns an error ("index out of range"), so the area fails here where C++ goes on, and the corpus verdict for this body is a stage difference (C++ area, Rust 1001).
