#### UB-289. `Fix_CoinVertices` keeps vertex-props pointers across `UpdateTargetLists`, which frees them, so whether a merged vertex's later pairs are merged depends on heap address reuse
- **Severity:** Undefined behaviour (use of freed pointers as identities); allocator-dependent result
- **Area:** Healing
- **Location:** `SmHealData::Fix_CoinVertices` (`source/SMLib/src/SmHealData.cpp`). After each merge, `CombineCoincidentVertices` runs under an `SmTrackTopologyChanges`, and `UpdateTargetLists` is called with its lists. The merge reports `SM_NO_MERGE_IN_BREP`, which puts both vertices in the remove list and the survivor back in the add list (`SmTrackTopologyChanges.cpp`), so `UpdateTargetLists` frees both pair members' `SmVertexProps` and allocates new props for the survivor. The loop then rewrites the later pairs' `pDeletedProps` to `pSurvivorProps`, a freed pointer, and each later pair is kept only if `m_sTgtVertexProps.FindElement` finds its pointers among the live targets.
- **Effect:** a later pair that named the deleted vertex is merged into the survivor only when the allocator gave the survivor's new props the old survivor's address. Otherwise it is skipped. Pointers are only compared, never dereferenced, so nothing crashes.
- **Trigger:** STEP Tools corpus `ap203/gehaeuse.stp`, body 0, built through `SmBrepConstructor`, healed. In `Fix_DegenFaces` two sliver faces are squeezed, and the catch-up healing of the new targets lists pairs such as (A, B) and (B, C), where B's tolerance has grown to several millimetres in the squeeze. On the C++ reference build (glibc), B is merged into A and the rewritten (A, C) is merged too: the healed body has 87 faces, 226 edges and 141 vertices after `Fix_DegenFaces`. The port skips (A, C) and has 228 edges and 143 vertices.
- **How found:** a stage-by-stage heal comparison of the two kernels (the heal stopped after each step) found the first difference at `Fix_DegenFaces`. A Rust trace of the catch-up's pair lists and merges showed the pairs present and the later pair skipped (probe batches 54j093, 54j26, 54j3555).
- **Confirmed:** the C++ outcome on this build. That it follows from address reuse is read from the code: the survivor's props are freed and reallocated between the merge and the rewritten pair's check. The allocator's choice was not traced.
- **Rust port:** props are arena records with fresh ids after `update_target_lists`, so the rewritten pair names a stale id and is skipped, deterministically and on every platform. This matches the C++ result whenever the allocator does not reuse the survivor's address. See also `plan/findings/heal.heal_data_p3--healer-sequencing-target-refresh-and-repair-stages-pr-164.md` (allocator address reuse in the healer's props).
