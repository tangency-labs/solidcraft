Updates: WR-513

#### WR-513 (update, 2026-11-15). `fillet_vertex_error_diagnostics` is removed

`create_fillet_corners_recording_vertex_errors` (`crates/solidcore/src/blend/fillet_executive/p1.rs`) now always notes a vertex no corner type handles as `FilletErrorType::CornerUnsupported` ("Corner case not implemented", with the vertex and its location), unless a refused corner was noted first. `FilletSession::do_fillet` (`session/finish.rs`) always keeps that note in `error_info()` across the later stage's failure. The returned error is still the later stage's own status, and the pending vertex entry and the operation's result do not change. Removed: the field, SolidCraft's preset line, its entries in `kernel_cases/fixes.json` and `issue_2260_gn_pipe_refined_range_end.rs`, and every test setting of it.

- **Results:** no goldens case changes (diagnostics only).
- **Tests:** the flag-off halves of `create_corners_notes_an_unsupported_vertex_only_when_opted_in` (now `create_corners_notes_an_unsupported_vertex`), `create_corners_consults_the_vertex_diagnostics_fix` (now `create_corners_notes_the_unsupported_vertex`) and `do_fillet_keeps_the_missing_corner_note_or_the_same_later_failure` (now `do_fillet_keeps_the_missing_corner_note_through_the_later_failure`) are removed, including its stale-note case, which only tested the flag off. The fixed halves keep every assertion. `create_corners_preserves_order_pending_and_final_error_assignment` ran on the default kernel and checked the pinned no-op: the error output kept its earlier code 17 after an unsupported vertex. It now checks that the output carries that vertex's note, code 9 (`CornerUnsupported`) and vertex H(2), as `create_corners_original_factory_shape_still_notes_without_a_location` already checked for the same factory shape with the flag on.
