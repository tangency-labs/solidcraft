Updates: WR-254

#### WR-254 (update, 2026-11-14). `analytic_corner_failure_is_false` is removed

Updates `WR-254--smfilletcorner-makeanalyticcornersurface-reports-its-ser-ner--dup2.md`, not `WR-254--manifoldboolean-keeps-a-face-lying-in-the-slicing-sheet-in.md` (the other record that shares the ID). It also supersedes the remark in `WR-716--chamfer-corner-mitre-marched-and-facet-a-coons-patch.md` that the flag stays for the corners that are not chamfers.

`SmFilletCorner::MakeAnalyticCornerSurface`'s `SER` / `NER` exits add no surface, and upstream returns their status as an `SmBoolean` that `SmFilletCorner::CreateCornerPatch` reads as `TRUE`, so the corner got neither an analytic surface nor the Coons patch and `CreateCornerPatch` reported success with no corner face. The fixed reading (those exits are `FALSE`, so the caller builds the Coons patch) is now unconditional and the flag is gone. SolidCraft's preset already had it on, so the shipped result does not change. Removed: the field `UpstreamFixes::analytic_corner_failure_is_false`, SolidCraft's preset line, its entries in `fixes.json` and in the SolidCraft preset list of `issue_2260_gn_pipe_refined_range_end.rs`, the flag-off branch of `FilletCorner::make_analytic_corner_surface_with` and the unit tests' flag-off halves. As before, only the exits that carry an upstream status change; the port's `Unported`, `Cancelled`, `InvalidInput` and `PortInvariant` still propagate.

- **Results:** 15 goldens rows move, status only (every other value of each row is unchanged):
  - `blend.fillet_corner_p2` `corner_analytic_13`, `_43`, `_70`, `_84`, `_85`, `_87`, `_90`: `MakeAnalyticCornerSurface` 1 to 0. Each row records `surfaces: [0]`, so no surface was made and `FALSE` is the function's answer by its own contract; the exits are `SM_ERR_NULL_POINTER` (an interpolating edge without its original face; six rows) and `SM_ERR` (a corner edge whose curve is not a B-spline; `_43`).
  - `blend.fillet_corner_p3` `gen0060`, `gen0089`, `gen0104`, `gen0145`, `gen0170`, `gen0189`, `gen0282`, `gen0326` (`CreateCornerPatch` directly or through `CalcCornerGeom`): status 0 to 1006. Every one of these corners has a fillet edge with no 3D curve in its input model, so the Coons patch has a side it cannot bound and cannot be built; the patch reports `SM_ERR_NULL_POINTER` (a missing boundary curve, or for the extended-surface corners `gen0104`, `gen0189`, `gen0326` the missing fillet geometry it reads first). Before, the same corners returned success with `surfaces: [0]` and no corner face.
- **Tests:** `crates/solidcore/src/blend/fillet_corner/p2.rs`: `analytic_corner_surface_reads_a_failing_status_as_false`, `analytic_corner_surface_keeps_the_false_controls`, `analytic_corner_surface_keeps_invalid_input` and `analytic_corner_surface_makes_the_chamfer_plane` (the chamfer plane checked against the plane through the corner's three vertices, where it compared flag off to flag on).
