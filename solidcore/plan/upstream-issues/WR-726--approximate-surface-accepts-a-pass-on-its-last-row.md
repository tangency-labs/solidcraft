#### WR-726. `SmSurface::ApproximateSurface` accepts a pass of patches when only its last row is within the tolerance, and returns success with an achieved tolerance above the requested one
- **Severity:** Wrong result (accuracy: a fit outside the requested tolerance reported as success)
- **Area:** Surfaces
- **Location:** `source/SMLib/src/SmSurface.cpp` at `3fd5b95`, `SmSurface::ApproximateSurface`: `bFailed = FALSE; // Starting over on a new row.` at the top of the loop over the 'outer' rows of patches (`:1114`), the break after a failed row commented out (`// if (bFailed) break;`, `:1186`), and the acceptance test after the loop (`if ( ! bFailed )`, `:1191`). The SMLib fork (tangency-labs/smlib) has the same code.
- **What happens:** each pass fits cubic Bezier patches and samples them row by row (or column by column) against the exact surface. A failed sample marks its row and adds a split knot for it; the next row starts with the flag cleared. After the loop the flag only says whether the last row failed, so a pass whose earlier rows miss the tolerance is accepted, and the split knots collected for them are dropped. `dAchievedTol` is the largest deviation over the whole pass, so it is above the requested tolerance, with `SM_SUCCESS`. `SmBrepData`'s `bWriteAsBSplines` writer only signals a "not within tolerance" message and writes the surface.
- **Trigger:** the offset wave of WR-573 with WR-573's fix on (tangency-labs/smlib@eae96cb; `Kernel::fixes.approximate_surface_bezier_starter`): a sheet on a cubic B-spline wave of 6 control points ((0, 0, 0), (2, 0, 0.4), (4, 0, -0.4), (6, 0, 0.4), (8, 0, -0.4), (10, 0, 0); knots 0 0 0 0 1/3 2/3 1 1 1 1), swept 10 along +y (`SmApiCreateLinearSweep`, no caps), offset by 0.5 (`SmApiOffsetBrepFull`). Its one face is on an `SmOffsetSurface`.
  - `ApproximateSurface(5e-6, 3, FALSE)` (the writer, with the B-rep's approximation tolerance) and `(5e-6, 5, TRUE)` (the flat export, #1441): a 33 x 4 surface at 1.1245747026548022e-05, 2.25 times the tolerance, on both engines.
  - `ApproximateSurface(1e-3, 3, FALSE)` of the same surface built by hand: 1.6208280437303383e-03, 1.62 times the tolerance.
- **How found:** tangency-labs/solidcore#2507, from the operation-level case of #2476 (`plan/upstream-issues/WR-573--addendum-2026-11-03-operation-level-offset-sheet.md`, "Above the requested tolerance").
- **Confirmed:** yes. C++ v1.0.1 with eae96cb gives the 1.12e-5 above with `SM_SUCCESS` for both calls (#2507); the Rust port matches it bit for bit (`crates/solidcore/tests/wr573_offset_wave_export.rs`, `the_flag_approximates_the_offset_face`; `surface::surface::approximate::tests::wr573_bezier_starter_approximates_the_offset_wave` for the 1e-3 case).
- **Rust port (opt-in):** `Kernel::fixes.approximate_surface_checks_every_row` (`UpstreamFixes`, default `false`).
  - A pass is rejected when any row or column of patches has a sample outside the tolerance. Each row still stops at its first failed sample and adds its split knot, so the next subdivision splits every failed row, not only the last.
  - The number of passes is unchanged (`2 * lSubdivisionLevel + 2`, alternating u and v), so the search still ends; when the last allowed pass is still outside the tolerance it fails with `SM_ERR`, as upstream's search does when its last row fails there, with no surface and the achieved tolerance of that pass.
  - With it (and `approximate_surface_bezier_starter`), the offset wave's two calls at 5e-6 give a 34 x 4 surface at 4.034260017062413e-06 (`with_every_row_checked_the_fit_is_within_the_tolerance_2507`), and the 1e-3 call a 13 x 4 surface at 9.183975903657478e-04 (`wr726_every_row_checked_keeps_the_fit_within_the_tolerance`). At subdivision level 0 the 1e-3 call fails with `SM_ERR` instead of returning a fit outside the tolerance (`wr726_every_row_checked_refuses_when_the_last_subdivision_misses`).
  - The quarter cylinder offset of #1441 (`issue_1441_offset_surface_export`, `approximates_an_offset_quarter_cylinder`) still approximates with the flag on.
