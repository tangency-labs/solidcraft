#### WR-51 (update, 2026-11-16). Touching points are added after the degenerate-curve cleanup; three plane-first cases are known failing

- **Order:** `DoIntersection` removes degenerate curves that lie on other curves. It now adds the touching points left for a start point (`SurfaceIntersector::add_deferred_touching_points`) after that removal, not before it (`remove_covered_degenerate_curves_then_add_touching`). Each point is checked against the curves that remain. Before, a point whose only cover was a degenerate curve the removal then dropped was lost. Such a point lies within 5 tol of the curve that the degenerate curve lay on but is not on it, and is now reported; the test `a_touching_point_covered_only_by_a_removed_degenerate_curve_is_kept` builds one. A point that is added lies on none of the remaining curves, and the removal uses the same test, so the removal would not have dropped it either.
- **Known failing, not blessed:** tangency-labs/solidcraft#17507 blessed a lone touching point, in place of 1001, for three `intersect.api_intersectors` cases: `ssi-revolution-plane-near-axis-parallel-swapped`, `ssi-revolution-plane-oblique-swapped` and `ssi0043`. The point alone is still the wrong topology. With the plane first, each case returns one touching point (deviation 0.500001, 0.2 and 2.44). With the revolution first, the same geometry gives the crossing curves: 2, 1 and 1 curves (deviation 1.75e-4, 1.37e-3 and 4.57e-3). These cases are listed in `known_failing.json` under tangency-labs/solidcraft#17720 and have no golden line. The `wr51_plane_first_pairs_report_their_touching_point` test, which asserted success there, is removed.
