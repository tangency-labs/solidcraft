#### ND-260. `offset.offset_executive_p2` generated cases: C++ values vary run to run at 1e-15..1e-14 (not TBB)
- **Severity:** Nondeterminism
- **Area:** Surface
- **Location:** not isolated. Excluded: TBB. Upstream's `tbb::parallel_for` sites (`SmBrep.cpp:8980`, `:8993`; `SmTopologyIntersector.cpp:1135`, `:1665`, `:1699`; `SmTess.cpp:11264`, `:11448`, `:11466`) are all inside `#ifdef SM_USE_TBB`, which no build file defines; the harness C++ reference (`harness/cpp/build.sh`, `CMakeLists.txt`) links no TBB and `libSMLib.a` has no `tbb::` symbols. The serial paths run. Leading candidate: pointer-keyed container iteration order (see ND-2 and ND-259: `SmMapPtrToPtr.h:115`, `SmRelation`) reaching vertex/edge merge order in `SmOffsetExecutive`.
- **What happens:** the same binary on the same inputs gives slightly different result values between processes in about 20 of 305 compared generated (`gen*`) cases; the Rust port is bit-identical every run. The unit's max_rel_err moves between 5.4e-15 and 1.8e-14 on unchanged code.
- **Trigger:** `offset.offset_executive_p2` generated cases, repeated difftest runs; persists with ASLR disabled (`setarch -R`), so it is not plain stack/heap base randomisation. Heap layout (allocation history) is not excluded: ND-259 shows the same dependence for one fixture.
- **How found:** repeated runs with a hash of each side's raw f64 values (temporary instrumentation): Rust identical in 6 of 6 runs, C++ differing in 19-26 cases per run pair, on main and on PR #1128's head.
- **Confirmed:** variation yes (C++ side only); cause no. A single-thread TBB pin was the planned test and is moot because TBB is not compiled in. Next step: run with a deterministic allocator or pre-fragmented heap (`LD_PRELOAD`, as for ND-259) and compare, then bisect the varying cases by `SmRelation` iteration sites.
- **Rust port:** deterministic (`geom::tol::Relation` iterates sorted handles). All values keep the 1e-9 relative gate; the noise is five orders below it, so it is not a blocker.
