Updates: WR-455

#### WR-455 (addendum 2026-11-16): a contact at a curve's end always moves there; `curve_contacts_at_curve_ends` is retired

- **Status in the port:** `UpstreamFixes::curve_contacts_at_curve_ends` is gone. `Curve::global_curve_intersect` (`curve/curve/p8.rs`) always runs `move_contacts_to_curve_ends` after `sm_RefineCCSolutions`: a point solution moves to an end of either curve when that end lies within tolerance of the other curve and the curves stay within tolerance of each other over the whole stretch, measured on each curve. Part (1), `offset_stitch_at_body_tolerance`, keeps its own flag.
- **Not for self intersections:** the move is skipped when the curve is intersected with itself. There the "other" curve is the same curve, so the stretch test compares the curve with itself and always passes; under the flag the move carried real self intersections onto the trivial diagonal, where they were dropped: a closed curve's seam (a full ellipse, closed Hermite curves) disappeared from `GlobalCurveSelfIntersect`, whose contract is that a closed curve always has one. The old default (flag off) never ran the move; the flagged path had this defect. Test: `self_intersection_keeps_a_closed_curves_seam` (goldens `curve_curve_p8`).
- **No move over a one-point stretch:** when the drop lands on the solution's own parameter, the drop curve's stretch is one point. The second gap measure then drops the end curve's samples onto a one-point interval, a sample that finds no foot counts as no gap, and the test passed a closed curve's whole turn (goldens `curve.curve_p8` gen2153: `t1 = 1` moved across the loop to 0). Such a solution now stays where it is. Test: `one_point_drop_stretch_does_not_move_the_contact`.
- **A failure in the move leaves the solution in place:** an evaluation or solve that fails while the move tests an end (for example an interval end past the knots of a B-spline evaluated out of bounds) skips that end instead of failing the intersection, so the pass only ever refines solutions already found. Errors with no upstream status (cancellation, unported calls, port invariants) still propagate.
- **Known limit, follow-up:** the move's stretch test (`curve_max_distance_between`, unchanged library code) samples, and a sample that its local solve cannot place adds no gap. The one-point guard covers the case the goldens reach (gen2153); a certified stretch test would replace the sampling. The move may also name an interval end that lies past a clamped curve's knots, where the curve is constant, as the fork does.
- **Certificate:** `contacts_at_curve_ends_are_certified` certifies every moved `curve.curve_p8` row: each solution is a contact, and each earlier solution is joined to a reported one by a stretch the curves keep within tolerance (Lipschitz bound from the curves' control data, no sampling).
- **The mouse case:** with the move on, the goldens case `blend.fillet_executive_p1` `remove_topo_edges_mouse_two_struts` failed with `create_by_joining: segments not end to end`. The defect was in the consumer, `longest_drop_run` (WR-543 addendum of the same date), which now joins only pieces the join accepts.
- **Not retired here:** `simple_coincidence_crossing_is_point` (WR-647) keeps its flag. With it on by default, the issue1036 coincident skins' sections (parallel curves 2.6e-6 to 1.7e-5 apart at tolerance 2e-5) become single points, and the booleans return wrong bodies where main refuses (WR-473). It is retired after WR-473 is fixed.
- **Removed:** the upstream path, the field and its doc, the preset line in `crates/smlib/src/core.rs`, the `fixes.json` and `issue_2260` entries and the flag settings in the integration tests.
- **Tests:** `issue_855_offset_stitch_keeps_the_bodys_tolerance` no longer loops over the contact setting: the stitch fix still gives the closed form 4564.924657 and the default still refuses (1001).
