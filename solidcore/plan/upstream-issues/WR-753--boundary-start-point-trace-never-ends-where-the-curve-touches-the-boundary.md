#### WR-753. A trace from a boundary start point where the curve touches the domain boundary never ends: `sm_IsPointOnCurve` refuses a same-direction landing on a point, and the boundary start loop sets no start point to close on

- **Severity:** Wrong result (a Boolean refused with `SM_ERR`, or a wrong body when the status is dropped)
- **Area:** Surface/surface intersection (the marcher)
- **Location:** `source/SMLib/src/SmSurfaceIntersector.cpp`: `sm_IsPointOnCurve` (the `[B401]` direction test after the Hermite drop, and the interior test that excludes the span's ends; the port's `is_point_on_tsect_curve`, `crates/solidcore/src/intersect/surface_intersector/p1.rs`), and `SmSurfaceIntersector::DoIntersection`'s loop over `m_vStartPoint` (the port's `do_intersection_with_caches`, `surface_intersector/p5.rs`), which never sets `m_pStartPoint` for a boundary start point's trace.
- **What happens:** A boundary start point is a crossing of a surface's natural boundary curve with the other surface. Upstream assumes the intersection curve crosses that boundary there, so a trace from the point leaves the domain at its other end and never returns. When the boundary curve is tangent to the other surface, the intersection curve touches the boundary at the point and stays inside: a closed loop. The trace from one touch point runs round the loop: at the other touch point the predictor is clipped to the boundary and the corrector lands exactly on the start point, `sm_IsPointOnCurve` drops it at the span's end (t = 1, distance 1e-14) but accepts an end-of-span hit only against the point's direction, so the point is "not passed"; at its own start there is no closed-curve test at all, because `m_pStartPoint` is only set for interior seeds and `DoPointIntersection`. The trace runs to the 5000-point limit; the occasional snap cuts it into pieces that overlap, and the Boolean's proto topology then fails in `CombineProtoEdge` (`SM_ERR` from `RemoveProtoEdge`, 1001) or, with the status dropped as upstream does, builds a wrong body.
- **Trigger:** tangency-labs/solidcore#3091, from tangency-labs/solidcraft#12858: a 43.5 x 36 x 10 plate with a boss (cylinder R = sqrt(12.68) at (27.2, 16), z 10..20) minus a D prism along +y whose chord face `x = 27.2 - R` touches the boss along y = 16 and whose arc face (cylinder r = 2.56398, axis y) notches the boss. The arc face's two edge lines are tangent to the boss at (27.2 - R, 16, 12.5435) and (27.2 - R, 16, 17.6134); the boss/arc loop (22.11 long) touches the arc face's boundary there. `SmApiIntersectFaces` on the pair returns 19 curves with the parameter running to 2778 (about 125 laps). The difference: 1001 with `linear_sweep_arc_is_cylinder`, `brep_edit_statuses_pass_on` and `ssi_proto_topology_statuses_pass_on`; 9 faces and 15582.75 mm³ for 16021.77 with no fixes. The chord 0.001 mm into or clear of the boss cuts correctly.
- **How found:** solidcraft#12858's repro (the body deleted in 0.40.0-rc.2), then `intersect_faces` on the face pair and prints in the marcher's snap test.
- **Confirmed:** no C++ build on this machine. The port's `is_point_on_tsect_curve` and `do_intersection_with_caches` are line-for-line ports of the two places (WR-52's parity test pins the direction test: `end_forward` → false), and SolidCraft 0.40.0-rc.2 on the pinned C++ shows the dropped-status outcome (the body deleted).
- **Fix (port, default):** `is_point_on_tsect_curve` answers true for a span that ends on the point within the tolerance whichever way the point's direction runs; `do_intersection_with_caches` sets `start_point` for a boundary start point whose direction runs along every boundary it lies on (upstream's own test for tracing such a point both ways), so its trace closes on it as an interior seed's does. The pair then gives one closed loop split at the second touch point, and the Boolean builds the 16021.7689 mm³ solid with SolidCraft's fixes and without. Regression: `crates/solidcore/tests/boolean_cut_face_tangent_to_cylinder.rs`; the WR-52 parity test's `end_forward` expectation becomes true.
