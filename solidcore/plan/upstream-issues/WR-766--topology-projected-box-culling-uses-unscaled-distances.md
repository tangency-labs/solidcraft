#### WR-766. `SmTopologySolver::MayContainAnswer` culls projected extrema in unscaled units and without tolerance

- **Severity:** Wrong result
- **Area:** Solvers
- **Location:** `source/SMLib/src/SmTopologySolver.cpp:2797-2827`, `SmTopologySolver::MayContainAnswer`, the `SM_SO_PROJECTED_MINIMIZE` and `SM_SO_PROJECTED_MAXIMIZE` arm, at v1.0.1 (`3fd5b9548d19aa8c12c29bc9637a96d42a06f8a5`).
- **What happens:** The topology solver measures a projected answer as `|N x D x N|` (`SmTopologySolver.cpp:186-189`), which is `(N . N) |P(D)|` for the orthogonal projection `P`. Its box test projects the second sphere centre with `smgu_PointProjectToPlane`, which divides by `N . N` (`SmGeomUtility.cpp:3862-3865`) and so returns the unscaled `P`. It then compares the unscaled centre distance, plus or minus the unscaled radii, with `m_dBestAnswerSoFarSq`, which holds the scaled answer squared. It also applies no tolerance. The `SM_SO_MINIMIZE` and `SM_SO_MAXIMIZE` arms keep a branch whose bound is within `m_d3dTolerance` of the best answer, so an All request returns every answer within tolerance. The projected arm culls such a branch.
  - With `N . N != 1`, the bound is off by the factor `N . N`. A minimum with `N . N < 1` or a maximum with `N . N > 1` culls a branch holding a better answer (as in WR-764 for `SmGlobalSolver`).
  - With any normal, an All request loses answers that are within tolerance of the best but not equal to it.
- **Trigger:** Normal N = (0, 0, 2), tolerance 1e-5, best answer 1. The first box is the point (0, 0, 0). The second is the point (x, 0, 0), whose projected distance is `4x`. For a minimum with x = (1 + 5e-6) / 4, the answer 1 + 5e-6 is within tolerance of 1, so an All request must keep it. The C++ bound is the unscaled distance x ≈ 0.25, and 0.25² is not above 1, so the branch happens to be kept, but only because the unscaled bound understates the answer fourfold. For a maximum with x = (1 - 5e-6) / 4, the answer 1 - 5e-6 is within tolerance and must be kept. The C++ bound is x ≈ 0.25, and 0.25² < 1, so the branch is culled.
- **How found:** Splitting the projected culling fixes out of PR [#2968](https://github.com/tangency-labs/solidcore/pull/2968). The `intersect.topology_solver_p2` subdivided-vertex fixtures return fewer of their within-tolerance All answers on the ported test, for example 5 of 21 for a line against 12 vertices.
- **Confirmed:** yes, from the pinned source. No C++ build was run. The Rust test `projected_box_culling_retains_answers_within_query_tolerance` in `intersect/topology_solver/p1.rs` encodes the trigger, keeping answers 5e-6 inside tolerance and culling ones 2e-5 outside, for both operations. It fails on the ported comparison and passes with the fix.

The Rust fix encloses the projected distance between every pair of box points in the double-cross metric, with outward-rounded intervals (`intersect/topology_solver/projected_metric.rs`). It then keeps a branch unless that whole range is more than the query tolerance worse than the best answer, as the Minimize and Maximize arms do.
