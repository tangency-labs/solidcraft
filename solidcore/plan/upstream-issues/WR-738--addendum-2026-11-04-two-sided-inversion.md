Updates: WR-738

#### WR-738 (addendum 2026-11-04). `STEPInversion` of a profile that crosses the axis solves one half plane only; the fix makes it two-sided, and its frame tests the axis by distance
- **Severity:** Wrong result
- **Area:** Surfaces and volumes
- **Location:** `source/SMLib/src/SmSurfOfRevolution.cpp`, `SmSurfOfRevolution::STEPInversion` (def. `:484`).
- **What changed:** the record's "Not fixed here" is the same cause as its trigger, seen from the other side: `STEPInversion` turns a point onto the frame's +X half plane only (`TransformPointToStartPlane`), but a point's circle about the axis meets the generator's plane in two points, `(+r, h)` and `(-r, h)`, and a profile that crosses the axis reaches the second on the side the frame does not face. The new frame (from the profile's origin) only chose which side fails (tangency-labs/solidcore#2636 review, #2628 item 7): for `λ(s) = (1, 0, 0) + s (1, 0, 1)` about Z, `(2, 0, 1) = λ(1)` inverted with the flag and `(-2, 0, -3) = λ(-3)` without it, never both. With `Kernel::fixes.revolution_frame_from_profile_origin` the inversion now also turns the point onto the -X half plane (STEP `u + 180`), and the first half plane on which the point lies on the generator gives `(u, v)`, +X first as upstream, so a point that lies on the generator there keeps the parameters it has there. Both points above invert, `(0, 1)` and `(0, -3)`, and `(0, -2, -3)` is `(90, -3)`, for the frame from the profile's origin and for upstream's. The same flag, because it is one defect: the frame fix alone moves the failure to the other side of the axis, and the two-sided inversion makes the result independent of the side the frame faces.
- **Also with the flag** (#2628 items 8 and 9, from the #2636 review): when the profile's point at parameter 0 is on the axis, `CreateCanonical` takes the interval's start before upstream's 45 % point (the frame selection at `:663-686` of the record), so the segment `s (1, 0, 1)` on `[-9, 11]`, whose points at 0 and at 45 % are both the origin, has a frame (X = (-1, 0, 0)) instead of `SM_ERR`. And (item 9) the reference point is on the axis by its distance from it (`|Z x (P - O)|² < SM_EFF_ZERO_SQ`, the bound its Y axis is then checked against), not by `IsParallelTo(Z, 1 degree)`, which takes the origin `(1, 0, 1000)` of `(1, 0, 1000) + s (1, 0, 1)`, one unit from the axis but 0.057 degrees from its direction, for a point on it and turns the frame to the 45 % point past the crossing (X = (-1, 0, 0) instead of (1, 0, 0)). The record's "a profile whose interval starts at 0 keeps upstream's frame bit for bit" now holds except where that start is off the axis but within 1 degree of its direction from the axis point; there the frame faces the start instead of the 45 % point.
- **Confirmed:** no (as the record: the difftest builds no such profile).
- **Rust port:** default unchanged (upstream's one half plane and tests). Tests in `crates/solidcore/src/surface/surf_of_revolution/p1.rs`: `profile_crossing_the_axis_inverts_on_both_sides`, `frame_from_the_interval_start_when_the_origin_is_on_the_axis`, `frame_point_on_the_axis_by_its_distance`.
