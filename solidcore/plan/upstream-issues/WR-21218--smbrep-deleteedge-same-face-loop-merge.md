#### WR-21218. `SmBrep::DeleteEdge` destroys the surviving face when deleting an edge between two loops of the same face
- **Severity:** Internal topology corruption / crash (`face 0 not found` on subsequent queries; dangling `SmFace*` in C++)
- **Area:** B-rep edge deletion (`topology.brep_p4`, `delete_edge` / `delete_manifold_edge`)
- **Location:** `source/SMLib/src/SmBrep.cpp`, `SmBrep::DeleteEdge` (lines 5877–5884 and 6470–6556; solidcore `topology/brep/p4.rs`, `delete_manifold_edge`).
- **What happens:** `SmBrep::DeleteEdge` sets `bSplitLoop = (pLU == pLURad)` and `bMergeFace = !bSplitLoop && !bVIsStrut && !bVRadIsStrut && !(both inner)`, assuming that distinct radial loop uses (`pLU != pLURad`) always belong to distinct faces (`pFace != pFaceRad`). On a single-face doubly-periodic body (such as a full torus with two internal seam edges), deleting the first internal seam splits the single loop into two loops (`Same` and `Opposite`) on the same face `F`. Deleting the second internal seam then sees `pLU != pLURad` yet `pFace == pFaceRad == F`, enters the face-merge branch with `pSurvF = F` and `pDelF = F`, removes `F`'s face uses from the shell, removes `F` from `m_pFaceListHead`, and deletes `F`, leaving the shell empty and the surviving face gone.
- **Trigger:** Calling `delete_edge` consecutively on both internal seam edges of a 1-face torus (as `complete_imported_face_seams` did when importing a full horn torus whose meridian and equator seams were both marked redundant in #21218).
- **How found:** #21218 (STEP import of a full horn torus failed with `topology::Brep::face: face 0 not found` inside `complete_imported_face_seams`).
- **Confirmed:** yes, in the port, which mirrored upstream's `bMergeFace` condition:
  - `topology::brep::p4::tests::deleting_a_second_internal_seam_keeps_the_surviving_face` failed on `00f7d5a4e3` with `b.face_list() == []` instead of `[FaceId(0)]`;
  - `topology::face::p1::seam_completion_fault_tests::complete_imported_face_seams_on_a_torus_with_all_seams_redundant_keeps_the_face` failed on `00f7d5a4e3` with `Err(NotFound { operation: "topology::Brep::face", entity: Face(FaceId(0)) })`.
  The pinned C++ was not run.
- **Fix in solidcore:** When `face == face_rad` and `lu != lu_rad` (`same_face`), `delete_manifold_edge` merges the two loops on that single face without emitting `MergeInBrep`, swapping surfaces, or destroying the face, and when the removed loop carried `OrientType::Same` it promotes the surviving loop to `OrientType::Same` and moves its loop uses to index 0 of both face uses' loop lists (`outer first`).
