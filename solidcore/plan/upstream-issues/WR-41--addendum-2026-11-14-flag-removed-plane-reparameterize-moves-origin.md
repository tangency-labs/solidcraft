Updates: WR-41

#### WR-41 (update, 2026-11-14). `plane_reparameterize_moves_origin` is removed

The fix is the default and its flag is gone (tangency-labs/solidcraft#14246, batch S-plane). `Plane::reparameterize` (`surface/plane/p1.rs`) always sets the origin to upstream's `sOriginMax`, the point that keeps the old domain's upper corner at the new domain's upper corner, so the analytic plane and its NURB stay one surface. `Plane::reparameterize_opt_in` and `Plane::reparameterize_with_kernel` are gone; `Surface::reparameterize` and `Plane::is_nurb_surface_plane` call `Plane::reparameterize`. A reparameterisation onto the same domain keeps the origin exactly instead of recomputing it through the upper corner with rounding.

- **Tests:** the `wr41_*` unit tests in `surface/plane/p1.rs` run on the default path: the moved origin against closed forms (`(26/3, 17.75, 30)` and `(4.5, 4.25, 5)`), analytic against NURB points across the new domain, and a new test that an identity reparameterisation leaves the plane bit for bit. The test that pinned the old divergence is gone.
- **Results:** on the library's default kernel (SolidCraft's preset had the flag on), 24 goldens rows of `surface.plane_p1` move, all in its record length; no other unit moves. Each is a generated program with a `Reparameterize` onto a new domain, after which the origin moves by 0.92 to 8.6e6 (the huge-scale planes). Replaying all 141 such programs, the analytic plane agrees with its NURB over a 5x5 grid of the new domain to 1.5e-9 absolute (at coordinates of order 1e7; 8e-15 for unit-scale planes), the same agreement the plane had before the call; upstream's kept origin left them apart by the full origin move. The later drops, line intersections and trims therefore run on the plane its NURB describes, and their solution counts change. The other 117 programs change only values the unit's block sums cannot show (their records hold infinities).
