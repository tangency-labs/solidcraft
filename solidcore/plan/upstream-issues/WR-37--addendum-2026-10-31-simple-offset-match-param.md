Updates: WR-37

#### WR-37 (update, 2026-10-31). Opt-in forwarding of `bOptMatchParameterization` in `CreateSimpleOffset`

- **Location:** `source/SMLib/src/SmBSplineCurve.cpp:2566`-`2572` (`SmBSplineCurve::CreateSimpleOffset`, def. `:2475`), calling `SmCurve::ApproximateCurve` (`source/SMLib/inc/SmCurve.h:122`-`137`).
- **Defect:** After handling in-plane circular arcs directly (`IsArc` at `:2513`-`2550`), `CreateSimpleOffset` approximates `SmOffsetCurve` via `sOff.ApproximateCurve(crContext, sBreaks, dApproxTol3d, dMaxGap3d, pOffsetApprox, bOptMatchParameterization, FALSE)`. In `SmCurve::ApproximateCurve`, parameter 6 is `bOptCreateAnalytics` and parameter 7 is `bOptMatchParameterization`, so the caller's `bOptMatchParameterization` lands in `bOptCreateAnalytics` (checked in `sm_FlushCrv` only for multi-span circular-arc polygons) while parameterization matching in `sm_TestSpanAccuracy` is hardcoded to `FALSE`.
- **Callers and derived curves:** `SmEllipse` has no override and inherits `SmBSplineCurve::CreateSimpleOffset` (`Ellipse::create_simple_offset` delegates non-circles to `BSplineCurve::create_simple_offset`), and `SmCircle::CreateSimpleOffset` (`source/SMLib/src/SmCircle.cpp:346`-`352`) forwards `bOptMatchParameterization` to `SmBSplineCurve::CreateSimpleOffset` for out-of-plane offset normals (`Ellipse::create_simple_offset` delegates via `BSplineCurve::create_simple_offset_with`). `Line::create_simple_offset` and in-plane circles build exact offsets without `ApproximateCurve`, and internal callers (`SmEdge.cpp:5913`, `SmSurfOfRevolution.cpp:1312`, `SmApiCurves.cpp:1017`) pass `false`.
- **Rust port:** `Kernel::fixes.bspline_simple_offset_matches_parameterization` (`#2141`, default `false`) keeps `(create_analytics = match_parameterization, match_parameterization = false)` when off for pinned C++ parity, and passes `(create_analytics = false, match_parameterization)` when enabled. Calls with `match_parameterization = false` pass `(false, false)` under both settings and are bit-identical.
- **Regression:** Unit tests in `crates/solidcore/src/nurbs/b_spline_curve/p2.rs`:
  - `wr37_bspline_simple_offset_matches_parameterization_when_opted_in`: offsets a `C2` non-arc planar cubic B-spline with non-uniform speed (`u = [0, 0, 0, 0, 0.1, 0.6, 1, 1, 1, 1]`) at `approx_tol_3d = 1e-4` with `match_parameterization = true`. Under `Kernel::default()`, `[0, 0.5]` passes as a single Hermite span on the straight `y = -0.5` offset locus with `> 0.1` parametric error at `t = 0.25`; with the fix enabled, parameterization matches the exact offset within `<= 1e-4` at `t = 0.25` and `<= 1.5e-4` across `[0, 1]`.
  - `wr37_bspline_simple_offset_unmatched_mode_unchanged_by_opt_in`: verifies bit-identical gap and canonical curve data between default and opt-in when `match_parameterization = false`.
  - `wr37_linear_bspline_and_ellipse_simple_offset_with_match_parameterization`: verifies `create_line_segment` offsets to a plain degree-3 `Unspecified`-form B-spline with exact linear parameterization under both default and opt-in, and verifies `Ellipse::create_simple_offset` matches parameterization across the natural interval on a non-circular ellipse when opted in.
