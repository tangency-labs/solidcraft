# blend.fillet_executive_p3: the Rust ray fire rebuilds each face's surface cache per solve (nightly fuzz00085, 2026-11-02)

- **Unit / case:** `blend.fillet_executive_p3`, nightly fuzz `fuzz00085` (run 41190675541, `rust: no result after 20 s`): base `issue-880-tilted-cylinder-rim-offsets-1-2` (the `two_offset_chamfer` case) with `/two_offset_chamfer/origin/0 = 1e+300`, a cylinder placed at x = 1e300 minus a box at the origin.
- **Both values:** both sides end in the same harness error, `two_offset_chamfer setup failed (-2): no edge at the rim height`. Not a value difference, a time difference: the C++ child returns in 1.8 s, the Rust side in about 140 s (main `340782351`, alone, x86-64).
- **Where the time goes (gdb samples and breakpoint counts):** both sides spend their time in `SubdivideToTolerances` of the cylinder faces' caches, which is slow at x = 1e300 (the tolerance tests never pass until nodes are tiny). The C++ makes 149 `SmBrep::RayFire` calls and runs `SmSurfaceCache::BuildTreeBase` 10 times: `smsurf_GetSurfaceCache` keeps each surface's cache across ray fires. The Rust side (`boolean::merge::p4::classify_remaining` -> `BrepQuery::classify` -> `topology::brep::p2::ray_fire` -> `query::brep::ray::live::solve_mutable_brep_point`) builds a new `LiveBrepObjects` per solve, whose face caches live for that solve only, so `query::brep::ray::face_surface_cache` ran 154 times, each about 0.9 s here.
- **Not a hang:** every loop and recursion is bounded (`MAX_SUBDIVISION_DEPTH`, `MAX_SUBDIVISION_NODES`) and the case returns. The gap is the cache's lifetime, not an unbounded loop, so #2393 leaves it.
- **Suspected fix (follow-up):** keep a face's built cache across ray solves of the same B-rep until the face or its surface changes, as upstream's cache manager does. Mind the cache-history findings (`general--trimmed-surface-cache-history-*`): a kept cache must match upstream's tolerance history.
