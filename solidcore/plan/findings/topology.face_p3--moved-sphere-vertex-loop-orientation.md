# topology.face_p3: loop orientation of a sphere whose vertex moved and grew (2026-11-01)

- **Unit:** found by `topology.assert_valid` (`update_tolerances.json`, shim op 5); the divergence is downstream in `topology::face::p3::compute_loop_orientation` (via `trimming_tools::check_face` in `ValidatePointers`).
- **Inputs:** `create_sphere((0,0,0), 1)`; vertex 0 moved by +1e-4 in x (mutation 6); then `SmBrep::ValidateAndUpdateTolerances(FALSE)`, which grows vertex 0 to 2e-4 (twice its gap) on both sides; then the capi check at level 2. Cases `update_sphere_m6_i0_v0.0001_l2/_l0` and `update_sphere_m6_i0_v1_l2/_l0` (vertex moved 1.0, grown to 2.0).
- **Values:** both sides agree on the update: status, maxima, reports, every vertex and edge tolerance (`[2e-4, 1e-5]`, `[1e-5]`). C++ `ValidatePointers` then reports `SmTrimmingTools::Test #3 Loop Orientation: Face Loop has bad orientation` and `#4 ... zero area`, so `AssertValid` is skipped. Rust's `compute_loop_orientation` returns `Same`, `ValidatePointers` passes, and `AssertValid` reports `SmFace::Test #36 Face Near missing Seam`.
- **Not affected:** without the update (vertex at 1e-5), both sides report the bad orientation (capi case of the same mutation, passing).
- **Cause (fixed):** `face::p2::is_singularity`, the helper `sm_AreConnected` (`SmFace.cpp:1512`) uses for the ends of a UV gap, passed `bPtTestOnly = FALSE` to `Surface::is_singularity`, where upstream passes `TRUE`. The UVs, tolerances and UV tolerances agree on both sides (traced: the gap across the pole at v = 0.99996 with the 2e-4 vertex). With the surface tests too, Rust took that end as on the pole and joined the trims (UV loop, `Same`). The C++ point test does not, so it falls to the 3D walk (`SM_OT_UNKNOWN`). The fix (unconditional parity) passes `TRUE`; regression test `crates/solidcore/tests/face_loop_orientation_pole_point_test.rs`.
- **PR:** tangency-labs/solidcore#2199.
