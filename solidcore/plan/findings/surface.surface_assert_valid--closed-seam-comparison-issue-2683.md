# surface.surface_assert_valid: closed-seam comparison and its measured C++ differences (2026-11-05)

Unit: `surface.surface_assert_valid`. Issue #2683; PR #2784, based on main `f06f897eab886e674873f5488e57b388392df1a9`.

The row and column walks now compare their last direction with their first. The absolute-zero path keeps its existing treatment of coincident pairs. The rounding-aware path also joins the last and first real directions across coincident or rounding-only seam steps, including when several such steps occur at either end. The 170-degree threshold and both zero criteria are unchanged. Open grids gain no comparison; the curved Setback caller supplies open grids in both directions.

The three initial regression tests fail before the change. After it, the four issue tests and all 28 tests of the containing validity module pass. They cover rows and columns, cyclic starting points, both windings, translated points, a real reversal across a repeated/noisy seam, accepted clean/collapsed nets and a rounding-only seam, and an open line. The full workspace passes: 5,044 kernel tests plus 982 tests in the other crates, with the existing 57 skips. Workspace doctests, fmt, workspace/all-targets Clippy and the wasm32 check also pass.

The native diagnostic intentionally differs for two existing generated cases: `gen0340` and `gen1316`. Both have a closed U net with its first row repeated at the end. A standalone reconstruction confirms that their skipped closing step is zero, but their real directions across it turn by 175.67190164009531 and 175.70733198415260 degrees respectively. Rust adds exactly one `SmBSplineSurface` test #5 report (`values.out.len = 157`); C++ emits none (`values.out.len = 3`). The full measurements, including the second reversed column of `gen1316`, are in `plan/upstream-issues/WR-752--point-grid-misses-last-turn-at-closed-seam.md`. The direct four-point native probe also demonstrates that the original nonzero-seam answer depends on which point starts the closed walk.

Baseline: the unexpired `difftest-reports` artifact of main CI run 41991964300, at the exact base above, seeds 16. No committed historical reports or filtered baseline run were used. The unfiltered `--green --jobs 0 --baseline ...` run compares 280 units and 592,286 cases: 262 units pass, 12 are partial and 6 fail, as on that baseline. Only the two case outcomes above change (pass to fail); every case is retained. Aggregate passes are 591,221 -> 591,219 and failures 22 -> 24. Rejected cases remain 631 and parked cases remain 33. The already-failing `gen0812` and `gen1016` remain visible too. The targeted unit has 2,902 cases, 2,566 passes, 4 failures, 329 rejections and 3 existing parks.

The new C++ disagreements are left visible: no known-mismatch marker, park, guard, case removal, tolerance change or baseline waiver was added. The diagnostic therefore exits nonzero. This PR proves the corrected kernel predicate with cyclic invariance and measured directions; it does not claim a green C++ sweep or promote a unit's port status.
