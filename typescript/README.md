# solidcraft (TypeScript)

Parametric parts written as TSX that build real [SolidCraft](https://solidcraft.io) designs: a `.sc`
file with the whole history (sketches, extrudes, fillets, holes, patterns) and the parameters, so
the part stays editable in the app. It drives `solidcraft-cli mcp` the way the Python client does
(`python/`), and every engine command is also there, typed, through `Session`.

```tsx
import { defineParams, edges, type ParamValues } from "solidcraft";

export const params = defineParams({
  thickness: { type: "number", default: 6, min: 3, max: 12, unit: "mm" },
  size: { type: "number", default: 60, unit: "mm" },
});

export default function MotorMount({ thickness: t, size }: ParamValues<typeof params>) {
  return (
    <part name="mount" material="PETG">
      <difference>
        <fillet radius={6} edges={edges.vertical()}>
          <box size={[size, size, t]} center={[true, true, false]} />
        </fillet>
        <cylinder d={22.5} h={t} />
        <linearPattern count={2} dx={31}>
          <linearPattern count={2} dy={31}>
            <hole at={[-15.5, -15.5, t]} d={3.4} counterbore={{ d: 6.5, depth: 3 }} />
          </linearPattern>
        </linearPattern>
      </difference>
    </part>
  );
}
```

```sh
bunx solidcraft-ts build mount.tsx -o mount.sc     # build, save, reopen and check it rebuilds
bunx solidcraft-ts build mount.tsx -o mount.sc --param size=80 --script replay.json
```

`mount.sc` opens in SolidCraft with parameters `thickness` and `size`, a box whose size is
`size` × `size` × `thickness`, a fillet on its four upright edges, a cut, a counterbored hole and
one 2 × 2 pattern. Change `size` in the app and the plate, the fillet and the holes follow.

Set `"jsx": "react-jsx"` and `"jsxImportSource": "solidcraft"` in `tsconfig.json`. Bun runs the
files as they are.

## How it maps to SolidCraft

| TSX | SolidCraft |
|---|---|
| `defineParams` (number, int) | user parameters (`parameters.add`); every number in the tree that moves in proportion with one is written as an expression naming it (`size / 2 - 3`) |
| `<part name material>` | the body's name, its material (`material.assign`; PETG, ASA and TPU are made with `material.create`) |
| `<box>`, `<cylinder>`, `<cone>`, `<sphere>`, `<torus>` | `solid.box`, `solid.cylinder`, `solid.cone`, `solid.sphere`, `solid.torus` |
| `<extrude>`, `<revolve>`, `<loft>` with `<rect>`, `<roundedRect>`, `<circle>`, `<polygon>`, `<slot>` | a sketch (`sketch.create`, its curves with expression coordinates) and `solid.extrude` / `solid.revolve` / `solid.loft` |
| `<union>`, `<difference>`, `<intersection>` | the tool feature's own `operation` and `targets` (a box cut into the plate is one Box feature that cuts); `solid.combine` when the tool is itself a built body |
| `<fillet edges>`, `<chamfer edges>` | `solid.fillet` / `solid.chamfer` on the edges the selector picks |
| `<hole>` (diameter or `size="M3"`, `counterbore`, `countersink`, `head`) | `solid.hole` |
| `<linearPattern>`, `<polarPattern>` | `solid.pattern.rectangular` (a pattern of a pattern is one feature with two directions) and `solid.pattern.circular` of the features inside |
| `<translate>`, `x`/`y`/`z`/`at` | positions and sketch planes (expressions, so they follow parameters) |
| `<rotate>` | `solid.move` features on the body it turns |

Each feature is named after its element and source line (`Fillet mount.tsx:18`), so the timeline
points back at the TSX. An element this package cannot map yet is an error naming its line; nothing
is dropped. What could not follow a parameter is reported, never silently baked in: a number that
is not linear in a parameter (`60 / n`), and a parameter that changes the tree's shape (a count
used in `.map()`, a boolean).

## Selectors

`edges.vertical()`, `edges.top()`, `edges.bottom()`, `edges.parallel("x")`,
`edges.perpendicular("z")`, `edges.circles()`, `edges.radius(r)`, `edges.max("x")`,
`edges.min("y")`, `edges.within(min, max)`, `edges.index(...)`, and `.and()`, `.or()`, `.not()`.
Each is resolved against the body SolidCraft built at that step (`model.edges`), and the chosen
edges are passed as their midpoints, the pick SolidCraft's own tools record. SolidCraft then keeps
the fillet on those edges when the design rebuilds or a parameter changes. `edges.index` follows
SolidCraft's edge order, which changes when the body is built differently.

## Commands directly

```ts
import { Session } from "solidcraft";

const s = await Session.open();
await s.run("solid.box", { length: 60, width: 40, height: 8, body_name: "Plate" });
await s.run("file.save", { path: "plate.sc" });
await s.close();
```

`CommandParams` types every command's parameters. It is generated by `cargo xtask typescript` from
`solidcraft-cli commands --schemas` into `src/generated/` and is not committed, so it cannot drift
from the program.

## Finding solidcraft-cli

As the Python client: `$SOLIDCRAFT_CLI`, the CLI downloaded earlier for this package's version (in
the same user cache folder the Python client uses), a `solidcraft-cli` on `PATH` of the same minor
version or newer, then a download of this version's own from the GitHub release, checked against
its `SHA256SUMS.txt`. `SOLIDCRAFT_NO_DOWNLOAD=1` turns the download off.

## Tests

```sh
cargo xtask typescript --cli path/to/solidcraft-cli
cd typescript && bun install && bun run typecheck
SOLIDCRAFT_CLI=path/to/solidcraft-cli bun test
```

The tests build every example in `examples/`, check its volume against the value worked out by
hand, reopen the saved file with `solidcraft-cli eval` (which rebuilds the timeline), and change
each example's parameters in the saved design to check the history follows them.
